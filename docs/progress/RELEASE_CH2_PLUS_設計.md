## 2. バフ/デバフ基盤 設計メモ（着手時の前提）

Ch1 期の調査で判明した実装現状（着手時に再確認）:
- **デバフ側はほぼ存在** — `src/logic/StatusAilmentSystem.ts` がターン制デバフ系として実装済み。BLEED/POISON/BURN/FREEZE/PARALYSIS/**WEAKEN**（ステ低下デバフ、`:227` で 0.7倍）。プレイヤー→敵付与（`applyAilmentToEnemy`）あり、敵→プレイヤーも `BattleCanvas:2777` で動くが **`enemy.tier==='BOSS'` 起点**っぽい → 非ボス開放が S1 の主作業。
- **バフ側は型ごと無い** — `StatusEffect.type` は `AilmentType`（負のみ）。プラスの状態という概念が無い。TribeSynergy（編成パッシブ）と魔神化 PARTY_BUFF（自己強化）のみ。→ S2 で新規プリミティブ。
- **二重経路注意** — M2 と同じく **BattleEngine（サーバ）＋ BattleCanvas（クライアント・live）** の両方に同一ロジックを通す必要。共有 pure ヘルパで drift 防止（M2 `EnemyScaling.ts` と同パターン）。
- **設計の利点** — S2 は S1（StatusAilmentSystem）の実証済みアーキテクチャを鏡像にできる（付与率・duration・stack・tick・UI の構造を流用）。

着手時は C4/B0 と同様に **設計を軽く議論 → 設計＆実装計画ドラフト** の順で。S1（薄く先行）→ S2 → 支援役 の段階が低リスク。

## 3. 着手順の目安（Ch2 内）
1. **基盤先行**: S1 デバッファー開放 → S2 バフ・プリミティブ（味方/敵が支援役を持てる土台）
2. **コンテンツ**: area2「幽霊都市」ステージ/敵/物語（バフ/デバフ役を最初から織り込んで設計＝Ch1敵の書き直し回避）

4. **その他先送り**: ヒーラー、UR、Tier2魔神化 ほか（DEFERRED.md）
