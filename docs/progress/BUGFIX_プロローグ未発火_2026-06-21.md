# BUGFIX: 新規登録時にプロローグが発火しない

調査日: 2026-06-21 / ブランチ: `feature/20260614_login`

---

## 1. 事象

新規登録（サインアップ → キャラクター作成）でゲームを開始しても、
プロローグ（`PROLOGUE_00`〜`PROLOGUE_03`, trigger=`GAME_START`）のストーリーシーンが再生されない。

---

## 2. 再現条件

新規登録フロー（`authRequired` → サインアップ → `characterRequired` → キャラ作成 → `ready`）を
**ページの完全リロードなしで**通過したとき。
※ブラウザを手動でフルリロードすると発火する場合があるため、見落とされやすい。

---

## 3. 原因分析（根本原因）

### 3-1. プロローグの enqueue は「ストア hydration 時に一度だけ」発火する

`src/hooks/useStoryTrigger.ts:31-44`

```ts
useEffect(() => {
  if (!hasHydrated) return;
  const store = useStoryStore.getState();
  if (!store.isViewed('PROLOGUE_00')) {
    store.enqueueScenes(getPrologueSceneIds());   // ← ここでプロローグを積む
    return;
  }
  ...
}, [hasHydrated]);   // ← 依存は hasHydrated のみ
```

この effect は **`hasHydrated` が false→true になった瞬間（アプリ起動直後）に一度だけ**実行される。
`hasHydrated` はその後二度と変化しないため、effect は再実行されない。

### 3-2. サインアップ時の `resetStoryProgress()` が、起動時に積んだものを消す

`src/components/auth/AuthGate.tsx:30-36`

```ts
if (mode === 'signup') {
  await signUpWithCredentials(email, password, displayName);
  resetStoryProgress();   // ← activeScene / sceneQueue / viewedScenes / storyFlags を全消去
}
await signInWithCredentials(email, password);
emitAuthChanged();
onAuthenticated();        // = authFlow.reload
```

`resetStoryProgress()`（`src/store/useStoryStore.ts:149-154`）は
`activeScene` `sceneQueue` `viewedScenes` `storyFlags` をすべて空にする。

### 3-3. `authFlow.reload` はフルリロードではない

`src/hooks/useAuthFlow.ts:82-84`

```ts
const reload = useCallback(() => {
  setVersion((value) => value + 1);   // boot() を再実行するだけ。window.location.reload() ではない
}, []);
```

`useStoryTrigger()` は `src/app/page.tsx:109`（条件付き return より前）で常時マウントされており、
サインアップ〜キャラ作成〜本編表示の間、**コンポーネントツリーは一度もアンマウントされない**。
よって `hasHydrated` は終始 true のまま変化せず、3-1 の effect は再実行されない。

### 3-4. タイムライン（バグの成立）

| # | フェーズ | 状態 | プロローグ effect |
|---|---|---|---|
| 1 | 起動・hydration | `authRequired`／`player=null`（`clearServerData`）／StoryOrchestrator未マウント | **一度だけ実行**。`viewedScenes` の中身次第で積む/積まない（積んでも非表示） |
| 2 | サインアップ | `resetStoryProgress()` で activeScene/queue/viewed を全消去 | 再実行されない |
| 3 | reload→boot | `characterRequired`（NO_CHARACTER） | 再実行されない |
| 4 | キャラ作成→reload→boot | `ready`／`player` セット／**StoryOrchestrator マウント** | 再実行されない → **キューが空のまま** |

結果、StoryOrchestrator が表示される頃には enqueue する契機が消えており、プロローグが流れない。

### 3-5. 補足（設計上の前提確認）

- 有効なストーリーパックは `ch1_scenes.json` / `ch2_scenes.json` のみ（`src/data/story/packs.ts:24-39`）。
  ハードコードされている `PROLOGUE_00` は `ch1_scenes.json` の `GAME_START` 先頭シーンと一致しており、ここは正しい。
  （`act1_prologue.json` `prologue_scenes.json` `act1_ch1_royal_capital.json` は未登録＝デッドファイル。今回の原因ではない）
- ストーリー進行（`viewedScenes`/`storyFlags`）は localStorage `necro-story-store-v2` に永続化され、
  **ユーザー単位ではなくブラウザ単位**。サインアップ時の `resetStoryProgress()` はこの「前ユーザーの既読を引き継がない」ための処理だが、3-1〜3-3 のタイミング不整合により無効化されている。

---

## 4. 修正方針

**プロローグの発火条件を「hydration 完了」だけでなく「プレイヤーがロードされ本編に到達した」状態にも反応させる。**

`useStoryTrigger` のプロローグ effect の依存に「プレイヤー存在フラグ」を追加し、ガードする。
これにより、キャラ作成後に `player` が null→セットへ遷移したタイミングで effect が再実行され、
`resetStoryProgress()` 後の空の `viewedScenes` を見て `PROLOGUE_00` 未読 → プロローグを enqueue できる。

- 起動時の AuthGate 中は `player=null`（`clearServerData`）なので**早すぎる発火はしない**。
- キャラ作成完了後（`loadFromServer` で `player` セット、status=`ready`）に**初めて発火**し、
  この時 StoryOrchestrator はマウント済みのため確実に表示される。
- `enqueueScenes` は既読/キュー重複を除外する idempotent 実装（`useStoryStore.ts:75-105`）なので、
  effect が複数回走っても二重再生しない。
- ゲスト（`initialize()` で `player` セット）でも従来どおりプロローグが流れる。

### 代替案（不採用）
- A: AuthGate の `onAuthenticated` 後に手動で prologue を enqueue する
  → 認証フローにストーリー知識が漏れ、責務分離が崩れる。キャラ作成経由の遷移も拾えない。
- B: `authFlow.reload` をフルページリロード化する
  → 体感が重くなり、Zustand のメモリ状態を捨てる副作用が大きい。過剰。

---

## 5. 修正計画

### 5-1. 本体修正: `src/hooks/useStoryTrigger.ts`

プレイヤー存在を購読し、プロローグ effect の依存・ガードに追加する。

```ts
// 追加（既存の clearedStages 購読の近く）
const hasPlayer = useGameStore(state => state.player != null);

// 変更: プロローグ判定 effect
useEffect(() => {
  if (!hasHydrated || !hasPlayer) return;          // ★ hasPlayer を追加
  const store = useStoryStore.getState();
  if (!store.isViewed('PROLOGUE_00')) {
    store.enqueueScenes(getPrologueSceneIds());
    return;
  }
  if (store.hasFlag('LINE_DEATH_SEEN')) {
    enqueueUnviewed(getFlagSceneIds('LINE_DEATH_SEEN'));
  }
  if (store.hasFlag('CH1_STARTED')) {
    enqueueUnviewed(getFlagSceneIds('CH1_STARTED'));
  }
}, [hasHydrated, hasPlayer]);                        // ★ hasPlayer を依存に追加
```

> 補足: フラグ系 effect（`useStoryTrigger.ts:46-55`）も本編到達後に評価したい場合は
> 同様に `hasPlayer` ガードを足してよいが、必須ではない（プロローグ未発火が主訴のため最小修正を優先）。

### 5-2. 確認: 既存の他フローへの影響

- 既存ユーザーの通常ログイン（status=`ready` 直行）: 起動時に `player` がほぼ即セットされ effect が走る。
  localStorage に `PROLOGUE_00` 既読があればスキップ、無ければ再生（＝従来通り／新規端末では再生）。
- 戻る/タブ移動では `player` は維持されるため再 enqueue は起きない（idempotent ガードも併用）。

### 5-3. テスト

- `src/data/story/StoryRegistry.test.ts` / `packs.test.ts` … 既存パスを維持（IDの整合のみ確認）。
- 追加（任意）: `useStoryTrigger` の hook テスト、もしくは手動 E2E で
  「新規登録 → キャラ作成 → プロローグ自動再生」を確認。
- `npx tsc --noEmit` と `npm test` を実行。

### 5-4. 手動検証手順

1. localStorage の `necro-story-store-v2` を削除（または別アカウントで既読が残った状態を用意）。
2. `npm run dev` → 新規登録 → プレイヤー名入力でキャラ作成。
3. 本編到達と同時に `PROLOGUE_00`（章タイトル/モノローグ）が自動再生されることを確認。
4. 一度視聴後、リロードしても再発火しないこと（既読スキップ）を確認。

## 6. 影響範囲

- 初回修正: `src/hooks/useStoryTrigger.ts`。
- 追加修正: `src/store/useStoryStore.ts` / `src/hooks/useAuthFlow.ts` / `src/components/auth/AuthGate.tsx`。
- リスク: 低〜中。プロローグ発火は `enqueueScenes` の idempotent 性で二重再生を防止し、
  ストーリー進行は `userId` スコープの localStorage キーへ分離する。

## 7. 関連する既知の制約（2026-06-21 追加修正で解消）

- ストーリー進行が **localStorage（ブラウザ単位）** で、同一ブラウザの別アカウントに既読が混入する制約は解消。
  `src/store/useStoryStore.ts` の永続化先を `userId` ごとのスコープキーに切り替え、
  `src/hooks/useAuthFlow.ts` で認証ユーザー確定時に `switchStoryPersistenceScope(userId)` を呼ぶ。
  未ログイン/ゲスト時は従来の未スコープキーへ戻す。
- 追加確認で、職業選択後の `CharacterCreation` が `loadFromServer()` で一度 `player` をセットした直後に
  `authFlow.reload()` を呼ぶため、`authFlow.status === 'characterRequired'` の間に積んだプロローグが
  次の rehydrate で消える問題を確認。`useStoryTrigger` に本編表示可能フラグを渡し、
  `ready` / `guest` 到達後に初期ストーリーを発火するよう修正済み。
- 未登録のストーリーJSON（`act1_prologue.json` 等）の整理。
