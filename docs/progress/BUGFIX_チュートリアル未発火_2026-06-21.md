# BUGFIX調査: チュートリアルが新規登録/別アカウントで発火しない

調査日: 2026-06-21 / ブランチ: `feature/2026062102`
関連: [`BUGFIX_プロローグ未発火_2026-06-21.md`](./BUGFIX_プロローグ未発火_2026-06-21.md)（ストーリー側・修正済み）

> プロローグ未発火バグ（コミット `5bbb2fb9`）の修正を受けて、「チュートリアルにも同種のバグが
> 潜んでいないか」を調査した結果のレポート。**結論: 同じ構造のバグが 1 件存在する（要修正）。**
> 一方、ストーリー側で必要だった「認証ロード中ガード」はチュートリアルには不要（構造的に回避済み）。

---

## 0. 結論サマリ

| # | 項目 | ストーリー（修正済み） | チュートリアル（現状） | 対応 |
|---|---|---|---|---|
| A | **永続化のユーザー別スコープ** | `switchStoryPersistenceScope(userId)` で `userId` ごとに分離 | **未対応。`necro-tutorial-store-v2` のブラウザ単位グローバルキー固定** | **要修正（本レポートの主題）** |
| B | 認証ロード中の早すぎる発火ガード | `canPresentStory`（`ready`/`guest`）で `useStoryTrigger` をガード | **不要**。`TutorialOrchestrator` は認証ガードの後でマウントされるため構造的に発火しない | 対応不要（確認のみ） |
| C | サインアップ時の手動リセット | `resetStoryProgress()` を撤去しスコープ切替へ一本化 | `resetTutorial()` は**元から呼ばれていない**（A の修正で不要になる） | A に吸収 |

## 1. 事象（再現する不具合）

同一ブラウザで以下を行うと、チュートリアル（スポットライト＋バナー）が **新しいユーザーで発火しない**。

1. ゲスト or アカウント A でプレイし、チュートリアルを 1 つでも進める／完了する
2. 別アカウント B を**新規登録**する（または別アカウントにログインし直す）
3. B では本来チュートリアルが最初から流れるべきだが、**一切表示されない**

ストーリー（プロローグ）は 2026-06-21 の修正で B でも正しく流れるようになったため、
**「ストーリーは出るのにチュートリアルだけ出ない」** という不整合な状態になる。

---

## 2. 根本原因（ストーリーと同型）

### 2-1. チュートリアル進行がブラウザ単位のグローバルキーに固定

`src/store/useTutorialStore.ts:41-46, 140-153`

```ts
const getTutorialStorage = (): StateStorage => {
  if (typeof window !== 'undefined' && window.localStorage) {
    return window.localStorage;          // ← 素の localStorage（スコープなし）
  }
  return memoryStorage;
};

// ...
{
  name: 'necro-tutorial-store-v2',       // ← 全ユーザー共通の固定キー
  storage: createJSONStorage(getTutorialStorage),
  partialize: s => ({
    completedPhases: s.completedPhases,
    tutorialCompleted: s.tutorialCompleted,
    viewedHints: s.viewedHints,
    visitedTabs: s.visitedTabs,
  }),
  // ...
}
```

`completedPhases` / `tutorialCompleted` / `viewedHints` / `visitedTabs` が
**ブラウザ単位で 1 つの localStorage キー**に保存される。ユーザー切替で分離されない。
これは修正前のストーリーストアと**完全に同じ構造**（修正前 `useStoryStore` も `name: 'necro-story-store-v2'` の単一キーだった）。

### 2-2. `useAuthFlow` がチュートリアルのスコープを切り替えていない

`src/hooks/useAuthFlow.ts`

ストーリーは認証遷移の各分岐で `switchStoryPersistenceScope(...)` を呼ぶ（4 か所）。

```ts
import { switchStoryPersistenceScope } from '../store/useStoryStore';
// ...
await switchStoryPersistenceScope(null);          // guest / no-user / 失敗パス
await switchStoryPersistenceScope(session.user.id); // 認証ユーザー確定
```

**チュートリアルには対応する `switchTutorialPersistenceScope` が存在せず、呼び出しも無い。**
そのため B でログインしても、チュートリアルストアは A（やゲスト）の保存内容をそのまま読む。

### 2-3. トリガーがグローバル状態で塞き止められる

`src/data/tutorial/triggers.ts`

```ts
export function shouldStartBattleTutorial({ stageId, completedPhases, activePhase, tutorialCompleted }) {
  return isTutorialBattleStage(stageId)
    && !tutorialCompleted                       // ← 前ユーザーで true だと永久に発火しない
    && !activePhase
    && !completedPhases.includes('BATTLE_BASICS'); // ← 前ユーザーの完了が残る
}

export function shouldEvaluateClearTutorialTrigger({ currentTab, tutorialHydrated, storyHydrated, tutorialCompleted }) {
  return tutorialHydrated && storyHydrated
    && !tutorialCompleted                       // ← ここも前ユーザー状態に依存
    && currentTab !== 'BATTLE';
}
```

最初の `BATTLE_BASICS`（`tutorial_battle_01` / `area1_node1` 入場時）も、
クリア連鎖（`PARTY_FORMATION` 以降）も、すべて `tutorialCompleted` / `completedPhases` で
ゲートされている。前ユーザーの完了状態が残っていると、新ユーザーでは一切起動しない。

### 2-4. サインアップ時のリセットも存在しない

ストーリーは旧 `AuthGate` で `resetStoryProgress()` を呼んでいた（現在はスコープ切替へ移行し撤去）。
**チュートリアルは `resetTutorial()` を `AuthGate` から元々呼んでいない**（`grep` 上、呼び出しは
`useTutorialStore` 定義内のみ）。よって新規登録でもクリアされず、グローバルキーを引き継ぐ。

## 3. 「不要」と判断した項目（ストーリーとの差分）

### 3-1. 認証ロード中ガード（`canPresentStory` 相当）は不要

ストーリーは `useStoryTrigger()` が `src/app/page.tsx:110` の**条件付き return より前**で
マウントされるため、`checking` / `loadingCharacter` の最中にも effect が走り、早すぎる enqueue が
起きうる。これを `canPresentStory`（`ready` / `guest`）でガードした。

チュートリアルのトリガー（`useTutorialTrigger`）は `TutorialOrchestrator` 内にあり、
`TutorialOrchestrator` は `src/app/page.tsx:366` で **`authRequired` / `characterRequired` /
`error` / `isCloudLoading` / `!player` の早期 return をすべて通過した後**にのみレンダリングされる。

```tsx
// page.tsx 内、全ての認証 early-return の後
return (
  <>
    <TutorialOrchestrator />   // ← status が ready/guest かつ player 存在時のみマウント
    <StoryOrchestrator>
    ...
```

加えて `useTutorialTrigger` は `tutorialHydrated && storyHydrated` を必須条件にしている。
よって**認証ロード中の誤発火は構造的に起きない**。ここは追加ガード不要（過剰実装を避ける）。

> 補足: トリガーが「マウントで」ガードされているだけなので、**永続化スコープ（項目 A）は
> 別途必ず必要**。マウント時点で読み込むストアの中身が前ユーザーのものだと、結局塞き止められる。

## 4. 修正方針

**ストーリーストアの修正（`5bbb2fb9`）をチュートリアルストアにそのまま横展開する。**
認証ユーザーごとに localStorage キーをスコープ化し、`useAuthFlow` の各認証遷移で
ストーリーと**同じタイミング・同じ分岐**でチュートリアルのスコープも切り替える。

設計を 2 ストアで揃えることで、「ストーリーは出るがチュートリアルは出ない」不整合を根絶する。

### 代替案（不採用 / オプション）
- **B-案: `AuthGate` の signup 後に `resetTutorial()` を呼ぶだけ** → ログイン切替（別アカウントへ）を
  拾えず、ストーリーとの設計不一致が残るため不採用。
- **オプション: 既存グローバルキーの 1 回限り移行** → 既にチュートリアル完了済みの単一ユーザー環境では、
  スコープ化後に**チュートリアルが再表示される**（user スコープが空のため）。これはストーリー側も
  同じ挙動で許容済み。気になる場合のみ、初回スコープ切替時に「user スコープが空かつグローバルキーに
  データあり」なら 1 度だけコピーする移行処理を `switchTutorialPersistenceScope` に足す（§7 参照）。

## 5. 修正計画（具体）

### 5-1. 本体修正: `src/store/useTutorialStore.ts`

`useStoryStore.ts` の `scopedStoryStorage` / `switchStoryPersistenceScope` と同じ実装を移植する。

```ts
import { createJSONStorage, persist, type StateStorage } from 'zustand/middleware';

export const TUTORIAL_STORE_STORAGE_KEY = 'necro-tutorial-store-v2';
export const TUTORIAL_STORE_SCOPE_STORAGE_KEY = 'necro-tutorial-store-scope-v1';

// memoryStorage は既存のものを流用

function getBaseTutorialStorage(): StateStorage {
  if (typeof window === 'undefined') return memoryStorage;
  try { return window.localStorage; } catch { return memoryStorage; }
}
function getSyncTutorialStorageItem(name: string): string | null {
  const v = getBaseTutorialStorage().getItem(name);
  return typeof v === 'string' ? v : null;
}
export function getTutorialPersistenceScope(userId: string | null | undefined): string | null {
  const normalized = userId?.trim();
  return normalized ? `user:${encodeURIComponent(normalized)}` : null;
}
export function getTutorialStorageKeyForScope(scope: string | null, baseName = TUTORIAL_STORE_STORAGE_KEY): string {
  return scope ? `${baseName}:${scope}` : baseName;
}
function getActiveTutorialScope(): string | null {
  const s = getSyncTutorialStorageItem(TUTORIAL_STORE_SCOPE_STORAGE_KEY);
  return s && s.trim() ? s : null;
}
function setActiveTutorialScope(scope: string | null) {
  const storage = getBaseTutorialStorage();
  if (scope) { storage.setItem(TUTORIAL_STORE_SCOPE_STORAGE_KEY, scope); return; }
  storage.removeItem(TUTORIAL_STORE_SCOPE_STORAGE_KEY);
}
const scopedTutorialStorage: StateStorage = {
  getItem: (name) => getBaseTutorialStorage().getItem(getTutorialStorageKeyForScope(getActiveTutorialScope(), name)),
  setItem: (name, value) => { getBaseTutorialStorage().setItem(getTutorialStorageKeyForScope(getActiveTutorialScope(), name), value); },
  removeItem: (name) => { getBaseTutorialStorage().removeItem(getTutorialStorageKeyForScope(getActiveTutorialScope(), name)); },
};
```

persist 設定を差し替え:

```ts
{
  name: TUTORIAL_STORE_STORAGE_KEY,
  storage: createJSONStorage(() => scopedTutorialStorage),  // ← 変更
  partialize: /* 既存のまま */,
  onRehydrateStorage: () => (state) => { state?.setHasHydrated(true); },
}
```

スコープ切替関数を追加（ストーリーの `switchStoryPersistenceScope` と同形。
チュートリアルの「再生中の一時状態」は `activePhase` / `activeStepIndex` / `bannerQueue`）:

```ts
export async function switchTutorialPersistenceScope(userId: string | null | undefined): Promise<void> {
  const nextScope = getTutorialPersistenceScope(userId);
  const nextStorageKey = getTutorialStorageKeyForScope(nextScope);
  const hasPersistedState = getSyncTutorialStorageItem(nextStorageKey) != null;

  setActiveTutorialScope(nextScope);

  if (!hasPersistedState) {
    useTutorialStore.setState({
      completedPhases: [],
      activePhase: null,
      activeStepIndex: 0,
      tutorialCompleted: false,
      viewedHints: [],
      bannerQueue: [],
      visitedTabs: [],
      hasHydrated: true,
    });
    return;
  }

  await useTutorialStore.persist.rehydrate();
  useTutorialStore.setState({
    activePhase: null,       // 再生途中の一時 UI 状態はスコープ跨ぎで持ち越さない
    activeStepIndex: 0,
    bannerQueue: [],
    hasHydrated: true,
  });
}
```

### 5-2. 配線: `src/hooks/useAuthFlow.ts`

`switchStoryPersistenceScope` を呼んでいる **4 か所すべて**で、隣に
`switchTutorialPersistenceScope` を同じ引数で呼ぶ（ストーリーとチュートリアルを必ずロックステップで切替）。

```ts
import { switchStoryPersistenceScope } from '../store/useStoryStore';
import { switchTutorialPersistenceScope } from '../store/useTutorialStore';

async function switchPersistenceScopes(userId: string | null | undefined) {
  await Promise.all([
    switchStoryPersistenceScope(userId),
    switchTutorialPersistenceScope(userId),
  ]);
}
```

| 行（現状） | 分岐 | 変更 |
|---|---|---|
| `useAuthFlow.ts:105` | セッション API 不在（guest） | `switchPersistenceScopes(null)` |
| `useAuthFlow.ts:121` | `session.user.id` 無し（authRequired） | `switchPersistenceScopes(null)` |
| `useAuthFlow.ts:131` | 認証ユーザー確定 | `switchPersistenceScopes(session.user.id)` |
| `useAuthFlow.ts:142` | キャラロード失敗 | `switchPersistenceScopes(null)` |

> 既存の `switchStoryPersistenceScope` 単独呼び出しを上記ヘルパに置換する形が最小差分。
> `cancelled` チェックの位置は現状（認証確定パスは await 後にチェック）を踏襲する。

## 6. 影響範囲とリスク

- 変更ファイル: `src/store/useTutorialStore.ts`（本体）、`src/hooks/useAuthFlow.ts`（配線）、
  `src/store/useTutorialStore.test.ts`（テスト）。
- リスク: **低〜中**。ストーリーで実績のある同一パターンの横展開。トリガーは idempotent
  （`startPhase` / `completeTutorial` が完了済みを弾く）なので二重発火は起きない。
- **移行に伴う既知の挙動**: スコープ化により、グローバルキーで既にチュートリアル完了済みだった
  ログインユーザーは、初回のみチュートリアルが再表示される（§7 でオプション移行を提示）。
  ストーリー側と同じ挙動で、許容範囲。

## 7. 付随する既知のエッジケース（ストーリー ST-1〜3 と同型・低優先）

ストーリー側 `TECH_DEBT.md` の ST-1〜ST-3 と**同じクラス**の問題がチュートリアルにも生じる。
いずれも実害は小さく現状スコープでは必須ではないが、将来 reload 経路を増やす際に再検討する。

- **TT-1（ST-1 相当）**: `reload` 毎に `switchTutorialPersistenceScope` が `activePhase` / `bannerQueue`
  をクリアするため、チュートリアル表示中に reload が走ると中断され得る。
  → スコープが同一なら一時状態クリアをスキップする。
- **TT-2（ST-2 相当）**: 並行 boot 時の rehydrate 競合。`Promise.all` で story/tutorial を同時に
  切り替えるなら、世代トークンで古い boot の反映を破棄する。
- **TT-3（ST-3 相当）**: フルリロード時、オートハイドレートがスコープマーカー
  （`necro-tutorial-store-scope-v1`）越しに前回ユーザーのデータを一瞬読む。トリガーは `player` 確定後の
  マウントでしか走らないため視覚的リークは無い。
- **オプション移行（任意）**: `switchTutorialPersistenceScope` 内で「user スコープが空 かつ
  グローバルキー `necro-tutorial-store-v2` にデータあり」のとき、1 度だけ user スコープへコピーすれば、
  既存ログインユーザーへのチュートリアル再表示を回避できる（ストーリー側も同様に未実装＝許容）。
