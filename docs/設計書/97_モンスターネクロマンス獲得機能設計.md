# 97. モンスターネクロマンス獲得機能設計

> 作成日: 2026-06-07  
> 対象: ステージクリア報酬、モンスター獲得、リザルトUI

> 2026-06-21 追記: 捕獲率の現行仕様は
> [120_死霊術Lv_Rank再設計.md](120_死霊術Lv_Rank再設計.md) を優先する。
> 敵マスターの `necromance.captureRate` は R1 基底値であり、実効捕獲率は
> `captureRate * rankMultiplier^(rank-1)` を `necroConfig.captureRate.cap`（既定 0.75）でクランプする。
> R1 時点の基底値も cap を超えない前提にする。

## 背景

現状のバトルリザルトは、経験値・ゴールド・装備/素材/残滓ドロップを表示するが、倒した敵をネクロマンスして使役モンスターとして獲得する導線がない。

ネクロマンスブレイブの中核体験として、ステージに出現した魔物を低確率で使役できる報酬を追加する。

## 目的

1. ステージに出現した全敵をネクロマンス抽選対象にする。
2. 各敵マスターIDにつき、プレイヤーが獲得できるのは1体までにする。
3. 通常ドロップと同じように、ステージクリア時にサーバーまたはローカルで確定抽選する。
4. 画面遷移を `リザルト画面 → ドロップ画面 → ネクロマンス結果画面` にする。
5. ネクロマンス成功が0体の場合、ネクロマンス結果画面は表示しない。
6. ボスモンスターのネクロマンス確率は極めて低くする。

## 非対象

- ネクロマンス確率を管理画面で編集する機能。
- モンスター図鑑、再抽選、天井、欠片化。
- Prismaスキーマ変更。既存の `Monster.masterId` を一度きり制約の判定キーとして利用する。

## 抽選仕様

ステージの `waves[].enemyIds` を走査し、敵マスターID単位で重複排除した候補を作る。召喚ギミックで戦闘中に追加された敵は、現時点ではステージマスターに明記された敵のみを対象にする。

所持済み判定は `Monster.masterId` で行う。ローカル状態では `MonsterData.masterId` を見て、なければ既存互換として `id` を補助的に見る。

| 敵Tier | 確率 | 方針 |
|---|---:|---|
| `MINION` | 12% | 序盤から使役魔が増える体験を作る |
| `ELITE` | 4% | 戦力更新として嬉しいが量産されない |
| `BOSS` | 0.1% | 極めて低確率の長期目標 |

1回のステージ内で同じ敵IDが複数回出ても、候補は1件にまとめる。成功した敵IDはその時点で所持済みセットへ追加し、同じ抽選処理内でも二重獲得しない。

## 生成仕様

ネクロマンス成功時は `EnemyData` から `MonsterData` を生成する。

| フィールド | 値 |
|---|---|
| `id` | `necro_${enemyId}_${uuid}` |
| `masterId` | 敵マスターID |
| `name` | `nameJa` 優先、なければ `name` |
| `tribe` | 敵の `tribe` |
| `cost` | MINION=1 / ELITE=2 / BOSS=4 |
| `stats` | 敵の `stats` |
| `resistances` | 敵の `resistances` |
| `tier` | 敵の `tier` |
| `weaknesses` | 敵の `weaknesses` |

## サーバー永続化

`processStageResultForUser` でステージ報酬を確定する時に、同じトランザクションで成功モンスターを `Monster` テーブルへ作成する。

- `masterId` に敵IDを保存する。
- `characterId` に現在キャラクターIDを保存する。
- `resistances` はJSONで保存する。
- 事前に所有済み `masterId` を取得し、成功候補から除外する。

旧 `GameManager.processStageResult` も同じ抽選と保存に対応させ、テストや将来の直接呼び出しでも挙動が揃うようにする。

## ローカル実行

Vite/Playwrightなどサーバーアクションを使わない環境では、Zustandの `inventoryMonsters` を参照して所有済みを判定する。成功モンスターはリザルト処理時に `inventoryMonsters` へ追加する。

## UI仕様

`ResultScreen` に `necromancedMonsters` を追加する。

1. サマリー画面では成功体数を「ネクロマンス反応」として表示する。
2. ドロップ鑑定画面を最後まで進める。
3. 成功体が1体以上なら `screen = "necromance"` へ遷移する。
4. 成功体が0体なら従来通り `onFinish()` で閉じる。
5. ネクロマンス結果画面では、成功したモンスターの名前、種族、Tier、コストを一覧表示する。

## テスト方針

- 純粋ロジックで、Tier別確率、ボス0.1%、所有済み除外、ステージ内重複排除をテストする。
- `RewardService` でステージからネクロマンス成功モンスターが生成されることをテストする。
- `GameManager.processStageResult` で `masterId` と `characterId` 付きでDB保存されることをテストする。
- 既存の全体Jestと型チェックを通す。
