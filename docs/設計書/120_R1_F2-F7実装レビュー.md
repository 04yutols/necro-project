## 2. フェーズ別レビュー

### F2 キャラ補正撤去（`StatSystem.ts`）
- `NecromanceLevelBonus` / `normalizeNecroBaseStatsBonus` / `calculateNecroBaseStatsContribution` / `normalizeNecromanceLevel` / `calculateNecromanceLevelBonus` を削除。
- `calculateCharacterStatProfile`: `necro = cloneZeroStats()`、passives/equipment/residue は `job` 基準に変更、`total` から necro 加算除去、`elementDmgBoosts` の necro マージ除去。✅ D3 完全。
- 回帰テスト: necroLevel **500 vs base が `total`/`elementDmgBoosts` で `toEqual`**（StatSystem.test.ts）。強い。

### F3 モンスター注入（`GameManager.ts` / `useGameStore.ts` / `BattleCanvas.tsx`）
- **server 単一注入点**: `GameManager.prepareBattle` で `rawMonsterList.map(m => applyNecroToMonster(m, level, getNecroConfig()))` → `new BattleEngine`。✅
- **client 単一注入点**: `buildBattlePartyFromState()` ＋ ストアセレクタ `getBattleParty()`。`BattleCanvas` は `battlePartyMonsters = useMemo(getBattleParty, [..necroStatus?.level..])` を**全ステ参照箇所**（メンバー表示・synergy・activeMonster・getActivePartyMonsters・monster energy 初期化・spendMonsterEnergy・init useEffect）へ展開。✅
- **raw-stat 漏れ検査**: 残存の生 `party` 参照は (a) `PartyStatusBar` の `party: BattlePartyMember[]`（=boost済み、別物）、(b) useMemo 依存配列のみ。3つの `calculateMonsterAttackProfile(monster, …)` の `monster` はすべて `activeMonster`(=`battlePartyMonsters`由来)。**漏れなし**。✅
- `resetMonsterHp` も `buildBattlePartyFromState` 経由に修正され、最大HPが boost 反映。✅（設計が見落としていた良い追加）
- 適用順序 `baseAtk × necroMult(stats焼込) × spiritCore × awakened1.5` を維持。✅

### F4 捕獲率Rank注入（`NecromanceCaptureSystem.ts` / `RewardService.ts` / `GameManager.ts` / `actions.ts` / `BattleCanvas.tsx`）
- `getNecromanceRateForEnemy(enemy, necroRank=1, cfg?)` が `applyNecroRankToCaptureRate` を呼ぶ（数式の二重持ちなし）。✅
- `rollStageNecromance` → `RewardService.processStageNecromance(stage, owned, necroRank)` → サーバー(`GameManager.processStageResult` / `actions.processStageResultForUser`)・client(`BattleCanvas.buildLocalStageResult`)すべてで `deriveNecroRank(level)` を伝播。✅

### F5 永続化・転生廃止（`PlayerSaveService.ts` / `playerSave.ts` / `NecroService.ts`）
- `PLAYER_SAVE_SCHEMA_VERSION=3`、union に `| 2` 追加。
- **v3 マイグレーション**: `newLevel = clamp((oldRank-1)*50 + oldLevel)`、`maxCost = max(calcNecroMaxCost(newLevel), oldMaxCost)`、rank/baseStatsBonus 破棄。設計§5.2 に一致。テストで `{99,rank2}→level149` を検証。✅
- `applyNecroExpGainToSave`: `necroExpFromGain`(×1.5) ＋ `necroLevelFromExp`(max500) ＋ maxCost 再計算。`Math.min(99,…)` 撤去。✅
- `normalizeNecroStatus` / `emptyPlayerSave`: rank/baseStatsBonus 除去、maxCost を level から導出（`max(derived, saved)`）。✅
- `performRankUp` / `rankUpNecroInSave` / `processGrowth(RANK_UP)` / `GrowthActionType=RANK_UP` を全削除。✅

### F6 管理画面（`necroConfig.json` / `MasterDataService.ts` / `admin/actions.ts` / `enemyBalance.ts` / `enemyAgent.ts` / `EnemyForm.tsx` / `NecroConfigForm.tsx` / `admin/necro-config/`）
- `necroConfig.json` は確定係数（kA0.006/kB0.0024/k2 0.05、base6/d1 10/c2 2、rankMult1.1/cap0.75、coef9/rate1.5）。`MasterDataService.getNecroConfig()` で公開。✅
- `saveNecroConfig`: `assertDev()` ＋ `assertValidNecroConfig` ＋ `writeJsonAtomic`。`auditMasterData` に `validateNecroConfigData` を統合。range は設計§6.1 に一致。✅
- `enemyBalance`: `captureRate > cap` を FAIL、`captureRate*1.10^9 > cap` を WARN、allyStats を「Lv1/R1基底」と明記。✅
- `enemyAgent` プロンプト: captureRate「0〜0.75・R1基底・R10で1.10^9倍」、allyStats「Lv1/R1基底・倍率は実行時自動適用」へ更新。✅

### F7 型整理
- `NecroStatus` から `rank`/`baseStatsBonus` 削除（level コメント max500）、`CharacterData.necroBaseStatsBonus` 削除。`NecroConfigData` 追加。tsc 0 で連鎖参照の解消を確認。✅
- 表示UI: `HomeHero` / `NecroLab` の RANK 表示を `deriveNecroRank(level)` に変更。HomeHero の necro EXP バーも `reqNecroExp`（necro曲線）基準に修正（旧 `getJobLevelProgress` 流用＝誤りを是正）。✅
