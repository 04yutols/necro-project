# 115_チュートリアルクリア後ホーム強制復帰設計

> 作成: 2026-06-14
> 目的: チュートリアルを発火させるステージを初回クリアした際、リザルト後に
> **ホーム画面へ強制的に戻し**、そこを起点にチュートリアルを発火させる。
> 前提: `114_チュートリアル再編成計画.md`（ステージクリア起点＋初回確定報酬）実装済み。
> ステータス: 計画段階（未実装）

---

## 1. 要件

- ステージ**初回クリア → リザルト確認 → ホーム画面へ自動遷移**（現状は MAP へ戻る）。
- ホーム到達後にチュートリアルバナー／スポットライトが発火する。
- 対象は「そのクリアでチュートリアルフェーズが発火するステージ」のみ
  （チュートリアルが無いクリアは従来どおり MAP へ戻す）。

## 3. 設計

### 3-1. 方針
戻り先タブの決定を「固定 `'MAP'`」から「**そのクリアでチュートリアルが発火するなら `'HOME'`、しなければ `'MAP'`**」に変える。
判定は `useTutorialTrigger` が持つ発火条件を**純関数に抽出して共有**し、二重管理を防ぐ。

### 3-2. 発火予測の純関数化（単一の真実）
現状 `useTutorialTrigger.ts` の if 連鎖に埋まっている「ステージクリア → フェーズ」条件を、純関数へ抽出する。

```ts
// 例: src/data/tutorial/triggers.ts（新規）
export function getTutorialPhaseAfterClear(input: {
  clearedStages: readonly string[];
  completedPhases: TutorialPhase[];
  storyFlags: Record<string, boolean>;
}): TutorialPhase | null
```
- `useTutorialTrigger` も `onEnd` も**この関数を使う**（条件のドリフト防止）。
- 戻り値が非 null なら「このクリアでフェーズが発火する」＝ホームへ戻すべき、と判定。

### 3-3. ナビゲーション分岐（`onEnd`）
```ts
// page.tsx onEnd（擬似コード）
onEnd={() => {
  setIsInBattle(false);
  setActiveStageAttemptId(null);

  const pending = getTutorialPhaseAfterClear({
    clearedStages: useGameStore.getState().player?.clearedStages ?? [],
    completedPhases: useTutorialStore.getState().completedPhases,
    storyFlags: useStoryStore.getState().storyFlags,
  });

  setCurrentTab(pending ? 'HOME' : 'MAP');   // ★チュートリアル発火時のみ HOME
}}
```
- `BATTLE_BASICS` は「バトル開始時」発火でクリア起点ではないため `getTutorialPhaseAfterClear` の対象外（従来どおり）。

### 3-4. ホーム到達後の発火 UX
1. `currentTab='HOME'` 着地 → `useTutorialTrigger` の effect が `startPhase()`＋`enqueueBanner()`。
2. `TutorialOrchestrator` が **バナー「◯◯が解放されました」をホームで表示**。
3. バナー CTA（例「確認する」）で該当 `requiredTab`（EQUIP/LAB/JOB）へ遷移し、スポットライト開始。
   - スポットライトは `requiredTab` 一致時のみ表示される既存仕様（`phases.ts` の `requiredTab`）を流用。

### 3-5. 「強制」の度合い（サブ決定）
- 最小案: 遷移先を HOME に強制するのみ（バナーはスキップ可能）。
- 強制案: ホームのバナーをモーダル化し、CTA を踏むまで他操作を抑止（より強い誘導）。

## 5. 既存設計との整合（矛盾チェック）

- **戻り先決定は 1 箇所**（`page.tsx:339`）に集約されており、他に MAP 復帰経路は無い（敗北時は別 `setBattleResult(isVictory:false)`、リトライ/撤退は MAP 維持で従来どおり）。HOME 強制は勝利かつチュートリアル発火時に限定。
- **タイミング安全**: 報酬・`clearedStages` は ResultScreen 表示前に確定済み（§2）。`onEnd` 判定は確定後で安全。
- **二重管理の回避**: 発火条件を純関数化し `useTutorialTrigger` と `onEnd` で共有するため、片方だけ変えて挙動がずれる事故を防ぐ。
- **`114` との関係**: `114` はフェーズ構成・確定報酬を定義。本書(`115`)は「発火タイミングの着地点（HOME 強制）」のみを足す**追加レイヤー**で、`114` の発火表を出典として再利用（変更しない）。
- **全画面オーバーレイ規約**: HOME は `ResponsiveFrame` 内（`page.tsx`）。MAP/BATTLE のみ全画面。HOME 着地は通常タブ表示で iOS Safari 規約（overflow+transform 分離）に影響しない。
