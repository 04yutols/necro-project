# BUG-10 軍団追撃ターゲット分散設計

> 作成日: 2026-05-26
> 対象: `src/logic/BattleEngine.ts`, `src/components/battle/BattleCanvas.tsx`, `src/logic/BattleEngine.test.ts`

## 1. 背景

軍団追撃は、プレイヤー行動後に編成中の最大3体の魔物が追加攻撃する死霊術の中核要素である。

既存の `BattleEngine.processMonsterActions()` はプレイヤーが選択した `target` だけを受け取り、全モンスターが同じ対象へ追撃していた。

```ts
private processMonsterActions(target: MonsterData): void {
  monsters.forEach(monster => {
    // 全モンスターが同じ target を攻撃する
  });
}
```

単体敵だけの戦闘では問題が見えにくいが、複数敵WAVEでは追撃が選択敵だけに集中し、他の生存敵へ流れない。

## 2. 問題

- 複数敵WAVEで、軍団追撃が戦場全体へ広がらない。
- 選択敵がプレイヤー攻撃で倒れた後も、追撃対象の再選択契約がBattleEngineにない。
- UI側の `BattleCanvas` は複数敵を持つが、追撃対象選択が「選択敵が生きていれば常に選択敵」だったため、3体編成でも実質集中砲火になっていた。

## 3. 設計方針

### 3.1 ターゲット候補

BattleEngineの既存互換を保つため、`simulateAction()` に任意の `enemyCandidates` を追加する。

```ts
simulateAction(actionType, target, skillId?, enemyCandidates?)
```

| 呼び出し | 挙動 |
|---|---|
| `enemyCandidates` なし | 従来通り `target` のみを候補にする |
| `enemyCandidates` あり | `target` を先頭優先にしつつ、候補内の生存敵から追撃対象を選ぶ |

### 3.2 追撃対象の分散ルール

追撃ごとに生存敵リストを作り直し、以下の順で並べる。

1. プレイヤーが攻撃した対象が生存していれば先頭
2. その他の生存敵を候補配列の順で続ける

その上で、追撃回数 `followUpIndex` に応じてローテーションする。

```ts
target = aliveTargets[followUpIndex % aliveTargets.length]
```

例:

| 生存敵 | 追撃1 | 追撃2 | 追撃3 |
|---|---|---|---|
| A/B/C、Aを選択 | A | B | C |
| A/B、Aを選択 | A | B | A |
| A撃破済み、B/C生存 | B | C | B |
| Bのみ生存 | B | B | B |

### 3.3 死亡ターゲットの扱い

追撃前にプレイヤー攻撃で選択敵が倒れている場合、その敵は `aliveTargets` に入らない。

生存敵が0体なら追撃ログもダメージも発生しない。

### 3.4 BattleCanvasとの整合

UIバトルはBattleEngineを直接再生せず、`BattleCanvas.tsx` 内で戦闘演出とダメージを進める。そのため、BattleCanvasの `runPartyFollowUps()` も同じローテーションルールに揃える。

## 4. 実装

### 4.1 BattleEngine

- `simulateAction()` に `enemyCandidates?: MonsterData[]` を追加。
- `resolveEnemyCandidates()` で `target` を先頭にした重複なし候補を作る。
- `selectFollowUpTarget()` で生存敵ローテーションを解決。
- `processMonsterActions()` は追撃ごとに対象を選び直す。

### 4.2 BattleCanvas

- `getLiveFollowUpTargetId(preferredTargetId, followUpIndex)` へ変更。
- `runPartyFollowUps()` 内で `followUpIndex` を進め、追撃先をローテーションする。

## 5. テスト方針

`src/logic/BattleEngine.test.ts` に以下の回帰テストを追加する。

| テスト | 確認内容 |
|---|---|
| 複数敵分散 | 3体の追撃が A/B/C に分散する |
| 選択敵撃破後の再選択 | プレイヤー攻撃で選択敵が倒れた場合、追撃が生存敵へ流れる |

## 6. 完了条件

- 複数敵候補がある場合、全追撃が必ず同一ターゲットへ固定されない。
- 選択敵が倒れている場合、生存敵へ追撃が再選択される。
- `enemyCandidates` なしの既存単体敵呼び出しは互換維持。
- BattleEngine単体テスト、全Jest、型検査、ビルドが成功する。
