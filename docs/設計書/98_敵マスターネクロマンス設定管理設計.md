# 98. 敵マスターネクロマンス設定管理設計

> 作成日: 2026-06-07  
> 対象: `enemies.json`、管理画面、ネクロマンス抽選、獲得モンスター永続化

## 背景

前回実装したモンスターネクロマンス獲得は、敵のTierごとの固定確率と敵ステータスのコピーで動作している。
そのため管理画面から「この敵をどれくらい仲間にできるか」「仲間にした時の性能はどうするか」「どのスキルを持つか」を調整できない。

今後のゲームバランス調整では、敵としての強さと味方化後の強さを分けて管理できる必要がある。

## 目的

1. `enemies.json` に `necromance` セクションを追加する。
2. 管理画面の敵編集で、ネクロマンス獲得確率、味方化後コスト、味方化後ステータス、スキルを確認・編集できるようにする。
3. ネクロマンス抽選は `necromance.captureRate` を優先し、未設定時は従来のTier固定値にフォールバックする。
4. 獲得モンスターは `necromance.allyStats`、`necromance.allyCost`、`necromance.skillIds` を使って生成する。
5. サーバー保存後も味方化後スキルが失われないように、`Monster.skillIds` をDBに永続化する。

## 非対象

- 味方モンスターが戦闘中にスキルを自動使用するAI。
- モンスターごとのレベルアップ、スキル解放レベル、スキル強化。
- ネクロマンス確率の天井、補正、チケット消費。

## JSON仕様

`enemies.json` の各敵に以下を追加する。

```json
"necromance": {
  "captureRate": 0.12,
  "allyCost": 1,
  "allyStats": {
    "hp": 15,
    "atk": 4,
    "def": 3,
    "spd": 70,
    "critRate": 0,
    "critDmg": 150,
    "effectHit": 0,
    "effectRes": 0
  },
  "skillIds": []
}
```

| フィールド | 必須 | 説明 |
|---|---:|---|
| `captureRate` | 任意 | 0〜1。設定時はTier固定確率より優先する。 |
| `allyCost` | 任意 | 編成コスト。未設定時は MINION=1 / ELITE=2 / BOSS=4。 |
| `allyStats` | 任意 | 味方化後ステータス。未設定時は敵の `stats` をコピーする。 |
| `skillIds` | 任意 | 味方化後に保持するスキルID配列。空配列可。 |

全既存敵には初期値として、従来挙動と同じ `captureRate`、`allyCost`、`allyStats` を付与する。`skillIds` は空配列を基本とし、バランス上必要な敵だけ既存スキルIDを設定する。

## 抽選・生成仕様

ネクロマンス候補は従来通りステージ `waves[].enemyIds` を敵ID単位で重複排除する。

抽選確率:

1. `enemy.necromance.captureRate` が有効な数値ならその値を0〜1に丸めて使う。
2. 未設定ならTier固定値を使う。

味方化生成:

1. `id` は `necro_${enemyId}_${uuid}`。
2. `masterId` は敵ID。
3. `name` は `nameJa` 優先。
4. `cost` は `necromance.allyCost` 優先。
5. `stats` は `necromance.allyStats` 優先。
6. `skillIds` は `necromance.skillIds` をコピーする。

## 管理画面仕様

`/admin/enemies/[id]` の敵編集フォームに「ネクロマンス」タブを追加する。

- 獲得確率はパーセント入力で表示し、保存時は0〜1の小数へ変換する。
- 味方化後コストは数値入力。
- 味方化後ステータスは既存の `StatInputGrid` を再利用する。
- スキルは `skills.json` から名前付き選択肢を表示し、ID直入力を避ける。
- 未登録スキルIDが既存データに残っている場合は「未登録: id」として表示し、削除・置換できるようにする。

## 永続化仕様

Prisma `Monster` に `skillIds Json @default("[]")` を追加する。

サーバーのステージ結果保存時:

- `Monster.skillIds` に `MonsterData.skillIds` を保存する。

プレイヤーデータ取得時:

- DBの `skillIds` を `MonsterData.skillIds` へ復元する。

## 監査仕様

管理画面監査と `data:audit` で以下を検証する。

- `necromance.captureRate` は0〜1。
- `necromance.allyCost` は1以上。
- `necromance.allyStats` がある場合は全ステータスが数値かつ0以上。
- `necromance.skillIds[]` は `skills.json` に存在する。

## テスト方針

- 純粋ロジックで、敵ごとの `captureRate` がTier固定値より優先されることを確認する。
- `allyCost`、`allyStats`、`skillIds` が `MonsterData` に反映されることを確認する。
- `RewardService` でマスターJSON由来の設定が使われることを確認する。
- `GameManager.processStageResult` で `skillIds` がDB保存されることを確認する。
- `data:audit --strict`、型チェック、全Jest、production build を通す。
