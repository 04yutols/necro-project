# 95 — エリアマップ管理とステージ反映設計

> 作成日: 2026-06-05  
> 対象: ワールドマップ → エリアマップ → ステージ選択の管理画面連携  
> ステータス: 実装対象

---

## 1. 現状調査

### 1.1 できていること

- ステージは `/admin/stages` から `stages.json` へ作成・編集・削除できる。
- プレイ画面の `AreaMap.tsx` は `stages.json` を読み、全ステージを `getStageList()` で並べて表示している。
- ステージの `position.x/y` は管理画面から編集でき、エリアマップ上のノード座標に反映される。
- `unlockRequires` を追加すれば、ステージ解放条件と線の接続はプレイ画面に反映される。

### 1.2 不足していること

- エリアは独立した管理対象ではなく、ステージの `chapter` / `area` / `chapterName` から暗黙的に作られている。
- ワールドマップ上のエリア名英字、説明文、色、座標は `AreaMap.tsx` の `WORLD_AREA_META` に固定されている。
- エリアの識別が `area` 数値だけなので、第1章Area1と第2章Area1を追加すると同じエリアとして混ざる。
- `StageForm` の `areaGimmick` 選択肢が現行型とズレており、`STATUS_AILMENT` / `SLIP_DAMAGE` をGUIで選びづらい。
- 古い `MapCanvas.tsx` は `area === 1` 固定だが、現在のSPAでは `AreaMap.tsx` が使われており実導線では未使用。

---

## 2. 設計方針

### 2.1 エリアを独立マスター化する

`src/data/master/areas.json` を追加し、ワールドマップ上のエリア表示情報を管理画面から編集できるようにする。

```typescript
export interface AreaData {
  id: string;
  chapter: number;
  area: number;
  nameJa: string;
  nameEn: string;
  description: string;
  color: string;
  position: { x: number; y: number };
  sortOrder?: number;
}
```

エリアIDは `ch{chapter}_area{area}` を推奨する。
例: `ch1_area1`, `ch2_area2`。

### 2.2 ステージは `chapter + area` でエリアを参照する

`StageData` には既に `chapter` と `area` が存在するため、新しい外部キーは追加しない。
代わりに以下の複合キーでエリアを解決する。

```text
areaKey = `${stage.chapter}:${stage.area}`
```

これにより、第1章Area1と第2章Area1を別エリアとして扱える。

### 2.3 プレイ画面の表示経路

```text
areas.json
  └─ ワールドエリアの表示名・説明・色・座標

stages.json
  └─ 各エリア内のステージノード・解放条件・報酬・WAVE

AreaMap.tsx
  ├─ areas.json と stages.json を読み込む
  ├─ chapter + area でグルーピング
  ├─ ワールドマップにエリアノードを表示
  └─ エリアマップにステージノードを表示
```

`areas.json` に登録済みでステージが0件のエリアもワールドマップには表示する。
ただしステージがないエリアは `LOCKED` 扱いにし、エリアマップへ入れない。

### 2.4 管理画面

`/admin/areas` を追加する。

| ルート | 内容 |
|---|---|
| `/admin/areas` | エリア一覧 |
| `/admin/areas/new` | 新規エリア作成 |
| `/admin/areas/[id]` | エリア編集 |

編集可能フィールド:

- `id`
- `chapter`
- `area`
- `nameJa`
- `nameEn`
- `description`
- `color`
- `position.x`
- `position.y`
- `sortOrder`

### 2.5 監査

管理画面監査とCLI監査に以下を追加する。

- `areas.json` の `id` がキーと一致する。
- `chapter` / `area` が1以上の整数。
- `color` が `#RRGGBB`。
- `position.x/y` が数値。
- 各ステージの `chapter + area` に対応するエリアが `areas.json` に存在する。

## 4. 受け入れ条件

- 管理画面からエリアを追加・編集できる。
- 管理画面からステージを追加し、既存または新規エリアの `chapter/area` に紐づけられる。
- プレイ画面は `areas.json` と `stages.json` を読み、追加したエリア/ステージを表示対象に含める。
- 第1章Area1と第2章Area1が混ざらない。
- 既存の第1章/第2章導線は維持される。
- `areaGimmick` は `NONE` / `SLIP_DAMAGE` / `STATUS_AILMENT` の現行仕様から選べる。
