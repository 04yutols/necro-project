# 82 — マスターデータ管理ツール仕様書

> 作成日: 2026-05-31  
> 目的: 敵データ・ダンジョン・職業・スキルなどのマスターデータを GUI で作成・編集できるツールの設計仕様

---

## 1. 概要

### 1.1 ツールの目的

`src/data/master/*.json` を直接テキスト編集することなく、構造化 UI でマスターデータを作成・確認・修正するための **管理ツール**。

現状の課題:
- JSON を手書きするとフィールド漏れ・ID 不一致が起きやすい
- 依存関係（「この敵が出るステージ」「このスキルを持つ職業」）が視覚化されていない
- ダメージ計算や防壁ギミックを変えた際の数値確認が手動

### 1.2 ツールの種別・配置

| 項目 | 仕様 |
|---|---|
| 実装形式 | **既存 Next.js アプリ内の `/admin` ルート** |
| 認証 | 開発環境限定（`NODE_ENV=development` のみ到達可能）、本番は 403 |
| URL | `http://localhost:3000/admin` |
| 技術スタック | React 19 + Tailwind CSS v4 + Framer Motion（ゲーム本体と共有） |
| データ保存 | ブラウザ上で編集 → 「JSONコピー」ボタンで手動ペーストによる反映 |

> **設計判断**: ファイルシステムへの直接書き込みは Server Action 経由で可能だが、誤操作で本番データを壊すリスクを避け、初版は **「確認 → コピー → ペースト」** フローを採用する。後続フェーズでファイル保存機能を追加可能。

### 4.1 敵データ管理（enemies.json）

#### 4.1.1 一覧パネル

| 表示項目 | 詳細 |
|---|---|
| エントリカード | `nameJa` / `nameEn` / `tier` バッジ / `tribe` バッジ |
| フィルタ | tier（MINION / ELITE / BOSS）、tribe（6種族）|
| ソート | HP / ATK / DEF / SPD |
| 検索 | ID・名称の部分一致 |

#### 4.1.2 編集フォーム

**基本情報タブ**

| フィールド | 入力種別 | バリデーション |
|---|---|---|
| `id` | テキスト（スネークケース強制） | JSON キーと一致必須 |
| `name`（英名）| テキスト | 必須 |
| `nameJa`（日本語名）| テキスト | 必須 |
| `nameEn`（表示用大文字）| テキスト | 自動生成可 |
| `tier` | セレクトボックス | MINION / ELITE / BOSS |
| `tribe` | セレクトボックス | 6種族 |
| `description` | テキストエリア | — |

**ステータスタブ**

8種ステータス（hp / atk / def / spd / critRate / critDmg / effectHit / effectRes）をスライダー＋数値入力で設定。

同 tier の他エネミーの平均値を薄く表示し、バランス参考値として提供する。

**属性耐性タブ**

9属性（FIRE / WATER / THUNDER / EARTH / WIND / ICE / LIGHT / DARK / NONE）の耐性値を `-100 〜 +100` のスライダーで設定。

- 負値 = 弱点（赤）、正値 = 耐性（青）のカラーフィードバック
- `weaknesses` 配列は耐性値が -1 以下のものを自動抽出して表示

**ギミックタブ**（ELITE / BOSS のみ）

| フィールド | 入力種別 |
|---|---|
| `shieldHp` | 数値スピナー |
| gimmick 追加 | trigger × effect × value のテーブル行追加 |

trigger: `HP_BELOW_50` / `TURN_3` / `ON_SHIELD_BREAK`  
effect: `ENRAGE` / `AV_DELAY` / `REVIVE` / `SUMMON_MINIONS`

**ドロップテーブルタブ**

ドロップ行を追加・削除できるテーブル。

| フィールド | 入力種別 |
|---|---|
| `type` | WEAPON / MATERIAL / RESIDUE / CONSUMABLE |
| `itemId` | セレクト（items.json / materials.json から選択） |
| `rarity` | R / SR / SSR / UR |
| `rate` | 0.01 〜 1.00 スライダー |
| `isHidden` | チェックボックス（UR 非掲載フラグ） |

rate の合計が 3.0 を超えるとWarning表示。

**バトル表示タブ**

| フィールド | 入力種別 |
|---|---|
| `battle.color` | カラーピッカー |
| `battle.sprite` | セレクト（WRAITH / KNIGHT / DRAGON / DEMON 等） |
| `battle.size` | 0.5 〜 1.5 スライダー |

## 5. 横断機能

### 5.1 データ監査パネル

ナビバー右端の「監査」ボタンから展開。

- 内部で `npm run data:audit` に相当するロジックを実行
- 結果を PASS / WARN / FAIL でカテゴリ別に表示
- 問題のあるエントリ ID をクリックすると対象の編集フォームへジャンプ

```
PASS  enemies: 全 ID が一致
WARN  stages/area1_node3: dropTable rate 合計が 2.8（参考値超え）
FAIL  skills/skill_warrior_3: jobs.json に参照元なし（未使用）
```

### 5.2 依存関係タブ（各エントリの詳細に追加）

「このデータを参照しているエントリ」を横断検索して表示。

例:
- `grave_soldier`（敵）→「area1_node1 WAVE1 / area1_boss WAVE1 に配置されている」
- `skill_warrior_1`（スキル）→「warrior Lv1 で解放される」
- `bone_cleaver`（武器）→「grave_soldier / rot_hound のドロップテーブルに存在」

### 5.3 JSON プレビュー

編集フォームと並んで「JSON」タブを切り替えると、現在のフォーム入力から生成した JSON を表示。

- `[JSONコピー]` ボタンで該当エントリのみクリップボードコピー
- `[全体コピー]` ボタンで対象ファイル全体をコピー（マージは手動）
- JSON は整形済み（2スペースインデント）

### 5.4 ダメージシミュレータ（全体版）

ナビバー上部に「シミュレータ」タブ（または監査ドロップダウン内）として提供。

入力:
- 攻撃キャラクター: 職業 × レベル × 武器（任意）
- 対象スキル: スキルセレクト
- 対象敵: 敵セレクト or カスタムステータス入力
- 種族シナジー有無

出力:
- 通常ダメージ / クリティカルダメージ / 期待値
- 防壁ありの場合の軽減後ダメージ
- 霊魂砕きに必要な累積ダメージ（ELITE/BOSS）

## 7. 技術設計

### 7.1 データ読み込み

`MasterDataService.getInstance()` は singleton だが、管理ツール側では **ファイルシステムから直接 JSON を読む Server Action** を用意し、ゲームランタイムと分離する。

```typescript
// src/app/admin/actions.ts
'use server'
import fs from 'fs'
import path from 'path'

export async function readMasterFile(filename: string): Promise<object> {
  if (process.env.NODE_ENV !== 'development') throw new Error('admin only in dev')
  const p = path.join(process.cwd(), 'src/data/master', filename)
  return JSON.parse(fs.readFileSync(p, 'utf-8'))
}

export async function writeMasterFile(filename: string, data: object): Promise<void> {
  if (process.env.NODE_ENV !== 'development') throw new Error('admin only in dev')
  const p = path.join(process.cwd(), 'src/data/master', filename)
  fs.writeFileSync(p, JSON.stringify(data, null, 2), 'utf-8')
}
```

### 7.2 状態管理

- 各セクションの編集状態は **ローカル `useState`** で管理（Zustand 不使用）
- フォームの変更検出: 初期値との deep equal で「未保存変更あり」バッジを表示
- JSON コピー: `navigator.clipboard.writeText()` で実装

### 7.3 バリデーション

既存スクリプト `scripts/master-data-audit.mjs` のロジックをモジュール化して再利用。

```typescript
// src/lib/admin/dataAudit.ts
export function auditAllFiles(): AuditResult[]
export function auditEntry(type: DataType, id: string): AuditResult
```

クライアント側でのリアルタイムバリデーションと、「実行」ボタン押下での完全バリデーション両方に対応。

### 7.4 ダメージシミュレータ

`src/logic/BattleEngine.ts` の `calculateDamage()` をそのまま import して計算。  
BattleEngine 自体はピュアクラスなので、サーバー/クライアント両方から呼び出し可能。

## 8. UI デザイン仕様

### 8.1 デザイン方針

- ゲーム本体の Gothic-Morphism（Void Purple `#8B00FF`）を継承しつつ、**管理ツールらしい視認性** を優先
- 暗色背景は維持するが、フォームフィールドは `bg-zinc-800` で十分な明度を確保
- エラー / 警告は赤 / 黄のシンプルな badge で表示

### 8.2 カラーパレット（管理ツール追加分）

| 用途 | カラー |
|---|---|
| 背景 | `#0d0d0f`（ゲームと共通）|
| パネル背景 | `#1a1a1f` |
| フォームフィールド | `#27272a`（zinc-800）|
| アクセント | `#8B00FF`（Void Purple）|

## 10. 制約・除外事項

| 項目 | 判断 |
|---|---|
| 本番環境での動作 | 除外（`NODE_ENV !== development` で 403）|
| 認証（ログイン）| 除外（ローカル開発専用のため不要）|
| 多人数同時編集 | 除外（個人開発ツールのため）|
| 深淵の残滓（AbyssalResidue）のランダム生成設定 | 除外（ResidueScore ロジックが複雑なため Phase 4 以降）|
| 画像・スプライトのアップロード | 除外（PixiJS スプライト管理は別途）|
