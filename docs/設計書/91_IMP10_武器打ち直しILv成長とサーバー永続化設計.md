# IMP-10 武器打ち直しILv成長とサーバー永続化設計

> サブオプションのレアリティ別倍率と枠数は、後続の `92_IMP11_武器レアリティ別サブオプション再設計.md` を優先する。

> 作成日: 2026-06-01  
> 対象: `src/logic/WeaponSystem.ts`, `src/store/useGameStore.ts`, `src/app/actions.ts`, `src/components/legion/LegionHub.tsx`, `prisma/schema.prisma`  
> 関連: `13_武器システム.md`, `14_武器UIUX実装設計.md`, `81_IMP9_序盤バランスと戦闘後MP全回復再設計.md`

## 1. 目的

現行の打ち直しは `ILv.40 / 60 / 80 / 90` へ段階的にジャンプするため、武器を少しずつ育てる手触りがない。
また、クライアントストアだけで素材消費と強化結果を保持しているため、ログイン後の再読込で状態が失われる。

本対応では以下を満たす。

- 打ち直し1回につき `ILv + 1` とする。
- メインステータスである武器基礎ATKは、すべてのILv上昇で必ず1以上増加する。
- サブステータスは `ILv.20 / 40 / 60 / 80` 到達時に一定倍率で成長する。
- `R / SR / SSR / UR` で最終ATK、サブステ成長率、素材コストに明確な差を設ける。
- 共鳴、打ち直し、分解をサーバーのトランザクションへ接続し、素材と武器状態を同時に永続化する。
- IMP-9で再設計した序盤4〜5ダメージ帯を壊さない。

## 2. 用語と責務

| 用語 | 役割 |
|---|---|
| `ILv` | 打ち直しで1ずつ上げる武器レベル。範囲は `1〜90` |
| 魂の共鳴 `rank` | 同レアリティのイデアを消費してパッシブを強化する段階。範囲は `0〜5` |
| メインステータス | 武器基礎ATK。ILvごとに必ず成長する |
| サブステータス | `ATK%`, `CRIT_RATE%`, `CRIT_DMG%` 等。20ILvごとに倍率成長する |
| 深淵の黒鋼 | ILv上昇に使う基本素材 |
| イデア | 共鳴と20ILv節目の打ち直しに使うレアリティ別素材 |

`WeaponSystem.ts` を計算の正とし、クライアントとサーバーで同じ純粋関数を使用する。

## 3. ILv成長方式

### 3.1 打ち直し単位

```
nextILv = currentILv < 90 ? currentILv + 1 : null
```

旧仕様の `1 → 40 → 60 → 80 → 90` は廃止する。ボタン1回、素材消費1回、サーバートランザクション1回で `ILv + 1` を確定する。

### 3.2 Lv90基礎ATKテーブル

| レアリティ | LOW | MID | HIGH | MYTHIC |
|---|---:|---:|---:|---:|
| R | 90 | 100 | 110 | - |
| SR | 115 | 130 | 145 | - |
| SSR | 145 | 165 | 185 | - |
| UR | - | - | - | 220 |

序盤の初期武器 `bone_cleaver` は `R / MID / ILv.1` のため、武器基礎ATKは `1` のまま維持する。
これによりIMP-9の序盤ダメージ帯を保持しつつ、終盤ではレアリティ差を明確にする。

### 3.3 メインステータス式

```
WeaponBaseATK =
  ILv
  + floor((Lv90BaseATK - 90) × (ILv - 1) / 89)
```

すべての `Lv90BaseATK` を `90` 以上にすることで、次を保証する。

- `ILv.1` は全武器で基礎ATK `1`
- `ILv.90` はテーブル値と一致
- `ILv + 1` ごとに基礎ATKが必ず1以上増加

ドロップ時点で高ILvの武器は即戦力になるが、初期武器を育てても無駄にならない緩やかな曲線とする。

## 4. サブステータス成長

### 4.1 節目

```
subStatGrowthStep = floor(ILv / 20)
```

| ILv | 成長段階 |
|---|---:|
| 1〜19 | 0 |
| 20〜39 | 1 |
| 40〜59 | 2 |
| 60〜79 | 3 |
| 80〜90 | 4 |

ILvを毎回上げる喜びはメインATKで保証し、サブステは20ILvごとの節目でまとまった伸びを見せる。

### 4.2 レアリティ別成長率

| レアリティ | 1節目ごとの加算倍率 | ILv.80以降の合計倍率 |
|---|---:|---:|
| R | +5.0% | 1.20x |
| SR | +7.5% | 1.30x |
| SSR | +10.0% | 1.40x |
| UR | +12.5% | 1.50x |

既存のアーキタイプ係数と組み合わせる。

```
EffectiveSubOption =
  masterValue
  × archetypeCoefficient
  × (1 + subStatGrowthStep × rarityGrowthRate)
```

アーキタイプ係数は `LOW 1.2 / MID 1.0 / HIGH 0.8 / MYTHIC 1.25` を維持する。
高ATK型はサブステを抑え、低ATK型はビルド特化に向く既存の役割を残す。

## 5. 素材コスト

### 5.1 打ち直し

1回の打ち直しで次ILv帯とレアリティに応じた深淵の黒鋼を消費する。

| 次ILv帯 | R | SR | SSR | UR |
|---|---:|---:|---:|---:|
| 2〜20 | 1 | 2 | 3 | 4 |
| 21〜40 | 2 | 3 | 4 | 5 |
| 41〜60 | 3 | 4 | 5 | 6 |
| 61〜80 | 4 | 5 | 6 | 8 |
| 81〜90 | 5 | 6 | 8 | 10 |

`ILv.20 / 40 / 60 / 80` 到達時のみ、サブステ解放の節目としてレアリティ対応イデアを1個追加消費する。
URは固定完凸かつ専用レア枠のため、通常イデアを要求せず深淵の黒鋼だけを重くする。

### 5.2 共鳴と分解

- 共鳴は既存通り、ランクに応じた同レアリティのイデアを消費する。
- 共鳴はパッシブ強化だけを担い、メインATKとサブステへ影響しない。
- 分解は既存通りイデアへ変換し、URは分解不可とする。

### 5.3 初回導線

新規作成キャラクターへ以下のチュートリアル素材を付与する。
既存アカウントにもマイグレーションで同じ初回パックを一度だけバックフィルする。

| 素材 | 個数 | 意図 |
|---|---:|---|
| 深淵の黒鋼 | 10 | 初期R武器を複数回打ち直して毎ILv成長を確認できる |
| 凡骨のイデア | 8 | 初期配布済みR1武器をR2へ共鳴し、強化を1回確認できる |

上位イデアはドロップと分解で獲得する。

## 6. サーバー永続化

### 6.1 Prisma

ユーザー単位の素材スタックを追加する。

```prisma
model WeaponMaterial {
  userId   String
  type     String
  name     String
  quantity Int    @default(0)

  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@id([userId, type])
}
```

武器本体は既存 `Item` の `rank`, `archetype`, `ilv`, `passiveA`, `passiveB`, `subOptions`, `atk` を使用する。

### 6.2 Server Action

以下を追加する。

| Action | 処理 |
|---|---|
| `rankUpWeaponAction(characterId, weaponId)` | 所有権確認、素材減算、`rank + 1` |
| `reforgeWeaponAction(characterId, weaponId)` | 所有権確認、素材減算、`ILv + 1`、`atk` 再計算 |
| `dismantleWeaponAction(characterId, weaponId)` | 所有権確認、装備中拒否、素材加算、武器削除 |

各Actionはサーバー上で再計算し、クライアントからコストや強化後数値を受け取らない。

### 6.3 トランザクション境界

素材不足による途中失敗を防ぐ。

```
transaction:
  1. character.userId === session.user.id を確認
  2. item.ownerId === session.user.id && item.type === WEAPON を確認
  3. quantity >= cost の素材だけを decrement
  4. 武器更新または削除
  5. 分解時は報酬素材を upsert increment
```

素材減算には `quantity >= cost` 条件を含め、同時操作でも負数を許可しない。

## 7. クライアント連携

- ゲストモードは既存Zustandアクションで同じ純粋関数を使用する。
- ログイン済みモードはサーバーActionを呼び、成功後に `loadFromServer()` で再読込する。
- サーバーロード済みかはZustandの `isServerBacked` で明示し、App Routerの実装詳細へ依存しない。
- ログイン済みモードではクライアント先行更新を行わない。サーバーを正として二重クリックや通信失敗時の表示ずれを避ける。
- UIには「ILv.+1」「ATKは毎回上昇」「サブステは20ILvごとに強化」を明示する。

## 8. テスト計画

### Unit Test

- 全レアリティ、全ILvで `WeaponBaseATK(next) > WeaponBaseATK(current)` を確認する。
- `ILv.19 → 20` でサブステが伸び、`20 → 39` では変化しないことを確認する。
- レアリティごとのサブステ成長率差を確認する。
- 打ち直しが常に `ILv + 1` であり、節目だけイデアを要求することを確認する。
- 上限 `ILv.90` で打ち直し不可になることを確認する。

### DB結合テスト

- 新規作成時にチュートリアル素材が永続化されることを確認する。
- 打ち直し後に `ilv`, `atk`, 素材残数がDB再読込後も維持されることを確認する。
- 素材不足時に武器と素材が変化しないことを確認する。
- 分解時に装備中武器を削除できないことを確認する。
