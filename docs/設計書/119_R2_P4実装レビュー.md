## 良い点

1. **マイグレーションのデータ安全性** — `ADD COLUMN`→孤児キャラに移行用Userを付与→`playerState` バックフィル
   （`COALESCE(既存blob, 旧列)`＝blob優先を維持）→`SET NOT NULL`→`DROP`。確定前に破壊しない順序。
2. **防御的バックフィル** — int/float キャスト前に正規表現ガード（`~ '^[0-9]+$'`）、配列は
   `jsonb_typeof = 'array'` 検査、jobs/weaponMaterials は「blob→旧テーブル集約→既定」の多段フォールバック。
3. **孤児キャラ救済** — `userId IS NULL` を削除せず `p4-orphan-*` User を生成してから
   `userId` を NOT NULL＋UNIQUE 化。
4. **アプリ側の徹底適応** — 全 `select/include` から旧列を除去、`toServerGameData` はブロブ専用化、
   `findFirst`→`findUnique`（userId unique 活用）、`buildPlayerSaveFromDb` と危険だった
   `tx.weaponMaterial.findMany` を撤去、`loadCharacter` のランタイム・バックフィルも削除。
5. **基礎ステータスDROPの安全性** — 全12職業が `baseStatsByLevel`（Lv1-100）完備のため
   `getJobBaseStatsAtLevel` は常にマスター表を採用し、DROPで0化した第3引数を消費しない。
   actions.ts は引数自体も除去済み。
6. **ドキュメント追従** — doc 119 のステータス・P4実装メモを更新。

## 指摘事項

### 🟡 F1.（**P5で実施予定 — 今回は未対応**）ブロブが唯一の真実 → 破損/未知バージョンの blob はサイレント初期化
旧列削除により、`readPlayerSave` は schemaVersion 不一致・破損時に
`emptyPlayerSave()`（Lv1・gold 50000・進行ゼロ）へフォールバック＝**静かなデータ消失**。
マイグレーションが完全化を保証するので現状は安全だが、
- blob 破損時の復旧手段が無い（旧列という保険が消えた）
- 将来 `PLAYER_SAVE_SCHEMA_VERSION` を 2 に上げた瞬間、**全 v1 blob が初期化**される。

**対応方針: P5（schema_version 前方マイグレーション関数 v1→v2…）で実施する。**
schemaVersion を引き上げる前に前方移行を必ず先行実装し、`readPlayerSave` が未知バージョンを
空で握りつぶす挙動はログ/エラー化する。**本フェーズ（P4）では対応しない**（schemaVersion=1 据え置きの間は実害なし）。

### 🟢 F2. 破壊的マイグレーションの運用ガード
列・テーブルDROPは不可逆（Prisma migrate に down なし）。本番適用前に**スナップショット取得を手順化**。
`p4-orphan-*` プレースホルダ User が本番に残る点も運用メモに残す。

### 🟢 F3. 死に引数 `toBaseStats(character)`（cleanup）
`PlayerSaveService.toCharacterDataForSave` は基礎ステータス列消失後、`getJobBaseStatsAtLevel` の
第3引数が常にゼロ＝未使用（マスター表完備で無害）。actions.ts 側は既に除去済みで**非対称**。
`INITIAL_PLAYER_BASE_STATS` 既定に任せて引数削除を推奨。

### 🔵 F4. `saveVersion` / `createdAt` / `updatedAt` は追加済みだが未配線（P5想定）
`saveVersion`(列) と blob 内 `schemaVersion` の二重管理になる。P5でどちらを正とするか決定を。

### ⚠️ F5. 統合テスト・マイグレーションは未実行（実DB必須）
tsc は通るが、orphan backfill / NOT NULL 化を含む migration は**実DBで1回流して**検証推奨
（クリーンDB＋データ入りDBの両方で `prisma migrate`）。`src/tests/*` も実DBで緑確認を。

> 既知の G1（死霊術育成が未実装で rankUp の Lv.99 ゲート到達不能）は P4 でも未解決＝想定通りスコープ外。
