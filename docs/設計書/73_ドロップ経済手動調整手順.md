# 73 — ドロップ経済 手動調整手順

> 対象: `src/data/master/stages.json` / `src/data/master/enemies.json` / `src/data/master/items.json` / `src/data/master/materials.json` / `scripts/drop-report.mjs`  
> 作成日: 2026-05-30  
> 関連: `15_ワールド・ダンジョン・エネミー設計.md` §5 / `28_RewardService設計.md`

---

## 1. 目的

ドロップ経済は、体感の気持ちよさとインフレを同時に左右する。ここでは、武器・残滓・素材・消費アイテムの期待値をステージ単位で見える化し、ユーザーがマスターデータを直接編集しても UR 非掲載・SSR低確率・R/SR供給量が崩れないようにする。

---

## 2. 編集するファイル

### 2.1 ステージ報酬

`src/data/master/stages.json`

```json
"rewards": {
  "baseExp": 120,
  "baseGold": 80,
  "dropTable": [
    { "type": "WEAPON", "itemId": "bone_cleaver", "rarity": "R", "rate": 0.55 },
    { "type": "RESIDUE", "rarity": "RARE", "rate": 0.65 }
  ]
}
```

現行の `GameManager` / `actions.ts` は主に `stage.rewards.dropTable` を報酬生成に使う。敵別 `dropTable` は UI表示・ダンジョン要約側でも参照されるため、両方の整合を確認する。

### 2.2 敵別ドロップ

`src/data/master/enemies.json`

```json
"dropTable": [
  { "type": "WEAPON", "itemId": "spirit_silver_saber", "rarity": "SSR", "rate": 0.01 },
  { "type": "WEAPON", "itemId": "grudge_manifest", "rarity": "UR", "rate": 0.00008, "isHidden": true }
]
```

敵別テーブルは「どの敵が何を落とすか」の表示根拠になる。UR は `isHidden: true` を必ず維持する。

---

## 3. レポートスクリプト

### 3.1 警告があるステージだけ表示

```bash
npm run balance:drops
```

### 3.2 全ステージの期待値を表示

```bash
npm run balance:drops -- --all
```

### 3.3 特定ステージだけ確認

```bash
npm run balance:drops -- --stage=area1_boss --all
```

### 3.4 CI向け

```bash
npm run balance:drops -- --strict
```

`FAIL` がある場合に exit code `2` で終了する。

---

## 4. レポート指標

| バケット | 意味 | 目安 |
|---|---|---|
| `R_WEAPON` | R武器の1周期待数 | 1〜3 |
| `SR_WEAPON` | SR武器の1周期待数 | 0.05〜1 |
| `SSR_WEAPON` | SSR武器の1周期待数 | 0.005〜0.05 |
| `UR_WEAPON` | UR武器の1周期待数 | 0.0002以下 |
| `EPIC_RESIDUE` | 高級残滓の1周期待数 | 0.3〜1.2 |

この期待値は、ステージ報酬テーブルと敵別ドロップテーブルを合算した「設計上の供給量」として扱う。実生成パスの実装差分を調べる場合は `RewardService` / `BattleCanvas` も確認する。

---

## 5. 調整手順

1. `npm run balance:drops -- --all` を実行する。
2. `FAIL` がある場合は、存在しない `itemId` / `materialId` / `enemyId` や UR 非hiddenを先に直す。
3. SSR が高すぎる場合は、ステージ報酬とボス敵別報酬の二重計上を確認する。
4. R武器が少なすぎる場合は、WAVE1雑魚かステージ報酬にR武器を追加する。
5. EPIC残滓が多すぎる場合は、ボス敵別かステージ報酬のどちらかに寄せる。
6. UR武器は `rate <= 0.0001` と `isHidden: true` を守る。
7. 変更後に `npm run balance:drops -- --stage=<stageId> --all` を再実行する。

---

## 6. 注意点

- `rate` は `0.0` から `1.0` の範囲にする。
- `CONSUMABLE` と `WEAPON` は `items.json` に存在する `itemId` を使う。
- `MATERIAL` は `materials.json` に存在する `itemId` を使う。
- UR をドロップリストに見せたい場合でも、通常UIでは非掲載にするため `isHidden: true` を維持する。
- ステージ報酬と敵別ドロップを両方上げると、表示上は自然でも実装パスによって期待値が過剰に見える。

---
