# 75 — マスターデータ制作運用手順

> 対象: `src/data/master/*` / `scripts/master-data-audit.mjs` / `scripts/master-data-template.mjs`  
> 作成日: 2026-05-30  
> 目的: 敵・ダンジョン・ドロップ・武器・素材・スキルを、今後の開発で安全に増やすための実務手順

---

## 1. 基本方針

ネクロマンスブレイブのコンテンツ追加は、まずマスターデータで完結できるかを判断する。

| やりたいこと | 主に編集するファイル | コード変更 |
|---|---|---|
| 敵を追加する | `enemies.json` | 原則不要 |
| ダンジョンノードを追加する | `stages.json` | 原則不要 |
| ステージに出る敵を変える | `stages.json` の `waves[].enemyIds` | 原則不要 |
| ドロップを変える | `stages.json` / `enemies.json` | 原則不要 |
| 武器・消費アイテムを追加する | `items.json` | パッシブ効果が新規なら必要 |
| 強化素材を追加する | `materials.json` | 原則不要 |
| 編成用モンスターを追加する | `monsters.json` | 入手経路が新規なら必要 |
| スキルを追加する | `skills.json` / `jobs.json` | 新効果・新VFXなら必要 |

`id` は英小文字スネークケースにし、`id` フィールドがあるデータは JSON キーと必ず一致させる。

## 2. 便利コマンド

### 2.1 全体監査

```bash
npm run data:audit
```

参照切れ、ID不一致、WAVE構成、ドロップ参照、UR非掲載、スキル参照、マップ座標の近接などをまとめて確認する。

### 2.2 特定データだけ監査

```bash
npm run data:audit -- --type=enemy --id=grave_knight
npm run data:audit -- --type=stage --id=area1_node2
```

`--type` は `enemy/stage/item/material/monster/skill/job/demonForm` の単数形か、`enemies/stages` の複数形を使える。

### 2.3 CI向け監査

```bash
npm run data:audit -- --strict
```

`FAIL` がある場合に exit code `2` で終了する。`WARN` は制作判断の余地があるため失敗扱いにしない。

### 2.4 JSON雛形生成

```bash
npm run data:template -- --type=enemy --id=grave_mason --tier=ELITE --tribe=UNDEAD --element=EARTH --nameJa=墓所の石工
npm run data:template -- --type=stage --id=area1_node4 --element=DARK --nameJa=黒棺の回廊
npm run data:template -- --type=weapon --id=coffin_lament --nameJa=黒棺の哀剣
```

このコマンドはファイルを書き換えず、コピー用のJSON断片を出力する。実際の追加は人間が内容を確認して `src/data/master/*.json` に貼る。

## 3. 敵モンスター作成フロー

### 3.1 先に決めること

| 項目 | 判断基準 |
|---|---|
| `tier` | WAVE1の雑魚なら `MINION`、WAVE2の圧力役なら `ELITE`、WAVE3決着役なら `BOSS` |
| `tribe` | 種族シナジーや世界観に合わせる |
| 弱点属性 | ステージで使わせたいスキル属性を1〜2個置く |
| 防壁 | `ELITE` / `BOSS` は原則 `shieldHp` を持たせる |
| ギミック | ボスのみ最小1個、章ボスは2〜3個 |
| ドロップ | 雑魚はR武器/COMMON素材、精鋭はSR/RARE残滓、ボスはSSR/EPIC残滓/UR隠し |

### 3.2 作成手順

1. `npm run data:template -- --type=enemy ...` で雛形を出す。
2. `src/data/master/enemies.json` にエントリを追加する。
3. `stats` を役割に合わせて調整する。
4. `resistances` の負数と `weaknesses` を一致させる。
5. `dropTable` の `itemId` が `items.json` / `materials.json` に存在するか確認する。
6. `battle.color` / `sprite` / `size` を設定する。
7. `npm run data:audit -- --type=enemy --id=<enemyId>` を実行する。
8. ボスの場合は `npm run balance:report -- --all` で直前WAVEとの逆転を確認する。

### 3.3 敵データの最小チェックリスト

- `id` と JSON キーが一致している。
- `nameJa` と `nameEn` がある。
- `stats` 8項目がすべて数値。
- `weaknesses` は `resistances` の負数属性と一致している。
- `dropTable.rate` は `0..1`。
- UR武器は `isHidden: true`。
- `ELITE` / `BOSS` は、防壁なしにする明確な理由がある。

## 4. ダンジョンノード作成フロー

### 4.1 WAVE構成の基本

| WAVE | role | 役割 |
|---|---|---|
| WAVE 1 | `WARMUP` | 属性・敵種族・状態異常の導入 |
| WAVE 2 | `SHIELD` / `ELITE` | 防壁・精鋭・ギミック準備 |
| WAVE 3 | `BOSS` | そのノードの主題を決着させる |

全ノードを必ず3WAVEにする必要はないが、現行UIと報酬テンポは3WAVE前提で整っている。

### 4.2 作成手順

1. そのノードで体験させたい主題を1文で書く。
2. 使用する敵IDを `enemies.json` から選ぶ。足りなければ先に敵を作る。
3. `npm run data:template -- --type=stage ...` で雛形を出す。
4. `src/data/master/stages.json` にエントリを追加する。
5. `unlockRequires` で前提ノードを設定する。
6. `position` を既存ノードと重ならない位置に置く。
7. `rewards.baseExp` / `baseGold` / `dropTable` を設定する。
8. `npm run data:audit -- --type=stage --id=<stageId>` を実行する。
9. `npm run balance:progression -- --stage=<stageId> --all` で前後ステージとの跳ね方を見る。
10. `npm run balance:drops -- --stage=<stageId> --all` で報酬期待値を見る。

### 4.3 ダンジョン配置のチェックリスト

- `waveCount` と `waves.length` が一致している。
- `enemyIds` が全て `enemies.json` に存在する。
- `role: BOSS` のWAVEには `tier: BOSS` の敵がいる。
- `role: SHIELD` のWAVEには防壁持ちがいる。
- `unlockRequires` は存在するステージIDで、循環していない。
- `position` が既存ノードと近すぎない。
- `nodeType: BOSS` の場合は `isAreaBoss: true` を付ける。

## 5. ドロップ調整フロー

### 5.1 どこに置くか

| 置き場所 | 用途 |
|---|---|
| `stages.json` の `rewards.dropTable` | ステージクリア報酬として確実に調整したい供給 |
| `enemies.json` の `dropTable` | 「この敵が落とす」という図鑑・UI上の意味を持たせたい供給 |

現行の一部処理はステージ報酬を直接使うため、実際に配布したいものは `stages.json` に置くのが安全。敵別ドロップは表示・期待値・将来の敵別抽選の根拠として整える。

### 5.2 調整手順

1. 新しい武器・素材を落とすなら、先に `items.json` / `materials.json` に定義する。
2. `dropTable` にエントリを追加する。
3. R/SR/SSR/URの期待値を `npm run balance:drops -- --stage=<stageId> --all` で見る。
4. URは `rate <= 0.0001` と `isHidden: true` を守る。
5. `npm run data:audit -- --type=stage --id=<stageId>` で参照切れを確認する。

### 5.3 ドロップエントリ例

```json
{ "type": "WEAPON", "itemId": "bleed_reaver", "rarity": "SR", "rate": 0.16 }
{ "type": "RESIDUE", "rarity": "EPIC", "rate": 0.45 }
{ "type": "MATERIAL", "itemId": "ossuary_memory", "rarity": "RARE", "rate": 0.26 }
{ "type": "WEAPON", "itemId": "grudge_manifest", "rarity": "UR", "rate": 0.00008, "isHidden": true }
```

## 6. 武器・素材・編成用モンスター

### 6.1 武器

1. `npm run data:template -- --type=weapon --id=<weaponId>` で雛形を出す。
2. `items.json` に追加する。
3. `passiveA.values` / `passiveB.values` はランク1〜5の5値にする。
4. 新しい `systemTag` や未実装効果を使う場合は、WeaponSystem / BattleEngine 側の実装が必要。
5. `npm run data:audit -- --type=item --id=<weaponId>` を実行する。

### 6.2 素材

1. `npm run data:template -- --type=material --id=<materialId>` で雛形を出す。
2. `materials.json` に追加する。
3. `expValue` と `rarity` を設定する。
4. ドロップテーブルに配置する。

### 6.3 編成用モンスター

1. `npm run data:template -- --type=monster --id=<monsterId>` で雛形を出す。
2. `monsters.json` に追加する。
3. `cost` は1〜6にする。
4. 入手経路をドロップにするなら `DropEntry.type: "MONSTER"` を使う。
5. `npm run data:audit -- --type=monster --id=<monsterId>` を実行する。

---

## 7. スキル追加・調整

1. `npm run data:template -- --type=skill --id=<skillId>` で雛形を出す。
2. `skills.json` に追加する。
3. `jobs.json` の該当職業 `skills` に追加する。
4. `npm run balance:skills -- --skill=<skillId> --all` で倍率とコスト帯を見る。
5. `effectKey` が新規の場合、BattleCanvas のVFX接続が必要か確認する。
6. 新しい効果フィールドを追加した場合、BattleEngine / BattleCanvas / 型定義 / テストも更新する。

## 8. 作業完了前の標準確認

敵・ステージ・ドロップを触ったら、最低限これを実行する。

```bash
npm run data:audit
npm run balance:drops
npm run balance:progression
npm test -- --runInBand src/services/MasterDataService.test.ts src/logic/DungeonSystem.test.ts
```

武器・スキル・報酬生成まで触った場合は追加で実行する。

```bash
npm run balance:skills
npm test -- --runInBand src/services/RewardService.test.ts src/logic/BattleEngine.test.ts
```

コード変更を含む場合は最後に実行する。

```bash
npm run build
git diff --check
```

## 9. 現行データでの既知警告

`npm run data:audit` では、現状 `grave_knight` が `ELITE` かつ防壁なしとして警告される。これは「強めの雑魚」として使うなら `tier: MINION` に寄せるか、「精鋭」として扱うなら `shieldHp` / `maxShieldHp` を追加する余地がある、という制作判断用の警告である。
