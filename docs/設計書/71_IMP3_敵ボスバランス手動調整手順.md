# 71 — IMP-3 敵・ボスバランス手動調整手順

> 対象: `src/data/master/enemies.json` / `src/data/master/stages.json` / `scripts/balance-report.mjs`  
> 作成日: 2026-05-30  
> 関連: `docs/progress/IMPROVEMENTS.md` の `IMP-3`

---

## 1. 目的

`IMP-3: ボスが直前の精鋭より弱い（stat逆転）` は、マスターデータ調整で解決するタイプの問題である。実装を直接変更せず、ユーザーが `enemies.json` を安全に編集し、調整後に `balance:report` で逆転や弱すぎるボスを発見できるようにする。

---

## 2. 編集するファイル

### 2.1 敵ステータス

`src/data/master/enemies.json`

主に編集する項目:

```json
"stats": {
  "hp": 680,
  "atk": 95,
  "def": 52,
  "spd": 55,
  "critRate": 10,
  "critDmg": 175,
  "effectHit": 0,
  "effectRes": 30
},
"shieldHp": 160,
"maxShieldHp": 160
```

### 2.2 出現順

`src/data/master/stages.json`

確認する項目:

```json
"waves": [
  { "label": "WAVE 2", "role": "SHIELD", "enemyIds": ["bone_colossus"] },
  { "label": "WAVE 3", "role": "BOSS", "enemyIds": ["ossuary_wyrm_lord"] }
]
```

ボスの強さは、直前WAVEの最強敵と比較する。

---

## 3. 調整で見る指標

| 指標 | 意味 | 目安 |
|---|---|---|
| `HP` | 素の耐久 | ボスは直前最強敵の 1.0 倍以上 |
| `shieldHp` | 霊的防壁 | ボス戦の儀式感。高すぎると削りが長い |
| `REV` | `REVIVE` による追加HP | `value: 1` は旧表現として 50% 復活扱い |
| `SUM` | `SUMMON_MINIONS` の召喚敵HP合計 | 増援ギミック込みの追加圧力 |
| `EHP` | 実効耐久 = HP + shield + REV + SUM | ボスは直前最強敵の 1.2 倍以上が安心 |
| `ATK` | 1発の圧力 | ボスは直前最強敵の 0.9 倍以上が目安 |
| `THR` | 脅威度 = ATK × SPD × 会心補正 | WAVE全体の圧力比較に使う |

---

## 4. 調整手順

1. `npm run balance:report -- --all` を実行し、全ステージの現状を確認する。
2. `FAIL` / `WARN` が出たステージを確認する。
3. 該当ボスを `src/data/master/enemies.json` で探す。
4. まず `hp` と `atk` を調整する。
5. ボスらしさが足りなければ `shieldHp` / `maxShieldHp` を調整する。
6. `REVIVE` 持ちの場合は、実効HPが増えるため `hp` を上げすぎない。
7. `SUMMON_MINIONS` 持ちの場合は、増援のHP合計も EHP に含めて見る。
8. 再度 `npm run balance:report -- --stage=<stageId>` を実行する。
9. 問題なければ `npm test -- --runInBand src/logic/BalanceTuning.test.ts` を実行する。

---

## 5. レポートスクリプト

### 5.1 全体確認

```bash
npm run balance:report -- --all
```

全戦闘ステージのWAVE構成、敵ステータス、比較警告を表示する。

### 5.2 特定ステージだけ確認

```bash
npm run balance:report -- --stage=area1_node2 --all
```

`area1_node2` だけを出す。ボス調整中はこの使い方が一番速い。

### 5.3 警告があるステージだけ表示

```bash
npm run balance:report
```

通常実行では、`WARN` / `FAIL` があるステージだけ表示する。

### 5.4 CI向け

```bash
npm run balance:report -- --strict
```

`FAIL` がある場合に exit code `2` で終了する。現在は手動運用向けなので、CIに入れる場合はボス調整基準が固まってからにする。

## 6. レポートの読み方

出力例:

```text
area1_node2 / 煤けた王城の地下牢 / difficulty 2
  WAVE 2 [SHIELD] ...
    - bone_colossus        骨巨人       ELITE  HP 720 SH 220 REV 0 SUM 0 EHP 940 ATK 124 DEF 78 SPD 68 THR 86.4
  WAVE 3 [BOSS] ...
    - ossuary_wyrm_lord    死骨竜王...  BOSS   HP 180 SH 60 REV 90 SUM 0 EHP 330 ATK 15 DEF 25 SPD 55 THR 9.2
    FAIL: ボス実効HPが直前最強敵未満 (0.35x)
    WARN: ボスATKが直前最強敵より低い (0.12x)
```

この場合、`ossuary_wyrm_lord` の `hp` / `atk` / `shieldHp` を上げるのが候補になる。

---

## 7. 調整の目安

### 7.1 素直に強くする

直前精鋭が `HP 720 / ATK 124 / EHP 940` の場合:

```json
"stats": { "hp": 680, "atk": 95, "def": 52, "spd": 55, ... },
"shieldHp": 160,
"maxShieldHp": 160
```

`REVIVE` があるなら EHP は `680 + 160 + 340 = 1180` になり、直前精鋭を超えやすい。

### 7.2 攻撃は低め、ギミックで強くする

ボスATKを低めにしたい場合は、以下で緊張感を作る。

- `shieldHp` を増やして霊魂砕きまでの儀式を作る。
- `AV_DELAY` / `ENRAGE` などギミックの発火タイミングを見直す。
- `REVIVE` の復活割合を `0.35` から `0.50` の範囲で調整する。

---

## 8. 注意点

- `enemies.json` は JSON なので末尾カンマを入れない。
- `shieldHp` を変えたら `maxShieldHp` も同じ値にする。
- `REVIVE` の `value: 1` は「1回復活」の旧表現で、実装上は 50% 復活として扱う。
- `value: 0.35` のように `0 < value < 1` を指定すると、その割合で復活する。
- ボスを強くしすぎた場合は、`stages.json` の `rewards.baseExp` / `baseGold` も後で見直す。
