## 3. 整合設計の核心：「ステージクリア起点 ＋ 初回確定報酬」

### 3-1. 解決する矛盾
チュートリアルが「機能Xの使い方」を教える時、プレイヤーが**機能Xの対象アイテムを未所持**だと矛盾する
（例：武器を1本も持っていないのに「武器を装備しよう」が発火）。
現状の報酬は**確率ドロップのみ**（`area1_node1` の武器 `rate:0.55` 等）で、所持を保証できない。

### 3-2. 解決方針
**チュートリアルを発火させるステージの初回クリア報酬に、そのチュートリアルの対象アイテムを「確定（quantity 1, rate 1.0）」で含める。**
報酬付与とフェーズ発火はどちらも同一ステージクリアの結果処理で起こるため、
**発火時点でプレイヤーは必ず対象アイテムを所持**している。

### 3-3. 既存システムとの整合（矛盾が出ないことの確認）
- **報酬処理は既に初回判定可能**: `RewardService.processStageDropTable(stage, clearedStages, ...)` が `clearedStages` を受け取る（`RewardService.ts:224`）。初回クリア判定点は `GameManager.ts:228` / `actions.ts:968`（`!clearedStages.includes(stageId)`）。同じ判定で確定報酬を分岐できる。
- **ドロップ型は既に対応済み**: `DropEntry`（`game.ts:338`）に `type:'MONSTER'|'MATERIAL'|...` と `monsterId`/`itemId`/`quantity` が存在。`StageDropResult` も `monsters`/`materials` バケットを持つ（`RewardService.ts:166`）。**型変更不要**で確定報酬を表現できる。
- **魔物入手の現状との両立**: 現状モンスターは**捕獲（captureRate / `processStageNecromance`）**で入手し、dropTable に MONSTER エントリは無い（CH1_TODO の既知事項）。初回確定モンスター報酬は捕獲ロールと**併存**させる（捕獲を置換しない）。**重複防止**は既存 `getOwnedMonsterMasterIds`（`NecromanceCaptureSystem.ts`）を流用し、既所持 masterId は付与しない。
- **発火順の安全性**: 報酬（`addInventoryItems`/`addAbyssalResidues`/捕獲反映）と `clearedStages` 更新は同一結果処理で store に反映され、チュートリアルは `requiredTab` のタブを開いた時に表示される。プレイヤーが EQUIP タブへ遷移する頃には所持が確定済みで競合しない。

## 4. 再編成案（ステージクリア起点 ＋ 初回確定報酬）

### 4-1. 新しいフェーズ構成と確定報酬

| 順 | フェーズ | 発火トリガー | このクリアの**初回確定報酬** | 状態 |
|---|---|---|---|---|
| 1 | `BATTLE_BASICS` | `area1_node1` バトル開始 | （戦闘中。報酬前） | 既存 |
| 2 | **`PARTY_FORMATION`（魔物の編成）** | **`area1_node1` クリア** | **確定モンスター ×1〜2**（編成対象） | トリガー変更 |
| 3 | **`WEAPON_EQUIP`（武器の装備）** | **`area1_node2` クリア** | **確定武器 ×1**（装備対象） | **新規** |
| 4 | `JOB_CHANGE` | `area1_node2` クリア（`WEAPON_EQUIP`後） | 不要（職業は常時利用可） | トリガー変更 |
| 5 | **`WEAPON_ENHANCE`（武器の強化）** | **`area1_boss` クリア** | **確定 武器強化素材 ×必要数**（打ち直し対象） | **新規** |
| 6 | `DEMONIZATION` | `area1_boss` クリア（`WEAPON_ENHANCE`後） | 不要（ソウルゲージ機構） | 既存 |
| 7 | `ABYSSAL_RESIDUE` | `area1_node3` クリア | **確定 残滓 ×1**（装備/強化対象） | 既存 |

> **同一ステージで2フェーズが候補になる場合**（node2→`WEAPON_EQUIP`+`JOB_CHANGE`、boss→`WEAPON_ENHANCE`+`DEMONIZATION`）は、
> 既存の `activePhase` ガード（`useTutorialStore.ts:62`、同時に1つしか走らない）と `hasCompleted(前提)` チェックで順序保証。
> さらに `WEAPON_ENHANCE`(EQUIPタブ) と `DEMONIZATION`(BATTLEタブ) はタブが異なり自然に分離する。

### 4-2. 確定報酬の data 表現（案）
`stages.json` の `rewards` に **`firstClearGuaranteed` 配列**を追加（既存 `dropTable` は確率枠のまま温存）。

```jsonc
// stages.json — area1_node2 の例
"rewards": {
  "baseExp": 16, "baseGold": 1460,
  "dropTable": [ /* 既存の確率ドロップ。変更しない */ ],
  "firstClearGuaranteed": [
    { "type": "WEAPON", "itemId": "bone_cleaver", "rarity": "R", "quantity": 1 }
  ]
}
```
- 初回クリア時のみ `firstClearGuaranteed` を `rate:1.0` 相当で確定付与。2回目以降は無視。
- `MONSTER` 型は `{ "type":"MONSTER", "monsterId":"...", "quantity":1 }`。既所持 masterId はスキップ。
