# 113_使役魔物スキル使用システム実装計画

> 作成: 2026-06-14
> 目的: 使役した魔物を、主人公（アルド）と同様にバトル中スキルを使えるようにする。
> 主人公との差分は **魔神化の有無のみ**。
> ステータス: 計画段階（未実装）

---

## 1. 全体像（最重要）

**データ層は既に完成済み**で、欠けているのは **戦闘層と魔物MPプールの配線** だけ。

| パイプライン | 状態 | 参照 |
|---|---|---|
| `MonsterData.skillIds` 型定義 | ✅ 存在 | `src/types/game.ts:320` |
| `enemies.json` の `necromance.skillIds` | ✅ 定義済み（例: `grave_soldier → skill_necromancer_1`） | `src/data/master/enemies.json` |
| 捕獲時のスキル継承 | ✅ | `src/logic/NecromanceCaptureSystem.ts:106` |
| DB保存/復元 | ✅ `Monster.skillIds` | `prisma/schema.prisma:279` / `src/app/actions.ts:347,954` / `src/logic/GameManager.ts:130` |
| **戦闘でのスキル使用** | ❌ 未実装（通常攻撃のみ） | — |
| **魔物のMPプール** | ❌ 未実装（型・DB・UIに無い） | — |

### 確定した設計方針
1. **魔物にもMPプールを付与**（主人公と完全に同じ挙動 / 最大忠実度）
2. **オートバトルは簡易AIで自動選択**（使えるスキルがあれば選ぶ→無ければ通常攻撃）

---

## 2. 現状の実装根拠

### プレイヤーのスキル使用フロー（複製元）
- スキル解決: `resolveUnlockedJobSkills(job, level, MASTER_SKILLS).map(toBattleSkill)` — `BattleCanvas.tsx:1961`
- スキル実行: `handleSkill(skill)` — `BattleCanvas.tsx:2992`（MP消費 `updateEnergyBy(-skill.mp)`、魔神化分岐多数）
- ダメージ: `calculatePlayerHitDamage()` — `BattleCanvas.tsx:2447`（`playerStats` + 魔神化フォーム使用）
- MPリソース: `player.currentEnergy / maxEnergy`（`game.ts:263`）、`battleParty[0].mp`（`BattleCanvas.tsx:1942`）

### 魔物の現状フロー（通常攻撃のみ）
- `BattleEngine.processMonsterAction()` — `src/logic/BattleEngine.ts:585`（固定倍率1.0の通常攻撃のみ）
- `BattleEngine.simulateMonsterAction()` — `src/logic/BattleEngine.ts:183`（公開入口、`skillId` 引数なし）
- `BattleCanvas.handleMonsterAttack()` — `BattleCanvas.tsx:3051`（通常攻撃のみ）
- 魔物ターンUI — `BattleCanvas.tsx:3410` 付近（「攻撃」CommandButton 1個のみ）
- オート時 — `BattleCanvas.tsx:3226` で `handleMonsterAttack()` を呼ぶ
- 攻撃プロファイル: `calculateMonsterAttackProfile()` — `src/logic/MonsterAttackSystem.ts`（霊核ATK倍率・覚醒倍率を反映）
- **魔物には `currentEnergy/maxEnergy` が存在しない**

## 3. レイヤー別 修正箇所

### Layer 1 — 型システム `src/types/game.ts`
- `MonsterData`（:312）に `currentEnergy: number` / `maxEnergy: number` を追加

### Layer 2 — マスターデータ `src/data/master/enemies.json`
- 各エネミーの `necromance` ブロックに `allyMaxEnergy`（魔物の最大MP）を追加
- `skillIds: []` が空の魔物（rot_hound 等）に、素性に合うスキルIDを付与（→ balance-designer / 設計書19 案件）

### Layer 3 — 捕獲 `src/logic/NecromanceCaptureSystem.ts`
- `createNecromancedMonster()`（:97）で `currentEnergy`/`maxEnergy` を初期化（`necromance.allyMaxEnergy` から）

### Layer 4 — 永続化（要マイグレーション）
- `prisma/schema.prisma` Monster モデル（:262）に `maxEnergy Int` / `currentEnergy Int` 追加
  → `npx prisma migrate dev` + `npx prisma generate`
- `src/app/actions.ts` — ロード（:347付近）とセーブ（:954付近）にフィールド追加
- `src/logic/GameManager.ts` — `:130` / `:216` のマッピングに追加

### Layer 5 — 戦闘ロジック（純粋・テスト可能）`src/logic/`
- **新規 `MonsterSkillPolicy.ts`** — オート時の簡易AI。
  `pickMonsterAction(monster, usableSkills, enemies)` → スキル or 通常攻撃を返す純関数。MP不足・AOE適性で選択。**テスト併設（`MonsterSkillPolicy.test.ts`）**
- `BattleEngine.ts`
  - `simulateMonsterAction()`（:183）に `skillId?` 引数を追加
  - `processMonsterAction()`（:585）を分岐: skillId 有り→`getSkill()` で power/element/コスト/状態異常を適用し MP 消費。無し→従来の通常攻撃
  - `BattleEngine.test.ts` にケース追加

### Layer 6 — 戦闘UI `src/components/battle/BattleCanvas.tsx`（中心作業・最大工数）
1. **魔物のBattleSkill解決** — `activeMonster.skillIds.map(id => MASTER_SKILLS[id]).map(toBattleSkill)`（プレイヤーの :1961 と同型。職業/レベルゲートは不要）
2. **魔物MPランタイム** — 現状 `battleParty`（:1924）はスロット0=プレイヤーのMPのみ。**パーティ各員のMP runtime state**（`useState` か ref のマップ）を追加。初期化／`endMonsterTurn` で同期
3. **魔物ターンUIにスキルボタン追加**（:3410ブロック）— 現「攻撃」1個 → 「スキル」を追加
4. **skillMenu のコンテキスト対応** — 現 `skillMenu` フェーズは `handleSkill`(プレイヤー専用)に直結。
   **推奨: 新フェーズ `monsterSkillMenu` を新設**（`src/logic/BattleFlowSystem.ts:1` の `BattlePhase` 型に追加）。プレイヤー用の魔神化分岐と混ざらない
5. **新規 `handleMonsterSkill(skill)`** — `handleSkill`(:2992) の魔物版。魔神化分岐を全除去し、`calculateMonsterHitDamage` を使用、魔物MPを消費
6. **新規 `calculateMonsterHitDamage`** — `calculatePlayerHitDamage`(:2447) の魔物版。`calculateMonsterAttackProfile` の stats を使用
7. **オートAI接続** — :3226 の `handleMonsterAttack()` を `MonsterSkillPolicy` 経由の自動選択に差し替え
8. **MP表示** — パーティステータスバーに魔物MPゲージを追加（プレイヤー同様）

### Layer 7 — 管理画面・AIエージェント（整合）
- `src/lib/agent/knownFields.ts:40` — `allyMaxEnergy` を既知フィールド登録
- `src/lib/agent/enemyBalance.ts` / `src/app/admin/actions.ts` — MP値のバリデーション
- `src/components/admin/forms/EnemyForm.tsx` — MP編集UI
- `src/lib/agent/enemyAgent.ts` — 生成プロンプトに MP/skillIds 指示（skillIds は一部既存）
