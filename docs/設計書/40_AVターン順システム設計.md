# 40_AVターン順システム設計

## 目的

`spd` を単なる表示ステータスではなく、バトル中の行動順と手番頻度に反映する。  
第1章時点ではコマンド選択 UX を維持しつつ、プレイヤー行動後に「次のプレイヤー手番までに割り込む敵」を AV で決定する。

## 基本式

```ts
actionDelay = Math.round(10000 / spd)
```

- `spd` が高いほど `actionDelay` は小さい。
- `currentAv` が小さいキャラクターから行動する。
- 行動したキャラクターは `currentAv += actionDelay` される。
- 同じ `currentAv` の場合は `actionDelay` が小さい、つまり速いキャラクターを優先する。

## 初期AV

バトル開始時・WAVE遷移時:

- プレイヤー: `currentAv = 0`
- 敵: `currentAv = actionDelay`

これにより従来通りプレイヤーが最初にコマンドを選びつつ、以降は SPD に応じて敵が割り込む。

## プレイヤー行動後の敵フェーズ

1. プレイヤー行動完了時に `player.currentAv += actionDelay(player.spd)`。
2. 生存している敵とプレイヤーを `currentAv` 昇順で並べる。
3. 次の actor が敵、かつ `enemy.currentAv < player.currentAv` なら、その敵を行動予定に入れて `enemy.currentAv += actionDelay(enemy.spd)`。
4. 次の actor がプレイヤーになるまで 2-3 を繰り返す。
5. 予定された敵だけが攻撃する。

敵とプレイヤーの `currentAv` が同値になった場合は、コマンドバトルの操作感を守るためプレイヤー手番へ戻す。

この仕様により:

- 高SPDの敵はプレイヤー手番の間に複数回割り込める。
- 低SPDの敵は毎回は動けない。
- プレイヤーの SPD が高いほど、敵に行動される前に再び手番が回りやすい。

## 状態異常・AV_DELAY

`StatusAilmentSystem.calcAVDelay(baseAVDelay, effectRes)` は AV 遅延量の軽減式として維持する。

```ts
actualDelay = Math.floor(baseAVDelay * (1 - effectRes / 100))
```

`TurnOrderSystem.applyStatusActionDelay()` から利用し、将来的にボスギミックやスキル効果で `currentAv` に直接加算する。

## テスト方針

- `10000 / spd` の行動遅延を検証する。
- 同一 `currentAv` では高SPDを先にする。
- プレイヤー手番までに行動できる敵だけをスケジュールする。
- 状態異常で行動不能の敵は攻撃せず、AV だけ進む。
- `calcAVDelay()` が `effectRes` で軽減されることを AV システム側から確認する。
