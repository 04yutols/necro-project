# 56. BUG-4 残滓強化素材スタック消費設計

作成日: 2026-05-24
対象: `src/store/useGameStore.ts` / `src/components/legion/LegionHub.tsx` / `src/components/necro/NecroLab.tsx`
ステータス: 実装済み

---

## 1. 背景

`ResidueMatData` は `quantity` を持つスタック型だが、旧 `upgradeResidue(residueId, matIds)` は選択された素材IDのスタック全量をEXP計算に使い、同時にスタック自体を削除していた。

```ts
const expGain = matIds.reduce((acc, id) => {
  const mat = state.residueMaterials.find(m => m.id === id);
  return acc + (mat ? mat.expValue * mat.quantity : 0);
}, 0);

const remainingMaterials = state.residueMaterials.filter(m => !matIds.includes(m.id));
```

このため、`quantity: 8` の素材を1回選んだだけで8個ぶんのEXPが入り、8個すべてが消える。プレイヤーが「1個だけ使う」操作をできない。

---

## 2. 仕様

### 2.1 選択IDの意味

`matIds` の1要素は「素材スタック1個」ではなく「素材1個の消費リクエスト」として扱う。

| 入力 | 所持数 | 消費数 |
|---|---:|---:|
| `['mat-1']` | 8 | 1 |
| `['mat-1', 'mat-1']` | 8 | 2 |
| `['mat-1' x 10]` | 8 | 8 |

現在のUIは `Set<string>` による選択なので、カード1回選択では1個だけ消費する。将来、数量ピッカーを追加する場合は同じIDを複数回渡すか、APIを `{ id, quantity }[]` に拡張する。

### 2.2 EXP計算

獲得EXPは実際に消費できた数量だけで計算する。

```ts
expGain += material.expValue * consume;
```

存在しないIDや所持数を超えたリクエストは無視し、所持数以上のEXPを付与しない。

### 2.3 素材スタック更新

- 消費後 `quantity > 0`: スタックを残して数量を減らす。
- 消費後 `quantity === 0`: スタックを配列から削除する。
- 消費EXPが0: 残滓も素材も変更しない。

## 3. 実装詳細

### 3.1 `spendResidueMaterials()`

`useGameStore.ts` に素材消費の小さな純粋ヘルパーを追加する。

```ts

  const requested = matIds.reduce(

    new Map<string, number>(),
  );

  ...
}
```

このヘルパーが「要求数」「所持数」「獲得EXP」「残り素材配列」の整合を一箇所で管理する。

### 3.2 `upgradeResidue()`

`upgradeResidue()` は `spendResidueMaterials()` の結果だけを使う。

- `spent.expGain <= 0` なら no-op。
- 残滓EXP/レベル計算は既存式を維持。
- 装備中スロットに同じ残滓があれば同時に同期。
- `residueMaterials` は `spent.materials` に置き換える。

### 3.3 UIプレビュー

`LegionHub` と `NecroLab` の強化プレビューは、選択ID1件につき `mat.expValue` だけを足す。

旧式の `mat.expValue * mat.quantity` は廃止する。

オート選択も「カード1枚=1個消費」に合わせ、`expValue` の高い順に1個ずつ選ぶ。

---

## 4. 非対象

今回の修正では、素材カード内で複数個数を指定するUIは追加しない。

理由:

- 現在の選択状態が `Set<string>` で、複数個選択を表現できない。
- BUG-4の直接原因は「1回選択で全量消費」なので、まず1回選択を1個消費に戻すのが安全。
- 数量ピッカーはUX設計とモバイル操作の検討が必要。

## 5. テスト設計

追加テスト: `src/store/useGameStore.party.test.ts`

検証内容:

1. `quantity: 8 / expValue: 200` の `mat-1` を1回選ぶと、残滓EXPが200増え、素材数量が7になる。
2. 装備中の同一残滓スロットにもEXPが同期される。
3. `quantity: 1` の `mat-3` を同じIDで3回要求しても、消費は1個ぶんに制限される。
4. `mat-3` 消費後はスタックが削除され、EXPは2500だけ入る。

## 6. 完了条件

- `upgradeResidue()` が `mat.expValue * mat.quantity` でEXP計算しない。
- `upgradeResidue()` が選択IDだけでスタック全体を削除しない。
- 1回選択で1個だけ消費される。
- 所持数以上の重複IDを渡してもEXPが過剰付与されない。
- UIプレビューが実消費EXPと一致する。
- 専用テスト、全体テスト、TypeScriptチェック、本番ビルドが通る。
