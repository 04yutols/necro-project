# 11 — ストーリーとチュートリアル

> 最終更新: 2026-07-11 ｜ 生成方法: コードからのリバースエンジニアリング（コードが正） ｜ 主要ソース: `src/types/story.ts`, `src/data/story/`（`packs.ts` / `index.ts` / `ch1_scenes.json` / `ch2_scenes.json` / `characters.json`）, `src/store/useStoryStore.ts`, `src/hooks/useStoryTrigger.ts`, `src/components/story/`, `src/data/tutorial/`（`phases.ts` / `triggers.ts`）, `src/store/useTutorialStore.ts`, `src/hooks/useTutorialTrigger.ts`, `src/components/tutorial/`, `src/app/page.tsx`

ストーリーシステムは「章別JSONパック（シーン本文）＋Zustand persist（既読・フラグ）＋トリガーフック（発火）＋全画面演出UI（表示）」の4層で構成される。チュートリアルは5フェーズのスポットライト誘導で、プロローグ完了後にステージクリアを起点として連鎖発火し、発火対象クリア後はリザルトからホームへ強制復帰させてバナー→タブ誘導→スポットライトの順に案内する。進行状態はどちらも localStorage のみに永続化され（DB保存なし）、ログインユーザーごとにストレージキーがスコープ分離される。

## 2. ストーリーデータ構造

### 2.1 シーン型（`src/types/story.ts`）

```typescript
SceneType = 'DIALOGUE' | 'MONOLOGUE' | 'ENVIRONMENT' | 'CHAPTER_TITLE' | 'CHOICE'

SceneTrigger =
  | { type: 'GAME_START' }
  | { type: 'FLAG_SET'; flagKey: string }
  | { type: 'STAGE_CLEAR'; stageId: string }
  | { type: 'STAGE_ENTER'; stageId: string }
  | { type: 'AREA_UNLOCK'; areaId: string }
  | { type: 'BOSS_CLEAR'; bossStageId: string }
  | { type: 'DEMONIZE_FIRST' }
  | { type: 'MANUAL'; sceneId: string }

StoryScene: {
  id, type, title?, titleEn?, description?, sequence?, trigger,
  background?, lines: DialogueLine[],
  onComplete?: { unlockArea?, setFlag?, navigateTo? },
  isSkippable: boolean, archiveTitle: string, archiveChapter: number
}

DialogueLine: {
  speaker: string | null, speakerJa?, text, textEn?,
  portraits?: CharacterPortrait[], expression?, bgm?, vfx?, pauseAfter?, skipIf?
}

CharacterPortrait: { characterId, position: 'LEFT'|'CENTER'|'RIGHT', expression, isDimmed? }
```

`onComplete` の実処理は次の2つのみ:

- `setFlag` — シーン完了時（`dismissScene`）に `storyFlags[flagKey] = true`（`src/store/useStoryStore.ts`）
- `navigateTo` — `StoryOrchestrator.completeScene` で `HOME | MAP | BATTLE | EQUIP | LAB | LOGS | JOB` のいずれかなら `setCurrentTab`（`src/components/story/StoryOrchestrator.tsx`）

`unlockArea` はランタイムでは**未処理**（型と管理画面バリデータのみ。エリア解放の実体は `stages.json` の `unlockRequires`）。`DialogueLine.bgm` / `skipIf` も現状未参照。`CHOICE` 型は Orchestrator に描画分岐が無く、実データにも存在しない。

### 2.2 章別JSONパックレジストリ（`src/data/story/packs.ts`）

```typescript
StoryPack: { id, fileName, label, archiveChapterRange: [min, max], scenes }
```

| id | fileName | label | archiveChapterRange | シーン数 |
|---|---|---|---|---|
| `act1_ch1` | `ch1_scenes.json` | 第1章 亡国の王都 | [0, 1]（プロローグ=第0章を含む） | 19 |
| `act1_ch2` | `ch2_scenes.json` | 第2章 幽霊都市 | [2, 2] | 4 |

- `STORY_SCENES` は全パックの scenes を flatMap し `sortStoryScenes` でソート（`sequence` 昇順、未定義は `MAX_SAFE_INTEGER`、同値は `id` の localeCompare）— `src/data/story/index.ts`, `packs.ts`
- シーンIDは全パックで一意。重複があると `buildSceneMap` が起動時に throw（`index.ts`）
- 章番号→パック解決（`getStoryPackForArchiveChapter`）は管理画面 `/admin/story` の保存先判定に使用（`src/app/admin/actions.ts` の `saveStoryScene` / `deleteStoryScene`）

### 2.3 レジストリAPI（`src/data/story/index.ts`）

| 関数 | 内容 |
|---|---|
| `findScene(sceneId)` | ID→シーン（無ければ null） |
| `getPrologueSceneIds()` | `GAME_START` トリガーの全シーンID |
| `getStageEnterSceneIds(stageId)` | `STAGE_ENTER` 一致分 |
| `getStageClearSceneIds(stageId)` | `STAGE_CLEAR` + `BOSS_CLEAR` + 導出された `AREA_UNLOCK` の合成 |
| `getFlagSceneIds(flagKey)` | `FLAG_SET` 一致分 |
| `getDemonizeFirstSceneIds()` | `DEMONIZE_FIRST` 全シーン |
| `getAreaUnlockIdsForClearedStage(stageId)` | 下記のAREA_UNLOCK導出 |

**AREA_UNLOCK の導出規則**（コード分岐なしの汎用化）: クリアした stageId を `unlockRequires` に含むステージを `stages.json` から探し、クリア元と `chapter`/`area` が異なり、かつ黄泉エリア（`isYomiArea`, `src/logic/YomiFloors.ts`）でない場合に `area{n}` を areaId として `AREA_UNLOCK` シーンを検索する。現行データでは `area1_node3` クリア → `area2_gate`（第2章）が解放条件を満たし `CH1_AREA2_UNLOCK` が再生される。黄泉（area 99, `yomi_b01` が `area1_node3` を要求）は除外される。

## 4. ストーリー進行管理（`src/store/useStoryStore.ts`）

### 4.1 状態とアクション

| 状態 | 永続化 | 内容 |
|---|---|---|
| `activeScene` | ✕（ランタイムのみ） | 再生中シーン |
| `sceneQueue` | ✕ | 再生待ちシーンID列 |
| `viewedScenes` | ○ | 既読シーンID配列 |
| `storyFlags` | ○ | フラグ辞書 |
| `hasHydrated` | ✕ | persist復元完了フラグ |

- `enqueueScene(id, {replay?, front?})` — 未既読（replay時は無視）かつ未キュー・未再生のときのみ投入。`activeScene` が空なら即再生。戻り値 boolean
- `enqueueScenes(ids, options)` — 同条件の一括投入。実際に積んだID配列を返す
- `playScene(id)` — `enqueueScene(id, { replay: true, front: true })`（アーカイブ再生用）
- `dismissScene()` — 現行シーンを `markViewed` → `onComplete.setFlag` 処理 → キュー先頭を次の `activeScene` へ
- `skipScene()` — `dismissScene()` と同一（既読化してから閉じる）
- `resetStoryProgress()` — 全状態初期化（UIからの呼び出し箇所は現状なし）

### 4.2 永続化とユーザースコープ

- ストレージキー: `necro-story-store-v2`（`STORY_STORE_STORAGE_KEY`）。partialize で `viewedScenes` と `storyFlags` のみ保存
- スコープキー: `necro-story-store-scope-v1` に `user:<encodeURIComponent(userId)>` を保持し、実キーは `necro-story-store-v2:user:...` になる（ゲスト時はスコープなし＝ベースキー）
- `switchStoryPersistenceScope(userId)` — ログイン切替時に呼ばれ、保存済みが無ければ全初期化、あれば rehydrate して `activeScene`/`sceneQueue` を空にする
- 呼び出し元は `src/hooks/useAuthFlow.ts` の `switchPersistenceScopes`（story と tutorial を Promise.all で同時切替）
- **サーバーDBへの保存はない**（localStorage のみ。SSR時はメモリストレージにフォールバック）

### 4.3 トリガーフック（`src/hooks/useStoryTrigger.ts`）

`page.tsx` から `useStoryTrigger(canPresentStory)` として1箇所だけ利用。`canPresentStory = authFlow.status === 'ready' || 'guest'`（認証確定前は発火しない）。

| トリガー | 発火タイミング・条件 |
|---|---|
| GAME_START | hydration完了後、`PROLOGUE_00` 未読ならプロローグ全4本をキューへ。既読なら `LINE_DEATH_SEEN` / `CH1_STARTED` フラグ済みの FLAG_SET シーンで未読分を再キュー（中断復帰） |
| FLAG_SET | `storyFlags` の変化を監視し、新規に true になったフラグの未読シーンをキューへ（`CH1_TITLE` → `CH1_SAFE_INTRO` のチェーンはこれで連鎖） |
| STAGE_CLEAR / BOSS_CLEAR / AREA_UNLOCK | `player.clearedStages` の増分を監視。**`currentTab === 'BATTLE'` の間は評価しない**（バトル終了しリザルトから戻った後に再生）。`getStageClearSceneIds` が3種を合成 |
| DEMONIZE_FIRST | `useGameStore.isDemonMode` が初めて true になったとき。`DEMONIZE_STORY_SEEN` フラグ済み or `CH1_DEMONIZE_FIRST` 既読なら発火しない（＝バトル中に z:10000 で割り込む唯一のシーン） |
| STAGE_ENTER | フックが返す `triggerStageEnter(stageId)` を `page.tsx` の `requestStageStart` が呼ぶ。未読シーンがあれば true |

**ステージ入場シーンのバトル待機**（`src/app/page.tsx`）: `requestStageStart` で `triggerStageEnter` が true を返すと `pendingStageId` に退避し、`activeScene` とキューが空になった時点の effect で `startStageNow`（BATTLE タブへ切替・バトル開始）を実行する。つまり入場シーンは MAP 上で再生完了してからバトルが始まる。

## 5. ストーリー演出UI

### 5.1 StoryOrchestrator（`src/components/story/StoryOrchestrator.tsx`）

`page.tsx` で全タブのラッパーとして常駐。`activeScene.type` により以下へディスパッチし、完了時に `dismissScene` → `onComplete.navigateTo` を処理する。全コンポーネント `position: fixed; inset: 0; zIndex: 10000`（EnvironmentCaption は上部バナーのみだが同 z）。

| type | コンポーネント | 進行 | 自動終了 |
|---|---|---|---|
| CHAPTER_TITLE | `ChapterTitleCard` | タップで即終了 | **4200ms** で自動 dismiss |
| DIALOGUE | `DialogueScene` | タップ送り / オート / SKIP | なし |
| MONOLOGUE | `MonologueOverlay` | タップ送り / SKIP | なし |
| ENVIRONMENT | `EnvironmentCaption` | タップで即終了 | **2500ms**（`DISPLAY_MS`） |

### 5.2 DialogueScene（原神風フル会話UI）

- 背景は `background` キーで6種のグラデーション定義（`BACKGROUND_STYLE`）: `DARK`(MEMORY DEPTH) / `SEPIA`(OLD MEMORY) / `BLOOD_RED`(BLOOD MEMORY) / `RUIN_LIGHT`(RUIN LIGHT) / `BLUR_MAP`(FALLEN CAPITAL) / `STAGE_DARK`(DRAGONBONE ALTAR)。未指定・未知キーは `DARK`
- 立ち絵状態は `resolvePortraits`: 行ごとの `portraits` 指定を引き継ぎ、`portraits` が無い行は `speaker`+`expression` で該当キャラの表情のみ差し替え。話者は `y: -6, scale 1.025`、非話者/`isDimmed` は `opacity 0.52` + 減光フィルタ
- タップ挙動: 表示途中→全文即時表示（flush）、表示完了→次の行、最終行→シーン終了
- オートモード: 行完了後 `pauseAfter ?? 1550ms` で自動送り。Play/Pauseトグルボタン
- SKIPボタン: `isSkippable || 既読` のとき表示（＝プロローグも2周目以降はスキップ可）
- 英語字幕: `textEn` が行完了後にフェードイン表示
- `vfx`: `soulChain`（幅58%の紫ライン）/ `ssrGoldPillar`（金の縦光柱）/ その他文字列は汎用紫ラインとして描画
- フッターに `行番号 / 総行数` と `TAP → NEXT / CLOSE` インジケータ

### 5.3 TypewriterText（`src/components/story/TypewriterText.tsx`）

| 定数 | 値 |
|---|---|
| `CHAR_MS`（通常1文字） | 40ms |
| `CHAR_MS_AUTO`（オート時） | 20ms |
| `SPACE_MS`（空白文字） | 60ms |
| `PUNCT_PAUSE_MS`（句読点後の追い待ち） | 200ms（対象: 。！？….!?） |

### 5.4 MonologueOverlay / ChapterTitleCard / EnvironmentCaption

- MonologueOverlay: 黒背景（`rgba(2,1,10,0.94)`）中央寄せの独白。✦アクセント → タイプライター → 英語字幕 → Void Purple ライン → `Tap to continue / Tap to close`。SKIP は `isSkippable || 既読`
- ChapterTitleCard: `Chapter {archiveChapter}` 見出し → 紫ライン(85%幅) → タイトル1文字ずつ表示（delay `1.0 + i * 0.08` 秒）→ 英語タイトル → description。4200ms 自動 or タップで終了
- EnvironmentCaption: 画面上部の環境描写バナー（`lines[0].text` のみ使用、幅78vw・max 400px）

### 5.5 ストーリーアーカイブ（`src/components/story/StoryArchive.tsx`）

LOGS タブ内のパネル切替「物語 / 戦歴 / 世界」の「物語」（`page.tsx` の `logPanel === 'STORY'`、デフォルト選択）。全 `STORY_SCENES` を sequence 順に一覧し:

- 既読: 紫ハイライト＋金の再生ボタン → `playScene(id)` で即時再生（replay + front）
- 未読: 減光（opacity 0.55）＋ロックアイコン、再生不可
- 表示: `CH.{archiveChapter} / {type}`、`archiveTitle`、`titleEn`

### 6.2 発火トリガー（`src/data/tutorial/triggers.ts`）

**バトル開始時（BATTLE_BASICS のみ）** — `shouldStartBattleTutorial`:
対象ステージは `TUTORIAL_BATTLE_STAGE_IDS = ['tutorial_battle_01', 'area1_node1']`。`tutorial_battle_01` は stages.json に存在しない仮想ID（`TUTORIAL_VIRTUAL_STAGE_IDS`、`src/data/stageRefs.ts` の存在検証から除外）。BattleCanvas が `useTutorialBattlePhase(stageId)` を呼び、未完了・未進行・チュートリアル未完なら `startPhase('BATTLE_BASICS')` + バナー投入。

**ステージクリア起点の連鎖** — `getTutorialPhaseAfterClear`（純関数。`useTutorialTrigger` と `page.tsx` の両方が使用）:

| フェーズ | 発火するクリアステージ | 前提フェーズ |
|---|---|---|
| `PARTY_FORMATION` | `area1_node1`（王都外縁の墓道） | BATTLE_BASICS 完了 |
| `WEAPON_EQUIP` | `area1_a2`（王都墓道・内郭） | PARTY_FORMATION 完了 |
| `DEMONIZATION` | `area1_a_mini`（墓守巨像の門） | WEAPON_EQUIP 完了 |
| `ABYSSAL_RESIDUE` | `isAbyssalResidueUnlocked` = `area1_node3`（血沼の渡し）クリア（`src/logic/AbyssalResidueUnlockSystem.ts`） | DEMONIZATION 完了 |

入口ゲート: `storyFlags.LINE_DEATH_SEEN !== true` かつ連鎖未着手なら null（プロローグ未完では始まらない）。評価ゲート `shouldEvaluateClearTutorialTrigger`: 両ストア hydration 完了・チュートリアル未完・`currentTab !== 'BATTLE'`。

**初回確定報酬との整合**（`stages.json` の `rewards.firstClearGuaranteed`、`RewardService.ts` が初回クリア時のみ確定付与）: `area1_node1` = モンスター2体（grave_soldier / rot_hound）→ 編成対象を保証。`area1_node2` = 武器 bone_cleaver ×1、`area1_boss` = 武器素材 ABYSSAL_OBSIDIAN ×1、`area1_node3` = RARE残滓 ×1。※ WEAPON_EQUIP の発火ステージ（`area1_a2`）と確定武器の付与ステージ（`area1_node2`）は一致していない点に注意（発火時は node1/a2 の確率ドロップ武器に依存）。

**DEMONIZATION のステップジャンプ**（`useTutorialTrigger.ts`）: `isDemonMode` が true になった瞬間、activePhase=DEMONIZATION かつ step=1（TUT_D_02）なら `nextStep()` で TUT_D_03 へ自動前進。

### 6.3 クリア後のホーム強制復帰（`src/app/page.tsx` `finishBattle`）

バトル終了（リザルト閉じ）時の戻りタブを次で決定:

1. `getTutorialPhaseAfterClear(...)` が非 null（＝このクリアでチュートリアルが発火する）→ **`HOME`**
2. 黄泉ステージ（`isYomiStage`）→ `YOMI`
3. それ以外 → `MAP`

HOME 着地後、`useTutorialTrigger` の effect が `startPhase` + `enqueueBanner` を実行。バナー CTA「確認する」で `getTutorialPhaseDestinationTab(phase)`（先頭ステップの `requiredTab` を `EQUIP`/`LAB`/`JOB` にマップ、BATTLE 系は null）のタブへ遷移し、そこでスポットライトが始まる。報酬と `clearedStages` はリザルト表示前に store 確定済みのためレースはない。

### 6.4 チュートリアルストア（`src/store/useTutorialStore.ts`）

| 状態 | 永続化 | 内容 |
|---|---|---|
| `completedPhases` | ○ | 完了フェーズ配列 |
| `tutorialCompleted` | ○ | `ALL_PHASES` 全完了で true |
| `viewedHints` | ○ | BubbleHint 既読ID |
| `visitedTabs` | ○ | 訪問タブ記録（Orchestrator が記録。現状読み手なし） |
| `activePhase` / `activeStepIndex` / `bannerQueue` | ✕ | 進行中フェーズはリロードで消える（未完了なら次の評価で再発火） |

- `startPhase(phase)` — 完了済み・進行中・全完了なら拒否（同時に1フェーズのみ）
- `nextStep()` — 最終ステップ到達でフェーズ完了、全フェーズ揃えば `tutorialCompleted = true`
- `skipPhase()` — 進行中フェーズを即完了扱い（SKIPボタン）
- `completeTutorial()` — 全完了状態へ（`useTutorialTrigger` が全フェーズ完了検出時に呼ぶ）
- `resetTutorial()` — 全初期化（UIからの呼び出し箇所は現状なし）
- ストレージキー: `necro-tutorial-store-v2`、スコープキー `necro-tutorial-store-scope-v1`。ユーザースコープ切替はストーリーと同じ仕組み（`useAuthFlow`）

### 6.5 スポットライト表示（`src/components/tutorial/TutorialOrchestrator.tsx` / `SpotlightOverlay.tsx`）

表示条件: `!tutorialCompleted && ストーリーシーン非再生中 && step非null && (requiredTab未指定 || requiredTab === currentTab)`。ストーリー再生中はチュートリアルが隠れる（storyBlocking）。

z-index 層（コメント準拠・実測値）:

| 要素 | 通常フェーズ | バトルフェーズ（BATTLE_BASICS / DEMONIZATION） |
|---|---|---|
| 暗幕SVG / リング / バブル / SKIP | 9500 / 9501 / 9502 / 9503 | 10001 / 10002 / 10003 / 10004（BattleCanvas z:9999 より上、ストーリー z:10000 より一部上） |
| TutorialBanner | 9400（固定） | 同左 |
| BubbleHint | 8000（固定） | — |

SpotlightOverlay の仕様:

- ターゲット計測: `document.getElementById(step.targetId)` を rAF + リトライ（90/240/520ms）+ ResizeObserver + visualViewport resize/scroll で追随。見つからない場合は画面中央に半径60pxのスポットを表示
- スポット半径: `max(44, max(width, height)/2 + 24)`（`SPOTLIGHT_PAD = 24`）
- 暗幕: SVG `clipPath`（evenodd で円形の穴）を `fill rgba(0,0,0,0.72)` に適用。**iOS Safari 規約に従い SVG は transform なし、グローリング（紫 border 円）は別の motion.div に分離**
- バブル: 最大幅 260px（`BUBBLE_MAX_W`）、推定高 126px、gap 18px、viewport padding 12px。`step.position`（above/below/left/right）が収まらない場合は対向→上下の順にフォールバックし、三角矢印の向きも追随。バブル出現は 460ms 遅延
- 進行: 暗幕タップ or「次へ」ボタンで `nextStep()`。右上 SKIP（表示 delay 0.6s）で `skipPhase()`（`canSkip` は Orchestrator から常に true）

### 6.6 解放バナー（`TutorialBanner.tsx` / `TutorialBanner.actions.ts`）

画面上端固定の紫グラデーションバナー。`bannerQueue` の先頭を表示（自動消滅なし）。

- 遷移先タブあり（PARTY_FORMATION / WEAPON_EQUIP / ABYSSAL_RESIDUE）: 「確認する」CTA →`confirmTutorialBanner` が `setCurrentTab` + `dismissBanner`。別に「×」ボタンで遷移せず閉じる
- 遷移先タブなし（BATTLE 系フェーズ）: ボタンは「閉じる」のみ（次のバトルでスポットライト本編）

フェーズ外の単発ヒント。`activePhase` 進行中は非表示。タップで `markHintViewed`（永続化）され二度と出ない。現在の設置は2箇所:
