本書は Necromance Brave の戦闘システム（WAVE 制ターンバトル）の実装仕様を記述する。戦闘はプレイヤー（アルド＝骸骨騎士）＋味方モンスター最大3体 対 敵最大3体で行われ、AV（行動値）による手番順、ダメージ計算、霊的防壁、状態異常、種族シナジー、魔神化、ボス/エリアギミック、Energy（MP）リソース、敗北判定で構成される。

## 1. 実行アーキテクチャ — 二重実装

戦闘ロジックは **2つの実行系** を持つ。両者は共通の純ロジックモジュール群を共有するが、進行フローには差異がある（差異は §14 の表を参照）。

| 実行系 | ファイル | 用途 |
|---|---|---|
| **BattleCanvas**（クライアント実戦。プレイヤーが実際に遊ぶ経路） | `src/components/battle/BattleCanvas.tsx` | SVG + Framer Motion の戦闘画面。共通ロジックモジュールを直接 import して独自フローで進行。**BattleEngine クラスは一切使用しない** |
| **BattleEngine**（純ロジッククラス） | `src/logic/BattleEngine.ts` | `simulateAction()` / `simulateMonsterAction()` / `simulateUltimateSkill()` で BattleLog[] を返す。サーバ側 `GameManager.ts`（`new BattleEngine(player, monsterList)`）とテストで使用 |

共有される純ロジック: `BattleDamage`, `TurnOrderSystem`, `StatusAilmentSystem`, `TribeSynergySystem`, `DemonizationSystem`, `BossGimmickSystem`, `AreaGimmickSystem`, `MonsterAttackSystem`, `MonsterSkillPolicy`, `MonsterEnergySystem`, `EnemyScaling`, `PlayerDefeat`, `BattleFlowSystem`。

## 2. ダメージ計算式（`src/logic/BattleDamage.ts` — 両実行系共通）

`calculateBattleDamage()` の段階式（コード転記）:

```
// 1. 基礎ダメージ
damage = attacker.atk × powerMultiplier            // power 既定 1.0

// 2. 防御軽減（防御削減シナジー込み）
rawDef       = max(0, defender.def)
reducePct    = clamp(synergyBonus.defenseReducePct, 0, 100)   // ORC シナジー
effectiveDef = rawDef × (1 - reducePct / 100)
defMult      = 1 - effectiveDef / (effectiveDef + 200)
damage      *= defMult

// 3. 属性ダメージ加成（装備・残滓 + シナジー）
equipBoost      = attackerElementBoosts[element] / 100
synergyPct      = synergyBonus.elementDmgBonus
                + (element == DARK          ? synergyBonus.darkDmgBonus     : 0)
                + (element ∈ {FIRE, DARK}   ? synergyBonus.fireDarkDmgBonus : 0)
damage         *= 1 + equipBoost + synergyPct / 100

// 4. 属性耐性（resistance < 0 = 弱点 isWeakness、> 0 = 耐性 isResisted）
damage *= 1 - resistance / 100

// 5. 会心
effectiveCritRate = max(0, critRate + synergyBonus.critRateBonus)
isCritical        = rng() × 100 < effectiveCritRate
if isCritical: damage *= 1 + max(0, critDmg + synergyBonus.critDmgBonus) / 100

// 6. 最終
finalDamage = max(1, floor(damage))
```

### 敵 → プレイヤー被弾式 `calculateIncomingEnemyDamage()`

```
defMult = 1 - playerDef / (playerDef + 200)
damage  = enemyAtk × defMult × incomingMultiplier × enrageMultiplier × variance
final   = max(1, round(damage))
```

- `incomingMultiplier`: 魔神化 GLASS_CANNON リスクの被ダメ倍率（§10）。既定 1
- `enrageMultiplier`: ENRAGE 発動時の倍率（§7）。既定 1
- `variance`: BattleCanvas では `0.8 + Math.random() × 0.4`（0.8〜1.2）。BattleEngine 経路では未指定＝1（`BattleCanvas.tsx` `runEnemyTurn()`）
- 攻撃側 atk には WEAKEN 状態異常の ×0.7 を事前適用（`getAilmentAttackMultiplier`）

攻撃側ステータスの出所: プレイヤーは `calculateCharacterStatProfile()` の total（装備・残滓・ネクロ補正込み、`src/logic/StatSystem.ts`）。属性加成は `player.elementDmgBoosts`（無ければ profile 側）。

## 3. AV ターン順（`src/logic/TurnOrderSystem.ts`）

```
actionDelay(spd)          = max(1, round(10000 / max(1, spd)))
initialAV(spd, offset=0)  = max(0, actionDelay(spd) + offset)
行動後:  currentAv += actionDelay(spd)
```

- **並び順**: `currentAv` 昇順 → 同値なら `actionDelay` 昇順（速い方が先）→ 同値なら `tieBreaker` 昇順
- **初期 AV**（`BattleCanvas.tsx` `createInitialAvState()`。バトル開始時と WAVE 遷移時に再初期化）:

| アクター | 初期 currentAv | tieBreaker |
|---|---|---|
| プレイヤー | 0（常に最初に手番） | 0 |
| 味方モンスター（スロット i=0..2） | actionDelay(spd) + (i+1) | i+1 |
| 敵 | actionDelay(spd) | 敵id+1 |

- プレイヤー spd には BEAST シナジーの `spdBonus` を加算（`getPlayerActionSpd()`）。味方モンスター・敵には加算しない
- **敵フェーズスケジューリング** `scheduleEnemiesUntilAlly()`: プレイヤー/味方の最小 AV より小さい AV の敵を順に行動予定へ入れ、その敵の AV に actionDelay を加算。次アクターが PLAYER/ALLY になるか、敵 AV ≥ 次味方 AV になったら打ち切り。ガード上限 `敵数×2` 回。FREEZE/PARALYSIS でスキップされた敵は行動しないが **AV は消費する**（`skippedEnemyIds`）
- 敵フェーズ終了後の手番は `nextAlly`（プレイヤー＋味方の AV 最小者）。ALLY なら `monsterTurn`、そうでなければ `playerTurn`（`runEnemyTurn()`）
- **AV 遅延の軽減式**（状態異常・ボスギミック共通、`StatusAilmentSystem.calcAVDelay`）:

```
actualDelay = max(0, floor(baseAVDelay × (1 - max(0, effectRes) / 100)))
```

- ターン順プレビューは先頭5件を UI 表示（`buildTurnOrderPreview`）

## 4. WAVE 進行とターン制フロー

### 4.1 WAVE 構築（`BattleCanvas.tsx` `buildBattleWaves()`）

- `stages.json` の `StageData.waves[]` から敵マスター（`enemies.json`）を解決し、`applyEnemyStatScale()` で wave ごとの `statScale`（hp/atk/def の乗算、floor。`src/logic/EnemyScaling.ts`）を適用
- WAVE 報酬 = `stage.rewards.baseExp / baseGold × WAVE_REWard重み`。重みは `WAVE_REWARD_WEIGHTS = [0.25, 0.32, 0.43]`（4WAVE 以降は 1/wave数）
- `wave.role === 'BOSS'` がボス WAVE。ステージ未指定/SAFE ノードはモック 3WAVE（骸骨山脈）へフォールバック
- 敵は最大3体。画面位置は体数に応じて left/center/right

### 4.2 バトルフェーズ（`src/logic/BattleFlowSystem.ts`）

`playerTurn | monsterTurn | skillMenu | monsterSkillMenu | itemMenu | animating | enemyTurn | waveTransition`

行動開始は `canStartPlayerAction()`（フェーズ一致 ∧ 非ロック ∧ WAVE 解決中でない）で二重入力を防止する。

### 4.3 プレイヤー手番のフロー（BattleCanvas）

```
コマンド選択（攻撃/術/アイテム/魔神技）
  → エリアギミック処理（§8）        … applyAreaGimmickBeforePlayerAction()
  → プレイヤー状態異常処理（§9）     … DoT・行動スキップ判定。スキップなら即 endPlayerTurn()
  → アクション実行（actionCountRef++ ＝ ターンカウント）
  → endPlayerTurn():
      敵全滅 → resolveWaveClear()
      魔神化中なら残り行動数 -1（0 で解除）
      非魔神化ならソウルゲージ +10
      player.currentAv += actionDelay
      → runEnemyTurn()
```

### 4.4 敵フェーズ `runEnemyTurn()`（BattleCanvas）

```
1. 敵の状態異常フェーズ（DoT・スキップ判定・全滅チェック）
2. ボス AV_DELAY ギミック判定（§7）
3. scheduleEnemiesUntilAlly() で行動する敵を決定
4. 各予約敵: calculateIncomingEnemyDamage() でプレイヤーへ攻撃
   （WEAKEN×0.7、HP≤50% かつ ENRAGE ギミック保持なら enrage 倍率、
     魔神化 GLASS_CANNON なら被ダメ倍率、variance 0.8〜1.2）
   → ELITE/BOSS は状態異常付与を試行（§9.4）
   → プレイヤー HP 0 で敗北
5. 次手番（ALLY → monsterTurn / それ以外 → playerTurn）
```

敵行動の予約は `setTimeout` ＋ `enemyTurnSerialRef` のトークン照合で管理され、魔神化 INTERRUPT や敗北でシリアルを進めると予約済み行動がすべて無効化される。

### 4.5 WAVE クリアと勝利（`resolveWaveClear()`）

- WAVE クリア条件は **敵全滅**（HP 判定は REVIVE/SUMMON 解決後）。クリアで EXP/Gold を積算、ソウル +18
- 次 WAVE: 敵再生成・AV 初期化・ボスギミック発火履歴リセット・`playerTurn` へ
- 最終 WAVE クリアで `processStageResultLocal()`（ドロップ・EXP・ネクロマンス・クラウド保存）→ ResultScreen（勝利）。保存失敗時は `SYNC FAILED` の敗北扱いリザルト

### 4.6 BattleEngine 側のターンフロー（サーバ/テスト経路）

`simulateAction()` 1回 = 1ターン: ①エリアギミック → ②ターン開始シナジー（UNDEAD 回復 / DRAGON ゲージ）→ ③プレイヤー状態異常（魔神化中はスキップ）→ ④敵の状態異常 → ⑤プレイヤー行動 → ⑥敵の反撃 → ⑦`updateState()`。WAVE 進行は「現 WAVE の敵全滅」で `wave++`（最大3）・`turn=1` リセット（10ターン経過での進行は廃止済み）。

## 5. 敵のターゲッティング（敵 → 味方）

| 実行系 | 挙動 |
|---|---|
| **BattleCanvas** | 敵の攻撃対象は **常にプレイヤー（骸骨騎士）**。味方モンスターは攻撃されない |
| **BattleEngine** | 隊列ヘイト重み付き抽選で生存味方モンスターを選択: **slot0=50% / slot1=30% / slot2=20%**。ORC 完全シナジーの `absorbDmgPct` でダメージの一部を吸収（`max(1, damage - floor(damage × absorbDmgPct/100))`）。**味方モンスター全滅時のみ** プレイヤーが直接被弾（`processEnemyCounterAttack()`） |

敵の攻撃属性は `spiritCore.element ?? 'NONE'`（BattleEngine）。BattleCanvas の敵攻撃は無属性の物理のみでスキル AI は未実装。

## 6. 霊的防壁（Spiritual Shield）

敵の `shieldHp / maxShieldHp / shieldBroken` に対し、ヒットごとに **計算後ダメージの全量** をシールドへも与えたうえで、HP への通過ダメージに以下の倍率を掛ける（`BattleEngine.applySpiritualShield()` / `BattleCanvas.damageEnemy()`、倍率は両実装共通）:

| ヒット種別 | 破壊せず | このヒットで破壊（霊魂砕き） |
|---|---|---|
| 弱点属性でない | × **0.22** | × **0.72** |
| 弱点属性（`weaknesses` に一致） | × **0.72** | × **1.45** |

- 端数処理: BattleEngine は全ケース `max(1, floor(…))`。BattleCanvas は全ケース `round(…)` だが、**弱点属性かつこのヒットで破壊（霊魂砕き、×1.45）の場合のみ `max(1, …)` の下限保護が無い**（`Math.round(finalDmg * 1.45)`）。他の3ケース（弱点・非破壊 ×0.72／非弱点・破壊 ×0.72／非弱点・非破壊 ×0.22）はいずれも `max(1, round(…))`
- 破壊（didBreak）時: ソウルゲージ加算（Canvas +30 / Engine +20）、`ON_SHIELD_BREAK` ボスギミック発火、武器パッシブ `SOUL_SHATTER` 発動（Engine のみ、§13）
- 魔神技の `IGNORE_DEF` はシールド処理自体をバイパスする（Canvas `ignoreShield`）
- REVIVE でシールドは全回復し `shieldBroken` 解除（§7）

## 7. ボスギミック（`src/logic/BossGimmickSystem.ts`）

型: `BossGimmick { trigger, effect, value? }`（`src/types/game.ts`）。発火は `bossId:trigger:effect` キーで 1 回限り（WAVE ごとにリセット）。

### トリガー（`shouldTriggerBossGimmick()`）

| trigger | 条件 |
|---|---|
| `HP_BELOW_50` | prevHpPct > 50 ∧ newHpPct ≤ 50（50% を跨いだ瞬間）。**REVIVE には適用されない**（マスターデータ互換マーカー。HP50% では発火させない） |
| `TURN_3` | turn === 3（BattleCanvas では `actionCountRef`＝プレイヤー/味方の行動回数を turn として渡す） |
| `ON_SHIELD_BREAK` | 今回の攻撃で防壁破壊 |
| `ON_REVIVE` | 自動では発火しない（REVIVE 発火時に発火履歴を解除して再武装する用途） |

### エフェクト

| effect | 仕様 | 定数 |
|---|---|---|
| `ENRAGE` | BattleEngine: `boss.atk = floor(atk × mult)` を恒久適用。BattleCanvas: HP ≤ 50% の攻撃ごとに enrageMultiplier として被弾式に乗算 | 倍率 `value`（<1 や非数は既定 **1.5**） |
| `AV_DELAY` | BattleCanvas: `player.currentAv += calcAVDelay(base, player.effectRes)`。effectRes100% で完全無効。BattleEngine: **AV ではなく PARALYSIS（value ターン）をプレイヤーへ付与** する代替実装 | BattleCanvas の基礎遅延 `value`（既定 **40** = `DEFAULT_BOSS_AV_DELAY`、`getBossAvDelayBase()`）。**BattleEngine 側は `DEFAULT_BOSS_AV_DELAY` を参照せず、`value` 未指定時は既定 `1` ターンにフォールバックする**（`const turns = g.value ?? 1`） |
| `REVIVE` | HP0 到達時のみ 1 回発火。HP を `maxHp × ratio` へ回復（`0 < value < 1` なら value、それ以外＝旧 `value:1` 表現含め既定 **0.5**）。防壁全回復・`shieldBroken` 解除。BattleEngine は `ON_REVIVE` トリガーの発火履歴も解除 | `DEFAULT_REVIVE_HP_RATIO = 0.5` |
| `SUMMON_MINIONS` | 生存敵 3 体を上限に増援を召喚（`availableSlots = 3 - 生存数`）。召喚数は `min(pool長, 空き枠, value)`（value 非数なら既定 **2**）。召喚敵は WAVE の `statScale` を適用し、初期 AV を持って次の敵フェーズから行動可能 | `DEFAULT_SUMMON_COUNT = 2` |

### 召喚プール（`SUMMON_POOLS`）

| bossSourceId | プール |
|---|---|
| `blood_mire_queen` | `bloodmire_leech`, `rot_hound` |
| `ossuary_wyrm_lord` | `grave_soldier`, `earthbound_grudge` |
| （その他） | `grave_soldier`, `rot_hound`, `hollow_handmaid` |

処理順（`BattleCanvas.resolveBossGimmicksAfterDamage()`）: ダメージ反映 → SUMMON_MINIONS 判定 → HP0 なら REVIVE 判定 → その結果で WAVE クリア判定。復活・増援が残る場合に誤ってリザルトへ進まない。

## 9. 状態異常システム（`src/logic/StatusAilmentSystem.ts`）

### 9.1 発動判定

```
chance = clamp( baseRate × (1 + attacker.effectHit/100) × (1 - target.effectRes/100), 0, 1 )
```

`baseRate` はスキルの `ailmentBaseRate` があれば優先、無ければ既定表。付与成功時の持続 = `既定持続 + durationBonus`（UNDEAD+DEMON クロス共鳴で +1）。

### 9.2 種別一覧（定数はコード転記）

| ID | 名称 | baseRate | 既定持続 | 効果（tick はターン開始時） | スタック |
|---|---|---|---|---|---|
| `BLEED` | 出血 | 0.35 | 3T | 各スタックの `sourceAtk × 0.05` 合算を floor して固定ダメージ | **最大3**。sourceAtk 降順で上位3保持。各スタック残ターン独立 |
| `POISON` | 毒 | 0.30 | 3T | `floor(maxHp × 0.03)` | 1（再付与で上書きリセット） |
| `BURN` | 燃焼 | 0.25 | 2T | `floor(maxHp × 0.05)` | 1（上書き） |
| `FREEZE` | 凍結 | 0.20 | 1T | 行動不能（確定スキップ） | 1（上書き） |
| `PARALYSIS` | 麻痺 | 0.25 | 2T | 50% で行動スキップ（`rng() < 0.5`） | 1（上書き） |
| `WEAKEN` | 衰弱 | 0.30 | 2T | 攻撃時 ATK ×0.7（`getAilmentAttackMultiplier`。魔神化中は無効） | 1（上書き） |

免疫（`immuneTypes`）: BLEED/POISON/BURN の tick ダメージを 0 にする（残ターンは進行）。UNDEAD 完全シナジーの POISON/BLEED 免疫は **BattleEngine のプレイヤー処理のみ** 適用。

### 9.3 属性/攻撃種別からの自動推論（`inferAilmentForAction()`）

スキルに `ailmentType` 明示が無い場合の推論順:

| 条件 | 付与異常 |
|---|---|
| FIRE | BURN |
| ICE または WATER | FREEZE |
| THUNDER | PARALYSIS |
| DARK ∧ SUMMON | WEAKEN |
| DARK ∧ (MAGIC または type=MAGICAL) | POISON |
| SLASH または STRIKE | BLEED |
| その他 | なし |

通常攻撃（物理）でも SLASH/STRIKE 推論により BLEED を試行する。

### 9.4 敵からプレイヤーへの付与（`BattleCanvas.applyEnemyAilmentToPlayer()`）

| 敵 tier | 付与異常 | baseRate |
|---|---|---|
| BOSS | WEAKEN | 0.28 |
| ELITE | PARALYSIS | 0.22 |
| MINION | なし | — |

魔神化中は `immune: true` で完全に弾く。

### 9.5 魔神化との連動

- 発動時に `clearStatusEffectsByDemonize()` で全解除
- 魔神化中（`isDemonMode ∧ actionsRemaining > 0`）は付与・tick とも免疫（`isDemonStatusImmune`）

## 10. 魔神化システム（`src/logic/DemonizationSystem.ts`）

### 10.1 ゲージと発動

| 項目 | 値 |
|---|---|
| ゲージ上限 | `DEMON_GAUGE_MAX = 100` |
| 行動回数 | `DEMON_ACTION_LIMIT = 3`（主人公の行動数基準。0 で自動解除） |
| 発動条件 | ゲージ ≥ 100 ∧ 非魔神化 ∧ フェーズが `playerTurn` または `enemyTurn` |
| INTERRUPT | `enemyTurn` 中の発動は敵行動割り込み: `enemyTurnSerialRef` を進めて予約済み敵行動を全キャンセルし、AV を 0 に固定して即 `playerTurn` へ（`resolveDemonActivation()` / `BattleCanvas.handleDemonize()`） |
| 発動時 | ゲージ 0 消費・AV=0・状態異常全解除・以後免疫 |
| 発動不可理由 | `GAUGE_NOT_READY` / `ALREADY_ACTIVE` / `INVALID_PHASE` |

### 10.2 ゲージ蓄積（実行系で数値が異なる）

| イベント | BattleCanvas | BattleEngine |
|---|---|---|
| 手番終了（非魔神化） | +10 | —（下記の行動別加算） |
| 通常攻撃 | —（手番終了+10 に包含） | +10 |
| スキル使用 | 同上 | +5 |
| 会心 1 回ごと | +5 | +5 |
| 防壁破壊 | +30 | +20 |
| WAVE クリア | +18 | —（WAVE 演出は Canvas 管轄） |
| DRAGON 完全シナジー | 未適用 | +5/ターン |
| アイテム `RESTORE_SOUL` | +value | — |
| 武器パッシブ `DEMON_MODE` | 未適用 | +ランク値（§13） |

### 10.3 Effect A（基礎昇華）

```
demonDmgMult = max(1, 1 + statBoosts.atk + statBoosts.critDmg × 0.35
                     + (MAGIC/SUMMON ∧ flags:MAGIC_OVERDRIVE ? 0.35 : 0))
```

攻撃側 atk に `floor(atk × demonDmgMult)` として乗算。`flags: IGNORE_RESISTANCE` で敵耐性を無視（魔神化中の通常攻撃・スキルにも適用）。

### 10.4 Effect B（深淵の理）

| onAttackEffect | 効果 |
|---|---|
| `TRIPLE_HIT` | 物理（SLASH/STRIKE/PROJECTILE）が 3 ヒット化 |
| `MIRAGE_CHAIN` | 物理が 2 ヒット化 |

| riskType | 効果 |
|---|---|
| `SELF_DAMAGE` | MAGIC/SUMMON 攻撃後に `max(1, floor(maxHp × riskValue/100))` の反動（riskValue 既定 10）。反動死あり |
| `ENERGY_DRAIN` | **Canvas**: 行動後に MP を `max(1, round(riskValue ?? 15))` 追加消費。**Engine**: スキルコストを 2 倍（払えない場合は等倍） |
| `GLASS_CANNON` | 被ダメージ `max(1, riskValue ?? 2)` 倍 |
| `SETUP_DEPENDENT` | ログ演出のみ（数値効果未実装） |

### 10.5 魔神技（Ultimate）

- 魔神化中 1 回限り（`ultimateUsed`）。`demonForm.ultimateSkill.damage`（power / element / targetType SINGLE|ALL / flags）で計算
- `IGNORE_DEF`: 敵 DEF=0 扱い＋Canvas ではシールドもバイパス。`IGNORE_RESISTANCE`: 耐性無視
- Canvas では魔神技に Effect A 倍率は乗せない（`attackMultiplier: 1`）
- `lingering`（残留効果）は **ログ表示のみで戦闘数値へ未反映**（§15 参照）

## 12. Energy（MP）リソース

- **プレイヤー**: `maxEnergy = jobs.json の baseStatsByLevel[level].mp`（無ければ `energyCurve.baseMaxEnergy(既定100) + spGrowthPerLevel × (level-1)`、最低1）。戦闘開始時は満タン（`calculateInitialEnergy = calculateMaxEnergy`。`src/logic/EnergySystem.ts`）
- スキル使用でコスト分減少。通常攻撃・スキルによる **暗黙回復はない**（`BattleEngine.processPlayerAction` コメント明記）。回復手段はアイテム `RESTORE_ENERGY` と戦闘終了時の `restoreEnergy()`（勝利/敗北/撤退すべてで全回復）
- MP 不足時は行動不成立（`NO_ENERGY` ログ / Canvas はメッセージ表示のみでターン消費なし）
- **味方モンスター**: `maxEnergy` 未設定なら `DEFAULT_MONSTER_MAX_ENERGY = 30`（`src/logic/MonsterEnergySystem.ts`）。スキルは `mpCost` を消費。回復手段は戦闘内には無い
- 魔神化ゲージは MP とは **別リソース**（BattleLog では `playerSp`=MP、`playerDemonGauge`=ゲージ）

## 13. 行動 AI・スキル使用ポリシー

### 13.1 味方モンスター

- 攻撃プロファイル（`src/logic/MonsterAttackSystem.ts`）: `atk = max(1, floor(atk × spiritCore.atkMultiplier × (主人公覚醒中 1.5)))`。属性は `spiritCore.element ?? NONE`。倍率が非正/非数なら 1
- オート時のスキル選択（`src/logic/MonsterSkillPolicy.ts` `pickMonsterAction()`）:
  - 候補 = 所持スキルのうち「HEAL でない ∧ targetType が SELF/ALLY でない ∧ power > 0 ∧ mpCost ≤ 現在 MP」
  - スコア = `power × 対象数 + (生存敵2体以上 ∧ ALL_ENEMIES ? 0.45 : 0) + Σ(弱点対象 +0.35 / 耐性対象 −0.2) − mpCost × 0.005`
  - 最高スコア（同点は低コスト優先）。候補なし/生存敵なしは通常攻撃
- 手動時は `monsterTurn` フェーズでプレイヤーがコマンド選択（攻撃 / 術）

### 13.2 プレイヤーのオートバトル

`auto` 有効時、`playerTurn` は常に通常攻撃、`monsterTurn` は `pickMonsterAction()` に従う（`BattleCanvas` Auto battle effect）。

### 13.3 敵

- BattleCanvas: AV スケジュールに乗った敵が通常攻撃のみ（スキル AI 未実装）。ELITE/BOSS は攻撃時に状態異常付与を試行（§9.4）
- BattleEngine: プレイヤー/味方の行動 1 回につき、選択ターゲット敵が 1 回反撃（§5）

### 13.4 武器パッシブ（`src/logic/WeaponPassive.ts` — BattleEngine 経路のみ）

| systemTag | トリガー | 効果（ランク値 = `passive.values[min(rank,長さ)-1]`） |
|---|---|---|
| `SOUL_SHATTER` | 防壁破壊時 | 追撃 `floor(atk × 率)`（既定率 0.3） |
| `ACTION_VALUE` | 会心時 | avReduction 値を返すが **ログのみ**（AV への反映未実装） |
| `DEMON_MODE` | 攻撃時 | 通常: ゲージ +値（既定5）。`condition: DEMON_ACTIVE` は魔神化中のみ追撃 `floor(atk × 値/100)` |
| `SHIELD_PIERCE` / `GIANT_KILLING` | — | 未実装（第2章以降） |

BattleCanvas は `evaluateWeaponPassive` を import しておらず、実戦画面では武器パッシブが発動しない（§15）。

## 14. 敗北判定と実行系差異まとめ

- 敗北 = **プレイヤー HP ≤ 0** のみ（`isPlayerDead()`, `src/logic/PlayerDefeat.ts`）。味方モンスターの全滅は敗北ではない（Engine ではプレイヤー直接被弾に切替わるのみ）
- 敗北経路: 敵攻撃 / エリアギミック SLIP / 状態異常 DoT / 魔神化 SELF_DAMAGE 反動
- Canvas の敗北処理 `triggerPlayerDefeat()`: 予約済み敵行動をキャンセル → `waveTransition` で入力無効化 → MP 全回復 → 敗北リザルト（`wavesCleared` = クリア済み WAVE 数）
- Engine は `PLAYER_DEFEATED` ログを 1 回だけ記録し以降の行動を拒否

### 実行系差異一覧（どちらもコード上の事実）

| 項目 | BattleCanvas（実戦） | BattleEngine（サーバ/テスト） |
|---|---|---|
| 敵の攻撃対象 | 常にプレイヤー | ヘイト重み 50/30/20 で味方モンスター、全滅時プレイヤー |
| 敵被弾 variance | 0.8〜1.2 | 1.0 固定 |
| AV_DELAY ギミック | プレイヤー AV へ加算（effectRes 軽減） | プレイヤーへ PARALYSIS 付与 |
| ENRAGE | HP≤50% 中の攻撃ごとに倍率乗算 | 発火時に atk を恒久 ×1.5 |
| 魔神化ゲージ加算量 | §10.2 左列 | §10.2 右列 |
| ENERGY_DRAIN | 行動後 MP −riskValue(15) | スキルコスト ×2 |
| 武器パッシブ | 未接続 | ON_ATTACK / ON_SHIELD_BREAK で発動 |
| ターン開始シナジー（HP回復/ゲージ/吸収/免疫） | 未接続 | 適用 |
| effectHit/持続シナジーの状態異常反映 | 未接続 | 適用 |
| 端数処理（シールド） | round | floor |
