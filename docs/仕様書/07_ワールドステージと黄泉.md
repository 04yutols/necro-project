## 2. ワールドマップ（Layer 1）— `src/logic/WorldMapSystem.ts`

### 2.1 `buildWorldAreas(areaRecords, stages, clearedStages)`

1. **黄泉除外**: `isYomiStage(stage.id)` または `isYomiArea(chapter, area)` に該当するステージ/エリアを入口でフィルタ（`WorldMapSystem.ts:84-95`）。ワールドマップ・解放線・CURRENT 選定のいずれにも黄泉は混入しない。
2. エリアキーは `getAreaKey() = "${chapter}:${area}"`（第1章Area1と第2章Area1を区別）。エリアマスター未登録のステージからは `fallbackAreaFromStage` で仮エリアを合成（id=`ch{chapter}_area{area}`、色 `#8A2BE2`、座標は固定レール6点の循環）。
3. 並び順: `sortOrder ?? chapter*100+area` 昇順。

### 2.2 エリア状態 `WorldAreaState`

| 状態 | 条件（判定順） |
|---|---|
| `LOCKED` | エリア内ステージ0件 |
| `CLEARED` | SAFE を除く全ステージがクリア済み（`totalCount` は SAFE 除外で数える） |
| `CURRENT` | グローバル次ステージ（`getNextAvailableStage`）がこのエリアにある、またはエリア内に AVAILABLE ステージがある |
| `AVAILABLE` | AVAILABLE は無いが LOCKED でないノード（SAFE 等）に到達可能 |
| `LOCKED` | 上記いずれでもない |

`getCurrentWorldArea` は `CURRENT → AVAILABLE → 先頭 → null` の優先で現在エリアを返す。`AreaMap.tsx` はこの `WorldAreaView` を描画し、エリア選択 → Layer 2 ステージマップ → ステージ挑戦へ遷移する。`MapCanvas.tsx`（PixiJS 旧版）は現在どこからも import されていない死コード（未使用を grep で確認済み）。

## 3. ステージ解放と進行 — `src/logic/DungeonSystem.ts`

### 3.1 解放判定

```
isStageUnlocked(stage, clearedStages):
  nodeType === 'SAFE'        → 常に解放
  unlockRequires.length === 0 → 解放
  それ以外 → unlockRequires の全ステージ ID が clearedStages に含まれること（AND 条件）
```

進行状態 `StageProgressState = 'SAFE' | 'CLEARED' | 'AVAILABLE' | 'LOCKED'`。`getNextAvailableStage` はソート済みリスト（`sortOrder` 明示値優先 → chapter → difficulty → id）の先頭 AVAILABLE を返す。`getStageLineSegments` が `unlockRequires` から解放線（from→to）を生成する。

サーバ側でも `startStageForUser`（`src/app/actions.ts:571`）が `getEffectiveClearedStages`（DB の `clearedStages` 列と playerState 内の和集合、`src/services/PlayerSaveService.ts:104`）に対して同じ `isStageUnlocked` を検査するため、クライアント改竄では未解放ステージを開始できない。

### 3.3 WAVE 構成

全戦闘ノードは `waveCount: 3`。役割は WARMUP → SHIELD → ELITE/BOSS が基本形。WAVE 3 に per-wave `statScale` を手調整で焼き込んだノードがある（§5.2）。ステージ情報画面用の集計ロジック:

- `getPrimaryWeaknesses`: 出現敵の弱点を tier 重み（BOSS=4, ELITE=2, MINION=1）で集計し上位4属性を返す
- `getStageDropTable`: ステージ dropTable + 出現敵 dropTable をキー統合（同一キーは高 rate 優先）し、レアリティランク（UR5 > LR4 > SSR/EPIC3 > SR/RARE2 > R1 > COMMON0）→ rate 降順でソート。`isHidden` は `getVisibleDropTable` から除外され、件数のみ `getHiddenDropCount` で得られる

## 4. ステージ開始・リザルトのサーバフロー — `src/app/actions.ts`

### 4.1 開始（`startStageForUser`）

1. `resolveStageId` でエイリアス解決 → ステージ存在確認 → `nodeType === 'SAFE'` は `STAGE_NOT_PLAYABLE`
2. サーバ側解放チェック（§3.1）→ NG は `STAGE_LOCKED`
3. `StageAttempt` レコード発行（`STAGE_ATTEMPT_TTL_MS = 2時間`、`actions.ts:139`）。ゲストプレイ時のみ attempt なしで開始可（`page.tsx:187` `requiresStageAttempt = authFlow.status !== 'guest'`）

### 4.2 リザルト（`processStageResultForUser`）— 単一トランザクション

1. **attempt 消費**: 条件付き `updateMany`（本人・キャラ・ステージ一致、未消費、未失効）。失敗理由は `INVALID_STAGE_ATTEMPT` / `TOKEN_*_MISMATCH` / `STAGE_ATTEMPT_CONSUMED` / `STAGE_ATTEMPT_EXPIRED` に分解
2. **メトリクス正規化**（`normalizeStageClearMetrics`, `RankingService.ts:89`）: turnCount ≥1・clearTimeSec ≥1・totalDamage ≥0。上限は `getStageMetricCaps`（`actions.ts:439`）= `maxTurnCount = max(30, waveCount×30)` / `maxClearTimeSec = 3600` / `maxTotalDamage = max(1000, 敵HP総量×4)`。敵HP総量は per-wave `statScale` 適用後 + REVIVE ギミック分（`floor(hp × value)`）を加算
3. **EXP/ゴールド**: `expGain = floor(baseExp × (1 + jobLevel/100) × (MAGICAL なら1.1))`（`RewardService.calculateExp`）、`goldGain = baseGold`（毎回払い出し）
4. **ドロップ**（`RewardService.processStageDropTable`）:
   - `firstClearGuaranteed` は **stage.id が clearedStages に無い初回のみ** rate=1 で確定処理。残滓の chapter ゲートを**通らない**（確定枠は無フィルタ）
   - 通常 dropTable は `getStageDropTableForResidueUnlock` を通す: RESIDUE / MATERIAL エントリは「`stage.chapter >= 2` かつ `area1_node3` クリア済み」でなければ除去（`AbyssalResidueUnlockSystem.ts`）
   - 各エントリ独立抽選（MULTI_ROLL、`DropPolicySystem.ts:3`）。rate は 0〜1 にクランプ
   - ネクロマンス捕獲抽選を追加実行（§3.4）
5. **進行保存**: `clearedStages` へ ID 追記（重複なし）+ EXP/ゴールドを playerState ブロブへ反映
6. **記録**（`RankingService.recordStageClear`）: `StageRecord` upsert（turnCount → clearTimeSec の辞書順で自己ベスト更新）、`PlayerStats` を upsert — `totalDamage` 加算 / `bossKillCount`（`nodeType==='BOSS' || isAreaBoss` のとき +1）/ `bestResidueScore` max / **`bestDungeonFloor` max**（§7.4）
7. **世界ログ**: `BOSS_CLEARED`（そのボスステージの世界初クリア時のみ）/ `YOMI_MILESTONE`（§7.5）/ `RANKING_UPDATED`（残滓スコア首位更新時）→ Pusher 配信
8. トランザクション後に `RankingService.invalidate()`（Redis キャッシュ削除）

## 5. 敵スケーリング — `src/logic/EnemyScaling.ts`

### 5.1 `applyEnemyStatScale(enemy, statScale?)`

```
対象キー: hp / atk / def のみ（ENEMY_STAT_SCALE_KEYS）
stats[key] = Math.floor(stats[key] × factor)   // キーごと独立に切り捨て
factor: 有限数かつ > 0 のときのみ適用。無効値・未指定は 1（等倍）
```

spd / critRate / critDmg / effectHit / effectRes / shieldHp はスケールされない。戻り値は深いコピー（resistances / gimmicks / necromance / dropTable / battle も複製）。

適用箇所（WAVE 単位の `wave.statScale` を渡す）:

| 経路 | 箇所 |
|---|---|
| ライブ戦闘（本番経路） | `BattleCanvas.tsx:380, 2240` |
| BattleEngine（召喚敵の実体化） | `BattleEngine.ts:1007-1008`（コンストラクタ引数のエンジン単位 `enemyStatScale` を使用。per-wave 未接続 = TECH_DEBT L-3。本番戦闘は BattleCanvas 駆動のため実害なし） |
| サーバのメトリクス上限計算 | `actions.ts:430` |

## 7. 黄泉の階層（エンドコンテンツ）

第1章の敵プールを再構成した独立チャレンジタワー。B1 から一本鎖で下り続ける。周回 farm コンテンツではなく、各階は本編互換の独立3WAVEステージ。挑戦回数無制限・HP/Energy はステージごと全回復（本編と同一の戦闘後回復仕様）。

### 7.1 判定の一元化 — `src/logic/YomiFloors.ts`

| 定数/関数 | 値・仕様 |
|---|---|
| `YOMI_STAGE_ID_PATTERN` | `/^yomi_b(\d+)$/`（ゼロ埋め2桁想定だが桁数は不問） |
| `YOMI_CHAPTER` / `YOMI_AREA` | `1` / `99`（仮想エリア `ch1_area99`） |
| `CH1_FINAL_NODE_ID` | `'area1_node3'` |
| `isYomiStage(stageId)` | パターン一致判定 |
| `getYomiFloorNumber(stageId)` | 階層番号（1始まり整数）。非黄泉・0以下は `null` |
| `isYomiArea(chapter, area)` | `chapter===1 && area===99` |
| `getYomiMilestoneFloorForFirstClear(stageId, clearedStagesBeforeClear)` | `floor % 10 === 0` かつ初回クリアのときのみ階層番号、それ以外 `null` |

呼び出し側で `stageId.startsWith('yomi_')` 等を直接書かない規約（MAP混入・ランキング更新漏れ防止）。

### 7.2 解放条件 — `src/logic/YomiUnlockSystem.ts`

```
isYomiUnlocked(clearedStages) = clearedStages.includes('area1_node3')
```

- `BottomNavBar.tsx`: タブ `YOMI`（アイコン Layers）は未解放時ロック表示
- `page.tsx:361`: 未解放で YOMI タブを開くと `YomiLockedScreen`（「亡国の王都を制圧した後に解放されます。」）
- クライアント専用のストーリーフラグ（`CH1_CLEARED` 等）は解放判定に**使用しない**（端末間非同期のため）

| 通常階 | それ以外 | WARMUP（MINION×2）→ SHIELD（MINION+ELITE）→ ELITE（ELITE+MINION） |

敵はプール循環で割当（MINION プール7体 / ELITE SHIELD プール3体 / ELITE CLOSER プール4体、`generate-yomi-floors.mjs:23-26`）。

### 7.5 報酬（初回クリアのみ・通貨なし）

全階 `baseExp: 0` / `baseGold: 0` / `dropTable: []` — **リプレイ報酬なし**（EXP・ゴールド・ドロップとも 0。ただしネクロマンス捕獲抽選は毎クリア発生する）。報酬は `firstClearGuaranteed` に集約:

- **各階の確定素材**: itemId は `n < 5 → bone_chip`、`n < 10 → grave_crystal`、`n ≥ 10 → ossuary_memory`。数量は節目階=2、それ以外 `1 + floor(n/7)`（B7〜B13 は2個、B14以降は3個）
- **節目チェスト（B5 / B10 / B15 / B20 の初回クリア）**: 上記素材に加えて

| 階 | WEAPON_MATERIAL | RESIDUE |
|---|---|---|
| B5 | IDEA_SR ×1 | RARE ×1 |
| B10 | IDEA_SSR ×1 | EPIC ×1 |
| B15 | IDEA_SSR ×1 | EPIC ×1 |
| B20 | ABYSSAL_OBSIDIAN ×1 | **LEGENDARY ×1** |

`firstClearGuaranteed` は残滓の chapter≥2 ゲートを通らないため、黄泉（chapter 1）でも残滓が確定入手できる（`RewardService.ts:317-329` が確定枠を無フィルタで処理）。節目チェストの「受取済」表示はサーバフラグではなく `clearedStages` からの導出（表示専用）。
