# 02 — システムアーキテクチャ仕様書

> 最終更新: 2026-07-11 ｜ 生成方法: コードからのリバースエンジニアリング（コードが正） ｜ 主要ソース: `package.json`, `src/app/page.tsx`, `src/app/layout.tsx`, `src/store/useGameStore.ts`, `src/services/`, `src/logic/`, `src/lib/`, `src/app/actions.ts`, `prisma/schema.prisma`, `.github/workflows/ci.yml`, `vite.config.ts`, `wrangler.jsonc`

Necromance Brave は Next.js 15 (App Router) 上に構築されたシングルページ・モバイルファースト RPG である。画面遷移は URL ルーティングではなく Zustand ストアの `currentTab` によるタブ切替で行い、戦闘・マップは z-index 9999 のフルスクリーンオーバーレイとして描画する。ゲームロジックは React 非依存の純粋モジュール群（`src/logic/`）、ドメイン操作は Server Actions ＋ サービス層（`src/services/`）、永続化は Prisma + Neon PostgreSQL（個人セーブは `Character.playerState` JSON ブロブ）、デプロイは OpenNext 経由の Cloudflare Workers という構成をとる。

## 4. SPA / タブルーティング機構

### 4-1. タブ一覧

`currentTab` の型（`src/store/useGameStore.ts` L341）:

```typescript
currentTab: 'HOME' | 'BATTLE' | 'MAP' | 'EQUIP' | 'LAB' | 'YOMI' | 'LOGS' | 'JOB'
```

タブ遷移方向判定用の順序 `APP_TAB_ORDER`（`src/lib/motion.ts`）:
`['HOME', 'MAP', 'BATTLE', 'EQUIP', 'JOB', 'LAB', 'YOMI', 'LOGS']`

| タブ | コンポーネント | ナビバー表示 | 描画方式 | 解放条件 |
|---|---|---|---|---|
| HOME | `HomeHero` | ○ | ResponsiveFrame 内 | — |
| MAP | `AreaMap` | ○ | **フルスクリーン**（zIndex 9999） | — |
| BATTLE | `BattleCanvas`（isInBattle 時）/ No Active Battle プレースホルダ | ○ | **フルスクリーン**（zIndex 9999） | — |
| EQUIP | `LegionHub`（ラベル "LEGION"） | ○ | ResponsiveFrame 内 | — |
| JOB | `JobChangeScreen` | ✕（HomeHero のメニューから遷移） | ResponsiveFrame 内 | — |
| LAB | `NecroLab` | ○ | ResponsiveFrame 内 | `isAbyssalResidueUnlocked` = `'area1_node3'` クリア（`src/logic/AbyssalResidueUnlockSystem.ts`） |
| YOMI | `YomiTowerScreen` | ○ | ResponsiveFrame 内 | `isYomiUnlocked` = `'area1_node3'`（第1章最終ノード）クリア（`src/logic/YomiUnlockSystem.ts`） |
| LOGS | STORY / BATTLE / WORLD の3パネル切替（`StoryArchive` / `NecroLog` / `WorldLogPanel`） | ○ | ResponsiveFrame 内 | — |

- 未解放の LAB / YOMI はロック画面を表示し、`BottomNavBar` 側もロックアイコンに差し替わる（`src/components/layout/BottomNavBar.tsx`）。
- `BattleCanvas` は `next/dynamic` + `ssr: false` で遅延ロード（`src/app/page.tsx` L17）。

### 4-2. フルスクリーンオーバーレイ

`src/app/page.tsx`: `isInBattle`（`currentTab` とは別の useState）が true の間は
`position: absolute; inset: 0; zIndex: 9999` の `motion.div` で `BattleCanvas` を全画面描画。
`currentTab === 'MAP'` も同様に zIndex 9999 の全画面。それ以外は `ResponsiveFrame`（`BottomNavBar` 内蔵、`src/components/layout/ResponsiveFrame.tsx`）内で `AnimatePresence mode="wait"` により切替。

タブ遷移アニメ定数（`src/lib/motion.ts`）:

| 定数 | 値 |
|---|---|
| `MOTION.spring.standard` | `{ type: 'spring', stiffness: 295, damping: 33 }` |
| `MOTION.spring.soft` | `{ stiffness: 260, damping: 28 }` |
| `MOTION.spring.snappy` | `{ stiffness: 330, damping: 34 }` |
| `MOTION.duration` | fast 0.16 / normal 0.22 / slow 0.38 秒 |

### 4-3. ステージ開始・終了フロー（`src/app/page.tsx`）

```
requestStageStart(stageId)
  ├─ ゲスト以外: startStageAction(stageId) で StageAttempt トークン発行
  │    失敗時: SYNC ERROR トースト表示（SESSION_EXPIRED は 'necro-session-expired' イベント発火）
  ├─ triggerStageEnter(stageId) がストーリーを起動した場合:
  │    pendingStageId に保留 → シーンキューが空になったら startStageNow
  └─ startStageNow: activeStageId/attemptId セット → isInBattle=true → currentTab='BATTLE'

finishBattle（BattleCanvas onEnd）
  ├─ チュートリアル未消化フェーズあり → currentTab='HOME'
  ├─ isYomiStage(activeStageId)        → currentTab='YOMI'
  └─ それ以外                          → currentTab='MAP'
```

### 4-4. 認証フロー分岐（`src/hooks/useAuthFlow.ts`）

`AuthFlowStatus = 'checking' | 'authRequired' | 'loadingCharacter' | 'characterRequired' | 'ready' | 'sessionExpired' | 'guest' | 'error'`

`page.tsx` は status に応じて `AuthGate` / `CharacterCreation` / `LoadingScreen` / SYNC ERROR 画面 / `ReloginModal`（sessionExpired 時）を出し分ける。`'guest'` はローカルセーブのみで動作し、StageAttempt 発行をスキップする。

## 5. Zustand ストア構成

| ストア | persist キー | 内容 |
|---|---|---|
| `useGameStore` | `necro-game-store-v1`（version 2） | プレイヤー・パーティ・インベントリ・魔神化・タブ等の全ゲーム状態 |
| `useStoryStore` | `necro-story-store-v2`（+ scope キー `necro-story-store-scope-v1`） | activeScene / sceneQueue / viewedScenes / storyFlags |
| `useTutorialStore` | `necro-tutorial-store-v2`（+ scope キー `necro-tutorial-store-scope-v1`） | チュートリアル完了フェーズ |
| `useAudioStore` | `necro-audio-settings` | 音量等のオーディオ設定 |

story / tutorial ストアはユーザーごとの「スコープ切替」機構を持ち、`useAuthFlow` が `switchStoryPersistenceScope` / `switchTutorialPersistenceScope` を呼んでアカウント単位に分離する。

### 5-1. useGameStore の状態区分（`src/store/useGameStore.ts`）

**永続化対象**（`partializeGameState` が列挙。ここに無いものは揮発）:
`player, necroStatus, party(3枠), inventoryMonsters, soulShards, inventoryItems, abyssalResidues, equippedResidueSlots(5枠), residueMaterials, weaponMaterials, transmutationPoints` + メタ情報 `cacheKind('guest-save' | 'server-snapshot'), cachedAt, offlineQueue(常に空配列)`

**揮発（ランタイム専用）**: `monsterCurrentHp, battleLogs(最大50件), actionTrigger, equippingMonsterId, currentTab, isServerBacked, demonGauge / isDemonMode / demonActionsRemaining / demonUltimateUsed / demonFormJobId / demonEffectBFlag / demonRiskType / demonRiskValue`

**復元規則（`mergePersistedGameState`）**:
- リハイドレート後は必ず `isServerBacked: false`（localStorage はキャッシュ扱い。真実はサーバー）。
- 残滓未解放なら `equippedResidueSlots` を空 5 枠へ強制リセット。
- `currentTab` は常に `'HOME'` に戻る。
- SSR / localStorage 不可時はインメモリ `Map` ストレージへフォールバック。

**主要アクション**:
- `initialize()` — ゲスト初期データ投入（アルド warrior Lv1、初期モンスター3体、モック武器4本 = `MOCK_WEAPONS`、初期消耗品3種）。E2E 用に `sessionStorage` の `necro-e2e-cleared-stages` / `necro-e2e-battle-boost` を読む（localhost 限定）。
- `loadFromServer(data: ServerGameData)` — サーバーロード。`isServerBacked: true`。
- `getBattleParty()` — `applyNecroToMonster`（ネクロレベル補正、`src/logic/NecroGrowthSystem.ts`）+ `hydrateMonsterEnergy` を適用した戦闘用パーティを返す。
- 魔神化: `startDemonMode` は `demonGauge >= 100` が条件。ゲージを 0 にして `demonActionsRemaining = DEMON_ACTION_LIMIT = 3`（`src/logic/DemonizationSystem.ts` L4）。
- 武器: `rankUpWeapon`（rank 上限5）/ `reforgeWeapon` / `dismantleWeapon`（装備中は不可）— コスト計算は `src/logic/WeaponSystem.ts` に委譲。
- 残滓: `equipResidueToSlot`（`isResidueSlotCompatible` でスロット適合検証）/ `upgradeResidue`。
- `setPlayer` / `equipItem` / `changeJob` 等は `withDerivedElementBoosts`（`src/logic/StatSystem.ts` の `calculateCharacterStatProfile`）で属性ダメージ加成を再導出してから格納する。

## 6. サービス層（`src/services/`）

| サービス | 実行環境 | 責務 |
|---|---|---|
| `MasterDataService` | 両方 | シングルトン。マスター JSON 10 本を型付きで提供（getJob/getMonster/getEnemy/getItem/getStage/getArea/getSkill/getDemonForm/getNecroConfig ほか getAll 系）。モンスターは `hydrateMonsterEnergy` を適用して返す |
| `JobService` | サーバー | 転職・ジョブレベル。Prisma 有無両対応のオーバーロード。保存は `PlayerSaveService` 経由 |
| `NecroService` | サーバー | 魂石化（SoulShard 生成: `atkBonus = floor(atk×0.1)`）・シャード装備。インメモリ/Prisma 両対応 |
| `RewardService` | サーバー | ステージドロップ計算（武器/消耗品/残滓/素材/武器素材/ネクロマンスモンスター）。残滓解放状態でドロップテーブルを切替 |
| `PlayerSaveService` | サーバー | `Character.playerState` JSON ブロブの読み書き。スキーマバージョン管理（`PLAYER_SAVE_SCHEMA_VERSION = 3`, 最小サポート = 1。`src/types/playerSave.ts`） |
| `AuthService` | サーバー | サインアップ・パスワード変更。パスワード規則: **12文字以上、または英数字混合8文字以上**（`MIXED_PATTERN = /^(?=.*[a-zA-Z])(?=.*\d).{8,}$/`） |
| `SessionSecurityService` | サーバー | `SESSION_MAX_AGE_SECONDS = 86400`（24h）。`User.sessionVersion` によるセッション一括失効 |
| `RateLimitService` | サーバー | 認証レート制限。login: IP 20回/10分・email 10回/10分。signup: IP 5回/60分・email 3回/60分 |
| `RankingService` | サーバー | ランキング。Upstash Redis REST をキャッシュに使用（`CACHE_TTL_SEC = 300`）。未設定時は Prisma 直読みへフォールバック |
| `WorldEventService` | サーバー | ワールドログ（`WorldLog` テーブル追記 + Pusher Channels 配信。Pusher 未設定時は配信スキップ） |
| `AudioService` | クライアント（'use client'） | Web Audio によるプロシージャル BGM/SE。シーン enum: HOME_LOBBY / MAP_EXPLORE / BATTLE_NORMAL / BATTLE_BOSS / DEMON_OVERLAY / RESULT_WIN / RESULT_LOSE / NECRO_LAB / STORY_NEUTRAL / STORY_EMOTIONAL / SSR_REVEAL / UR_REVEAL |

## 7. サーバーサイド

### 7-1. Server Actions（`src/app/actions.ts`, 'use server'）

主要アクション（各々に認証済みユーザーを引数に取る `*ForUser` 変種あり）:

`signUpAction, changePasswordAction, startStageAction（StageAttempt 発行）, processStageResultAction（結果検証・報酬確定）, loadCharacterAction, createCharacterAction, fetchPlayerAction, changeJobAction, processGrowthAction, soulStoneAction, updatePartyAction, equipShardAction, equipItemAction / unequipItemAction, equipResidueAction, enhanceResidueAction, rankUpWeaponAction / reforgeWeaponAction / dismantleWeaponAction, loadGameStateAction`

### 7-2. API Routes / middleware

| パス | 内容 |
|---|---|
| `/api/auth/[...nextauth]` | NextAuth ハンドラ |
| `/api/auth/login`, `/api/auth/signup`, `/api/auth/logout` | 独自認証エンドポイント（レート制限付き） |

### 7-3. 認証（`src/auth.ts`）

NextAuth v5、Credentials プロバイダのみ（email + password、bcrypt 照合）。セッションは JWT 戦略・`maxAge = SESSION_MAX_AGE_SECONDS`（24h）。JWT コールバックで `sessionVersion` を検証し、DB 側の `User.sessionVersion` と不一致ならトークン無効化（強制再ログイン）。

### 7-4. 管理画面（`src/app/admin/`）

マスターデータ CRUD ページ群（areas / demon-forms / enemies / items / jobs / materials / monsters / necro-config / skills / stages / story）、LangGraph エージェント実行（`agents/`, `agents/batch/`）、バランスシミュレータ（`simulator/`）、監査（`audit/`）。`adminGuard.ts` でガード。

| `PlayerStats` / `WorldLog` | 統計・ワールドイベントログ |

個人セーブブロブ `PlayerSaveData`（`src/types/playerSave.ts`）: `schemaVersion(現行 3)`, `player{name, currentJobId, gold, clearedStages, jobs, passives, necroStatus, equipmentIds(8スロット), partyMonsterIds(3), equippedResidueIds(5)}`, `weaponMaterials`, `residueMaterials`, `transmutationPoints`。装備・パーティ・残滓は **ID 参照**で、実体は正規化テーブル側に持つ（doc 118 のハイブリッド方針が実装済み）。

### 8-3. Prisma クライアント（`src/lib/prisma.ts`）

`PrismaNeon` アダプタ + `DATABASE_URL`。非本番では `ws` を WebSocket コンストラクタに設定し `WS_NO_BUFFER_UTIL=1` を強制。globalThis キャッシュで開発時の多重生成を防止。
