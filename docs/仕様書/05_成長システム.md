# 05. 成長システム（職業・経験値・死霊術）

> 最終更新: 2026-07-11 ｜ 生成方法: コードからのリバースエンジニアリング（コードが正） ｜ 主要ソース: `src/logic/ExperienceSystem.ts`, `src/logic/JobSystem.ts`, `src/logic/JobGrowthSystem.ts`, `src/logic/JobBaseStatsInterpolation.ts`, `src/logic/EnergySystem.ts`, `src/logic/NecroGrowthSystem.ts`, `src/logic/NecromanceCaptureSystem.ts`, `src/logic/StatSystem.ts`, `src/services/JobService.ts`, `src/services/NecroService.ts`, `src/services/PlayerSaveService.ts`, `src/services/RewardService.ts`, `src/data/master/jobs.json`, `src/data/master/necroConfig.json`

本書は主人公（アルド）の成長二軸を定義する。**縦軸＝職業システム**（職業ごとの独立レベル・EXP、レベル固定テーブルによる基礎ステータス、職業跨ぎ永続パッシブ、SP=MP成長）と、**横軸＝死霊術（ネクロマンス）**（ネクロLv 1〜500 / Rank 1〜10、味方モンスターへのステ倍率、軍団コスト上限、捕獲成功率）である。ネクロLvは主人公自身を一切強化しない（`src/logic/NecroGrowthSystem.ts` 設計原則）。あわせて、戦闘用最終ステータスの集計パイプライン（基礎＋パッシブ＋装備＋残滓）を記述する。

## 1. 職業EXP曲線と職業レベル

ソース: `src/logic/ExperienceSystem.ts`

### 1.1 EXP曲線（累積式）

```
MAX_JOB_LEVEL = 99
expForLevel(L) = (L - 1) × (L + 8)    // Lv L に到達するための累積EXP。Lv1 = 0
levelFromTotalExp(totalExp)           // 累積EXPからLvを線形探索（上限99）
```

| Lv | 2 | 3 | 4 | 10 | 20 | 30 | 50 | 99 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 累積必要EXP | 10 | 22 | 36 | 162 | 532 | 1,102 | 2,842 | 10,486 |

- EXPは**職業ごとに独立**に保持する（`UserJobState { jobId, level, exp }`、`src/types/game.ts`）。
- `getJobLevelProgress(totalExp)` が UI 用の進捗（`expIntoLevel` / `expToNextLevel` / `progressRatio`）を返す（HomeHero で使用）。

### 1.2 EXP付与量（ステージクリア時）

ソース: `src/services/RewardService.ts` `calculateExp()`

```
expGain = floor( stage.rewards.baseExp × (1 + 現職業Lv/100) × categoryMultiplier )
categoryMultiplier = 1.1 (category === 'MAGICAL') / 1.0 (それ以外)
```

### 1.3 EXP付与フロー（サーバー永続化）

ソース: `src/services/PlayerSaveService.ts` `applyJobExpGainToSave()`、呼び出し元 `src/app/actions.ts`（processStageResultForUser）と `src/logic/GameManager.ts` `processStageResult()`

1. `expGain` を**現在職業のみ**の `exp` に加算し、`levelFromTotalExp` で新Lvを確定。
2. Lvが上がった場合、`levelBonuses`（§2.4）の該当区間分を `player.passives` に**永続加算**。
3. 同じ `expGain` がそのままネクロEXPフィード（§5.4）にも渡る（`applyNecroExpGainToSave`）。

クライアント（ローカル実行）は `useGameStore.addExp()` が同じ `levelFromTotalExp` / `getJobBaseStatsAtLevel` / `calculateEnergyState` でLv・基礎ステ・maxEnergy を再計算する（`src/store/useGameStore.ts`）。

### 2.2 転職（changeJob）

ソース: `src/services/JobService.ts` `changeJob()` / `buildChangedCharacter()`、`src/services/PlayerSaveService.ts` `changeJobInSave()`

- 解放条件未達なら `Job ${id} is locked` エラー。

- 永続化版（`changeJobInSave`）はセーブJSONの `currentJobId` / `jobs[]` のみ更新（ステータスはロード時に毎回導出。§3.4）。

### 2.3 スキル解放

## 3. 職業別基礎ステータス（baseStatsByLevel）

ソース: `src/logic/JobGrowthSystem.ts`, `src/data/master/jobs.json`, `src/logic/BalanceConfig.ts`

### 3.1 導出ルール

```
getJobBaseStatsAtLevel(job, level, fallback = INITIAL_PLAYER_BASE_STATS):
  safeLevel = clamp(floor(level), 1, 100)         // JOB_BASE_STATS_MIN/MAX_LEVEL
  table = job.baseStatsByLevel[String(safeLevel)]
  if (table が 8ステータス全て有限数値) return round(table)
  else return round(fallback × job.statModifiers) // フォールバック
```

- 丸め（`roundBaseStats`）: hp ≥1・atk ≥1・spd ≥1 は四捨五入、def ≥0 四捨五入、critRate/critDmg/effectHit/effectRes は小数1桁（下限0）。
- `INITIAL_PLAYER_BASE_STATS = { hp:30, atk:4, def:4, spd:100, critRate:5, critDmg:150, effectHit:0, effectRes:0 }`（`src/logic/BalanceConfig.ts`）。
- 全12職業が `baseStatsByLevel`（キー "1"〜"100"、mp 込みの9値）を持つため、通常プレイでフォールバック（`statModifiers`）が使われることはない。`statModifiers` はテーブル欠損時の保険。
- テーブルは Lv100 まで存在するが、職業Lv上限は 99（§1.1）のため **Lv100 行はEXPでは到達不能**（クランプ用）。
- レベルアップ時のDBへの増分加算は存在しない。基礎ステはロード・転職・EXP加算のたびにテーブルから再導出する（`toCharacterDataForSave`, `JobService.buildChangedCharacter`, `useGameStore.addExp`）。

### 3.3 中間レベル補間（管理画面専用）

ソース: `src/logic/JobBaseStatsInterpolation.ts`（使用箇所は `src/components/admin/forms/JobForm.tsx` のみ）

Lv100 の最終値を入力すると Lv2〜99 を自動補間する管理ツール用ロジック。**ランタイムの成長計算では使わない**（ランタイムはテーブル参照のみ）。

```
t = (lv - 1) / 99
ratio = 0.72t + 0.28t²                        // 序盤緩やか・終盤やや加速
value(lv) = start + (end - start) × ratio
```

- 整数ステータス（hp/mp/atk/def/spd）は四捨五入、hp/mp/atk/spd は下限1、def と%系は下限0、%系は小数1桁。

### 3.4 レベル差分・監査スコア

- `calculateJobBaseStatsDelta(job, fromLv, toLv)`: HP/ATK/DEF のテーブル差分を返す（レベルアップ演出用）。
- 監査用総合スコア（`calculateJobBaseStatsPowerScore`）:
  `score = hp×0.15 + atk×3 + def×2 + spd + critRate×2 + critDmg×0.5 + effectHit×0.8 + effectRes×0.8`

## 4. SP（MP / Energy）成長

ソース: `src/logic/EnergySystem.ts`, `src/data/master/jobs.json` `energyCurve` / `baseStatsByLevel.mp`

### 4.1 maxEnergy 導出

```
calculateMaxEnergy(job, level):
  mp = job.baseStatsByLevel[String(min(100, level))].mp   // 第1優先
  if (mp が正の有限数値) return max(1, floor(mp))
  // フォールバック（テーブル欠損時のみ）
  return max(1, floor(energyCurve.baseMaxEnergy + energyCurve.spGrowthPerLevel × (level - 1)))
```

### 5.3 軍団コスト上限（maxCost）

```
calcNecroMaxCost(L) = base + floor(L / d1) + (rank - 1) × c2
                    = 6 + floor(L/10) + (rank-1)×2
```

| necroLv | 1〜9 | 10〜19 | 30〜39 | 50 | 51 | 100 | 500 |
|---|---:|---:|---:|---:|---:|---:|---:|
| maxCost | 6 | 7 | 9 | 11 | 13 | 18 | 74 |

- 編成検証は `NecroService.validatePartyFormation()`（`src/services/NecroService.ts`）: スロットは**3枠固定**（違反時「パーティ編成は3枠固定です。」）、合計コスト > maxCost で「コスト超過です」。
- セーブ正規化（`normalizeNecroStatus`, `src/services/PlayerSaveService.ts:142`）では `maxCost = max(導出値, 保存値)`（旧セーブ救済のラチェット）。

### 5.4 ネクロEXP曲線（職業EXPと独立）

```
reqNecroExp(L) = (L - 1) × (L + 9)          // Lv L 到達の累積EXP（coefficient=9）
necroLevelFromExp(totalExp)                  // 線形探索、上限500
necroExpFromGain(expGain) = floor(expGain × 1.5)   // necroExpRate
```

| Lv | 10 | 50 | 51 | 100 | 500 |
|---|---:|---:|---:|---:|---:|
| 累積必要EXP | 171 | 2,891 | 3,000 | 10,791 | 253,991 |

- 取得源は職業EXPと**同一フィード**: ステージクリアの `expGain` を job 側にそのまま、necro 側に ×1.5 して付与（`applyNecroExpGainToSave`, `src/services/PlayerSaveService.ts:527`）。
- レベルはラチェット式: `newLevel = max(現level, necroLevelFromExp(newExp))`（下がらない）。maxCost も `max(現maxCost, 導出値)`。
- 職業の `expForLevel`（MAX 99 ハードコード）と関数を共有しない（流用禁止、`NecroGrowthSystem.ts` コメント）。

### 5.5 永続化とマイグレーション

- `NecroStatus = { level, maxCost, exp }`（`src/types/game.ts:439`）。**rank は保存せず都度導出**。旧 `rank` / `baseStatsBonus` フィールドは廃止済み。
- セーブは `Character.playerState`(JSON) 内、schema v3。v2→v3 変換（`PLAYER_SAVE_MIGRATIONS[2]`, `src/services/PlayerSaveService.ts:263`）:
  `新level = clamp((旧rank-1)×50 + 旧level, 1, 500)`、`新maxCost = max(calcNecroMaxCost(新level), 旧maxCost)`、rank/baseStatsBonus は読み捨て。
- 初期値: `level=1, maxCost=calcNecroMaxCost(1)=6, exp=0`（`emptyPlayerSave`、`useGameStore` 初期値も同じ）。

## 6. ステータス集計パイプライン

### 6.1 主人公（calculateCharacterStatProfile）

ソース: `src/logic/StatSystem.ts:295`。BattleEngine・LegionHub・EquipmentManager・BattleCanvas が共通利用。

```
job       = character.stats                    // §3 の職業基礎ステ（テーブル導出値）がそのまま基準値
passives  = passiveBonusesToStats(character.passives, job)
            hp/atk/def/spd: job値 × passiveXxxBonus% / 100（乗算由来の加算値）
            critRate/critDmg: %ポイントをそのまま加算値に
            effectHit/effectRes: パッシブ対象外（常に 0）
equipment = calculateEquipmentContribution(character.equipment, job)   // 全スロット走査
residues  = calculateResidueContribution(残滓5枠, job)                 // mainStat + subOptions
total     = round(job + passives + equipment.stats + residues.stats)
necro     = 常にゼロ（ネクロLvは主人公を強化しない。StatBreakdown.necro はゼロ固定）
elementDmgBoosts = mergeElementDmgBoosts(equipment分, residue分)
```

- **合成順序は単純加算**（equipment/residue の %オプションも「job基準値×%」を先に加算値化してから合算）。グループ間の乗算はない。
- 丸め: 各グループは `roundStatsForBonus`（四捨五入・%系は1桁、下限なし）、total は `roundStats`（hp/atk/spd ≥1、def ≥0、%系 ≥0・1桁）。
- 武器は `WeaponSystem` の実効値（`getWeaponEffectiveStats` / `getWeaponEffectiveSubOptions`）を使い、強化Lv・限界突破を反映。

#### サブオプション正規化（applyOption）

- エイリアス変換: `MATK→ATK, MDEF→DEF, AGI→SPD, LUCK→CRIT_RATE, TEC→CRIT_DMG, MP→ENERGY`（`OPTION_ALIASES`）。
- `XXX_FLAT` → 実数加算、`XXX%` → `job基準値 × value / 100` を加算、接尾辞なし → 実数加算。
- `<ELEMENT>_DMG_BOOST` → 属性ダメージ加成に加算。`VOID_DMG_BOOST` / `ALL_DMG_BOOST` は全8属性へ一括加算。
- `ENERGY`（MP由来）に対応する BaseStats キーは無いため、ステータス集計上は**無効**（maxEnergy 加算は未実装。§8）。

### 6.2 味方モンスター

```
raw stats（DB/ストア保存値）
  → applyNecroToMonster（hp/atk/def/spd × necroMult、§5.2。唯一の注入点）
  → hydrateMonsterEnergy（currentEnergy/maxEnergy 正規化）
  → BattleEngine（HP初期化・行動順 10000/spd・被ダメ防御に effective stats を使用）
攻撃力のみ追加乗算: atk × spiritCore.atkMultiplier × (awakened ? 1.5 : 1)   // MonsterAttackSystem.ts
```

モンスターには装備（weapon）・残滓5枠・SoulShard・霊核の装着枠があるが（`src/types/game.ts` MonsterData）、本書の範囲では捕獲・necro倍率までを正とする。装備側の効果詳細は装備仕様書を参照。

## 7. ネクロマンス捕獲

ソース: `src/logic/NecromanceCaptureSystem.ts`、オーケストレーション `src/services/RewardService.ts` `processStageNecromance()`

### 7.1 基底捕獲率とコスト（Tier別）

| EnemyTier | 基底捕獲率 | 軍団コスト |
|---|---:|---:|
| MINION | 0.12 (12%) | 1 |
| ELITE | 0.04 (4%) | 2 |
| BOSS | 0.001 (0.1%) | 4 |

- 敵マスターの `necromance.captureRate` があればそれを基底値として優先（R1基底値）。`necromance.allyCost`（≥1、floor）があればコストも上書き。

### 7.2 実効捕獲率（Rank補正）

```
applyNecroRankToCaptureRate(base, rank) = clamp(base × 1.1^(rank-1), 0, 0.75)
```

| tier(基底) | R1 | R5 | R10 |
|---|---:|---:|---:|
| MINION (0.12) | 0.1200 | 0.1757 | 0.2830 |
| ELITE (0.04) | 0.0400 | 0.0586 | 0.0943 |
| BOSS (0.001) | 0.0010 | 0.0015 | 0.0024 |

- cap 0.75 は R1 でも適用される（基底 0.9 を設定しても実効 0.75）。
- rank は `deriveNecroRank(necroStatus.level)` で導出して渡す（`src/logic/GameManager.ts:156`, `src/app/actions.ts:740`）。

### 7.3 抽選フロー（rollStageNecromance）

1. `stage.waves[].enemyIds` を走査し、敵マスターID単位で**重複排除**した候補リストを作る（出現順維持）。
2. 所持済み（`MonsterData.masterId`、なければ `id` で補完）はスキップ。**同一 masterId は1体まで**。
3. 各候補で `roll = rng()` を引き、`roll < effectiveRate` なら成功。成功した ID は同一抽選内でも即座に所持済み扱い。
4. 成功時 `createNecromancedMonster(enemy)` で `MonsterData` を生成:

| フィールド | 値 |
|---|---|
| `id` | `necro_${enemyId}_${uuid}`（Web Crypto の UUID v4） |
| `masterId` | 敵マスターID |
| `name` | `nameJa` 優先、なければ `name` |
| `tribe` / `resistances` / `tier` / `weaknesses` | 敵のコピー |
| `cost` | `necromance.allyCost` または Tier別値（§7.1） |
| `stats` | `enemy.stats` に `necromance.allyStats`（部分上書き）をマージ — **Lv1/R1 基底値として保存**（necro倍率は焼き込まない） |
| `skillIds` | `necromance.skillIds` のコピー |
| `currentEnergy` / `maxEnergy` | `necromance.allyMaxEnergy`、なければ 30 |

### 7.4 魂の欠片（SoulShard）変換

ソース: `src/services/NecroService.ts` `createSoulShard()`

モンスターを欠片化すると（DB版はモンスター削除を伴う）:

```
atkBonus        = floor(monster.stats.atk × 0.1)
elementDmgBoost = floor(monster.stats.effectHit × 0.1)
specialAbility  = 種族別: UNDEAD→REGENERATE_SOUL / DEMON→BANE_OF_LIGHT /
                  DRAGON→ELEMENTAL_SURGE / ORC→IRON_HIDE / BEAST・HUMANOID→なし
```

装備は `equipSoulShard(monsterId, shardId)`（所有者一致チェックあり、DB のみ）。

## 9. 旧設計書との差異

コードを正として検出した食い違い。旧設計書は「意図」の参考であり、以下の点で現実装と異なる。

1. **doc 10（職業転職システム）— energyCurve 構成が旧式**: doc は `{ baseMaxEnergy, energyRegen, ultimateCost }` と記載するが、現行は `{ baseMaxEnergy, ultimateCost, spGrowthPerLevel }` で `energyRegen` は存在しない（`src/types/game.ts:71-75`）。また「転職時は `baseStats × statModifiers` で再計算」は旧仕様で、現行は `baseStatsByLevel` テーブル導出が正（`statModifiers` は欠損時フォールバックのみ。`src/logic/JobGrowthSystem.ts:44-53`）。転職条件表・スキル解決フローは現行と一致。
