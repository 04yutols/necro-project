## 2. 基幹ステータス型

### 2.1 BaseStats（8種・`src/types/game.ts`）

| フィールド | 説明 |
|---|---|
| `hp` | 最大HP |
| `atk` | 攻撃力（物理・魔法共通） |
| `def` | 防御力（物理・魔法共通） |
| `spd` | 速度（行動値 = 10000/spd） |
| `critRate` | 会心率 %（基礎 5.0） |
| `critDmg` | 会心ダメージ加算 % |
| `effectHit` | 効果命中 % |
| `effectRes` | 効果抵抗 % |

- `Resistances = Partial<Record<ElementType, number>>`。負数 = 弱点、正数 = 耐性（%）。
- `JobBaseStats = BaseStats & { mp: number }`（職業レベルテーブル用。`mp` は最大MP）。

### 2.2 PassiveBonuses（永続パッシブ・転職後もリセットされない）

`passiveAtkBonus` / `passiveDefBonus` / `passiveSpdBonus` / `passiveHpBonus`（現在職の基礎ステに対する **%補正**）、`passiveCritRateBonus` / `passiveCritDmgBonus`（%値の**直接加算**）。ソース: `src/types/game.ts` のコメント。

## 3. 主要エンティティ型

### 3.1 CharacterData（主人公アルド）

```typescript
// src/types/game.ts
CharacterData: {
  id, name, currentJobId: string; category: ClassCategory;
  baseStats?: BaseStats;
  necroLevel?: number;            // 死霊術Lv（max 500）。主人公は強化せず、味方モンスター補正と軍団コスト上限に使う
  stats: BaseStats; passives: PassiveBonuses;
  equipment: EquipmentSlots;      // weapon + 7スロット（現行UXは weapon のみ使用）
  baseResistances: Resistances;
  jobs: UserJobState[];           // { jobId, level, exp } — 職業ごと独立レベル
  isAwakened: boolean; clearedStages: string[]; gold: number;
  statusEffects?: StatusEffect[];
  currentEnergy: number;          // 現在MP（ランタイム・DB非保存。魔神化ゲージとは別リソース）
  maxEnergy: number;              // job.baseStatsByLevel[level].mp または energyCurve から導出
  elementDmgBoosts: Partial<Record<ElementType, number>>;  // 装備・残滓から集計
}
```

`EquipmentSlots` は `weapon / sub / head / body / arms / legs / acc1 / acc2` の8スロット（各 `ItemData | null`）。

### 3.2 MonsterData（編成モンスター兼バトル敵ランタイム）

```typescript
// src/types/game.ts
MonsterData: {
  id: string; masterId?: string;  // ネクロマンス元マスターID。同一masterIdは1体まで獲得可能
  name: string; tribe: Tribe; cost: number;
  stats: BaseStats; resistances: Resistances;
  skillIds?: string[];            // 味方化後に保持するスキルID
  currentEnergy: number;          // スキル使用で消費、自動回復しない
  maxEnergy: number;              // 捕獲時は enemy.necromance.allyMaxEnergy から初期化
  equipment?: EquipmentSlots;     // weapon のみ使用
  equippedResidues?: (AbyssalResidueData | null)[];  // 深淵の残滓 5スロット
  equippedShardId?: string;       // 魂の欠片
  spiritCore?: SpiritCoreData;    // 霊核
  // ▼ バトルランタイム専用（DB非保存）
  tier?: EnemyTier; weaknesses?: ElementType[];
  shieldHp?: number; maxShieldHp?: number; shieldBroken?: boolean;
  statusEffects?: StatusEffect[]; gimmicks?: BossGimmick[];
}
```

### 3.3 育成・装備系サブエンティティ

| 型 | 定義（`src/types/game.ts`） |
|---|---|
| `SoulShardData` | `{ id, originMonsterName, effect: { atkBonus, elementDmgBoost, specialAbility? } }` |
| `AbyssalResidueData` | `{ id, name, itemId, rarity: 'COMMON'\|'RARE'\|'EPIC'\|'LEGENDARY', mainStat: {type,value}, subOptions: SubOption[], level(1〜20), exp, maxExp, residueScore?, tierHistory? }` |
| `ResidueMatData` | `{ id, name, quantity, expValue, rarity: 'COMMON'\|'RARE'\|'EPIC'\|'LEGENDARY' }` — materials.json のレコード型 |
| `SpiritCoreData` | `{ id, name, element?, skillChangeId?, atkMultiplier }` |
| `SubOption` | `{ type: string, value: number }` |

### 3.4 NecroStatus と死霊術成長式

```typescript
// src/types/game.ts
NecroStatus: { level: number /* Max 500 */; maxCost: number; exp: number }
```

**注意: `rank` と `baseStatsBonus` はフィールドとして存在しない。** Rank はレベルから導出する派生値（下表）。数式の単一の真実源は `src/logic/NecroGrowthSystem.ts`、調整係数は `src/data/master/necroConfig.json`（`NecroConfigData` 型）。

| 定数/式 | 値・定義 | ソース |
|---|---|---|
| `MAX_NECRO_LEVEL` | 500 | `src/logic/NecroGrowthSystem.ts` |
| `MAX_NECRO_RANK` | 10 | 同上 |
| `LEVELS_PER_RANK` | 50 | 同上 |
| Rank導出 | `rank = clamp(floor((L-1)/50)+1, 1, 10)`（50Lvごと自動昇格・転生なし） | `deriveNecroRank` |
| モンスターステ倍率 | `mult = 1 + min(L,50)*kA + max(0,L-50)*kB + (rank-1)*k2`。HP/ATK/DEF/SPDのみに `Math.round(stat*mult)` で適用 | `necroMonsterMultiplier` / `applyNecroToMonster` |
| 軍団コスト上限 | `maxCost = base + floor(L/d1) + (rank-1)*c2` | `calcNecroMaxCost` |
| 捕獲率Rank補正 | `clamp(baseRate * rankMultiplier^(rank-1), 0, cap)` | `applyNecroRankToCaptureRate` |
| ネクロEXP曲線 | `reqNecroExp(L) = (L-1)*(L+coefficient)`（Lv1=0） | `reqNecroExp` |
| EXP変換 | `necroExp = floor(expGain * necroExpRate)`（職業共有EXPからの変換） | `necroExpFromGain` |

**necroConfig.json 実測値**（`DEFAULT_NECRO_CONFIG` と同値）:

| セクション | 値 |
|---|---|
| `monsterStatMultiplier` | kA=0.006, kB=0.0024, k2=0.05 |
| `maxCost` | base=6, d1=10, c2=2 |
| `captureRate` | rankMultiplier=1.1, cap=0.75 |
| `expCurve` | coefficient=9, necroExpRate=1.5 |

### 3.5 職業EXP曲線（参考: `src/logic/ExperienceSystem.ts`）

- `MAX_JOB_LEVEL = 99`（ネクロLvとは別軸・分離必須）
- `expForLevel(L) = (L-1)*(L+8)`（累積。Lv1=0, Lv2=10, Lv3=22, Lv4=36）

## 5. 各ファイルのスキーマ詳細

### 5.1 jobs.json（`JobData`）

- 主要フィールド: `name / displayName / nameEn / title / tier(1|2) / category / baseAttackType / role / description / unlock / statModifiers / energyCurve / baseStatsByLevel / levelBonuses / skills`
- `baseStatsByLevel`: キー `"1"`〜`"100"` の100段階（`JobBaseStats`、`mp` 含む）。**全12職が100レベル分を保持**。ただしランタイム上限は `MAX_JOB_LEVEL = 99`（`src/logic/ExperienceSystem.ts`）。
- `energyCurve`: `{ baseMaxEnergy, ultimateCost, spGrowthPerLevel }`。`ultimateCost` は型コメントで「未使用・将来用」。`baseMaxEnergy` 実測: Tier1 は 10〜22、Tier2 は 90〜130。
- `levelBonuses`: マイルストーンLv（実データでは `"10"/"20"/"30"` または `"10"/"20"/"40"`、necromancer のみ4本）→ `Partial<PassiveBonuses>`。
- `skills`: `{ level, skillId }[]`。Lv1 で初期スキル + 奥義 `ult_*` を持つ。
- `statModifiers`: `Partial<BaseStats>`（職業ごとの倍率的補正値。実データでは 0.8〜1.2 程度の係数）。
- `unlock`: Tier1 は `null`。Tier2 は `{ jobs: [{ jobId, minLevel }] }` 形式で2条件（主系統 Lv20 + 副系統 Lv10）。実測の解放系譜:

| Tier2職 | 条件1 | 条件2 |
|---|---|---|
| dark_knight | warrior Lv20 | dark_priest Lv10 |
| berserker | warrior Lv20 | rogue Lv10 |
| archmage | mage Lv20 | dark_priest Lv10 |
| sorcerer | mage Lv20 | rogue Lv10 |
| warlock | dark_priest Lv20 | mage Lv10 |
| necromancer | dark_priest Lv20 | warrior Lv10 |
| assassin | rogue Lv20 | warrior Lv10 |
| trickster | rogue Lv20 | mage Lv10 |

`unlock.clearedStageId`（型に存在）は現行データでは未使用。

### 5.2 skills.json（`SkillData`）

- 基本形: `{ id, name, mpCost, power, type: 'PHYSICAL'|'MAGICAL', element, attackType, targetType, effectKey, description }`。実データの `type` は `PHYSICAL`/`MAGICAL` のみ（`HEAL` は型のみ）。`targetType` は `SINGLE`/`ALL_ENEMIES` のみ使用。
- 奥義: `isUltimate: true`。型コメントにより「true のとき maxEnergy を全消費」。`mpCost` は表示用で 80〜120（12本中10本が 100 以外）。
- 状態異常付与は**2形式が併存**: 単発形 `ailmentType` + `ailmentBaseRate`（例: `skill_rogue_1` = BLEED 0.4）と配列形 `ailments: [{type, baseRate}]`（`ult_archmage` のみ: BURN 0.35 + POISON 0.3）。
- `flags` 実測値: `IGNORE_DEF`, `HP_DRAIN_20`, `BLEED_STACK_3`, `ENEMY_SPD_DOWN_30_2T`, `PARTY_HP_REGEN_2T`, `RANDOM_AILMENT_0.35`。
- `healSelfPct` 使用例: `skill_darkpriest_1`（30 = 与実ダメージの30%自己回復）。
- `effectKey` は `<属性>_<攻撃種別>` 形式（例: `fire_magic`, `dark_slash_ult`）で BattleCanvas の VFX 選択に使う。実データ25種。

### 5.3 enemies.json（`EnemyData`）

- 基本形: `{ id, name, nameJa, nameEn, tier, tribe, stats, resistances, weaknesses, shieldHp?, maxShieldHp?, gimmicks?, necromance?, dropTable, battle?, description? }`
- `weaknesses` は `resistances` の負数属性と一致させる運用（`docs/設計書/75` 3.3項の規約、現行データも準拠）。
- `battle`: `{ color: string(hex), sprite: 'WRAITH'|'GIANT'|'WYRM', size?: number }`。
- `necromance`（`EnemyNecromanceConfig`）: **全14体が保持**。`{ captureRate, allyCost, allyStats, allyMaxEnergy, skillIds }`。captureRate 実測: MINION=0.12, ELITE=0.04, BOSS=0.001。

### 5.4 monsters.json（初期編成用マスター）

- レコードは `MonsterData` の部分型（`MasterDataService.ts` の `MonsterMasterEntry`）: **`id` / `currentEnergy` / `maxEnergy` を持たない**。実測フィールド: `name, tribe, cost(1〜3), stats, resistances` のみ。`skillIds` 保持エントリは 0 件。
- 読み出し時に `MasterDataService` が `id`（= JSONキー）を補完し、`hydrateMonsterEnergy` で energy を補完する（§6）。
- ORC 種族（orc_warrior, troll）は本ファイルのみに存在し、enemies.json には未登場。

### 5.5 items.json（`ItemData`）

- 実データの `type` は `WEAPON`（7件）と `CONSUMABLE`（3件）のみ。防具スロット種別（SUB〜ACC2）は型のみ。
- 武器フィールド: `weaponRarity / archetype / rank(魂の共鳴 0〜5) / ilv(1〜90) / subOptions / passiveA / passiveB / isUnique / flavor`。`stats` は全武器 `{}`（実効値は subOptions とパッシブ側）。
- `WeaponPassive`: `{ nameJa, descTemplate("{value}"置換), values: number[5](ランク1〜5対応), condition?, systemTag? }`。
- 武器実測一覧:

| id | rarity | archetype | rank | ilv | passiveA/B systemTag |
|---|---|---|---|---|---|
| bone_cleaver | R | MID | 1 | 1 | —/— |
| apprentice_cinder_staff | R | MID | 1 | 1 | —/— |
| mourning_bell_crozier | R | MID | 1 | 1 | —/— |
| grave_thorn_dagger | R | MID | 1 | 1 | —/ACTION_VALUE |
| bleed_reaver | SR | HIGH | 3 | 70 | GIANT_KILLING/ACTION_VALUE |
| spirit_silver_saber | SSR | MID | 2 | 72 | SOUL_SHATTER/DEMON_MODE |
| grudge_manifest | UR | MYTHIC | 5 | 90 | DEMON_MODE/SHIELD_PIERCE |

- 消耗品: `battleUsable: true` + `battleEffect: { type: 'HEAL_HP'|'RESTORE_ENERGY'|'RESTORE_SOUL', value }`。実測: underworld_potion（HEAL_HP 200）、ether_shard（RESTORE_ENERGY 100）、soul_incense（RESTORE_SOUL 35）。
- `subOptions.type` 実測値: `ATK%`, `CRIT_RATE`, `CRIT_DMG`, `EFFECT_HIT`, `DARK_DMG_BOOST`。
- 第一発見者システム用フィールド（`isUnique / discovererId / discovererName / serialNo / discoveredAt`）は型に存在。マスターデータでは全件 `isUnique: false`。

### 5.6 stages.json（`StageData`）

- 基本形: `{ id, name, nameJa, nameEn, chapter, chapterName, area, nodeType, element, difficulty, sortOrder?, description, waveCount, areaGimmick?, unlockRequires: string[], waves: StageWaveData[], rewards, position, isAreaBoss? }`
- `StageWaveData`: `{ label, role: 'WARMUP'|'SHIELD'|'ELITE'|'BOSS', enemyIds: string[], intent, statScale? }`。`statScale`（`Partial<Pick<BaseStats,'hp'|'atk'|'def'>>` の倍率）は実測65 WAVEで使用（例: `{hp:1.2, atk:1.1}`）。
- `rewards`: `{ baseExp, baseGold, dropTable: DropEntry[], firstClearGuaranteed?: GuaranteedDropEntry[] }`。`GuaranteedDropEntry` は `rate` 省略可の `DropEntry`。
- 第1章本編は `area1_safe`（SAFE, waveCount 0）→ `area1_node1` → `area1_a2` → `area1_a_mini` → `area1_node2` → `area1_b2` → `area1_b3` → `area1_c1` → `area1_c2` → `area1_c3` → `area1_node3` → `area1_boss`（BOSS, `isAreaBoss: true`）の直列アンロック。
- `area2_gate`（chapter 2）は「ロック表示のみ」のプレースホルダ（データ内 description に明記）。
- 黄泉の階層 `yomi_b01`〜`yomi_b20`: chapter 1 / area 99 / sortOrder 9001〜。報酬は `baseExp: 0, baseGold: 0, dropTable: []` で `firstClearGuaranteed` のみ（5階ごとに WEAPON_MATERIAL / RESIDUE の節目報酬）。

### 5.7 DropEntry（ドロップ規則・`src/types/game.ts`）

```typescript
DropEntry: {
  type?: 'WEAPON' | 'RESIDUE' | 'MATERIAL' | 'MONSTER' | 'CONSUMABLE' | 'WEAPON_MATERIAL';
  itemId?; monsterId?; weaponMaterialType?; rarity?; quantity?;
  rate: number;        // 0..1
  isHidden?: boolean;  // UR隠しドロップ（実測: grudge_manifest rate 0.00008）
}
```

| type | 参照キー | 参照先 |
|---|---|---|
| `WEAPON` / `CONSUMABLE` | `itemId` | `items.json` |
| `MATERIAL` | `itemId` | `materials.json` |
| `MONSTER` | `monsterId` | `enemies.json`（necromance 設定から味方化。実測参照は grave_soldier / rot_hound で、monsters.json ではなく enemies.json のIDに解決） |
| `RESIDUE` | `itemId` なし | `rarity` 指定でランダム生成（COMMON/RARE/EPIC/LEGENDARY） |
| `WEAPON_MATERIAL` | `weaponMaterialType` | `WeaponMaterialType` enum（items/materials に実体レコードなし） |

### 5.8 areas.json（`AreaData`） / demonForms.json（`DemonFormData`）

- `AreaData`: `{ id, chapter, area, nameJa, nameEn, description, color, position:{x,y}, sortOrder? }`。3件: `ch1_area1`（第1章）, `ch1_area99`（黄泉の階層・position は画面外 999999）, `ch2_area2`（幽霊都市・第2章）。

- Tier1×4（warrior=黒翼の剣聖 / mage=五葬の魔導王 / dark_priest=反聖の黒司祭 / rogue=影喰いの夜王、いずれも `riskType: null`）+ Tier2×8（リスク付き。データは存在するが第2章対象 — §9）。

## 6. MasterDataService API（`src/services/MasterDataService.ts`）

シングルトン。**必ず `MasterDataService.getInstance()` を使う**。全JSONはビルド時 import（ランタイムfetchなし）。

| メソッド | 戻り値 | 備考 |

| `getJob(id)` / `getAllJobs()` | `JobData` | |
| `getMonster(id)` / `getAllMonsters()` | `MonsterData` | **読み出し時変換あり**: `id` を JSONキーで補完し `hydrateMonsterEnergy` を適用 |
| `getEnemy(id)` / `getAllEnemies()` | `EnemyData` | |
| `getItem(id)` / `getAllItems()` | `ItemData` | |
| `getStage(id)` / `getAllStages()` | `StageData` | |
| `getArea(id)` / `getAllAreas()` | `AreaData` | |
| `getSkill(id)` / `getAllSkills()` | `SkillData` | |

| `getNecroConfig()` | `NecroConfigData` | GameManager / RewardService / admin から参照 |
| `getMaterial(id)` / `getAllMaterials()` | `ResidueMatData` | |

単数形 getter はすべて `T | undefined` を返す（存在チェックは呼び出し側の責務）。

**モンスターEnergy補完**（`src/logic/MonsterEnergySystem.ts`）:

- `DEFAULT_MONSTER_MAX_ENERGY = 30`
- `maxEnergy = max(1, floor(値))`、非数値なら 30
- `currentEnergy = min(maxEnergy, floor(値))`、非数値なら maxEnergy（満タン初期化）
- 捕獲時の maxEnergy は `resolveNecromanceMaxEnergy` が `enemy.necromance.allyMaxEnergy`（なければ 30）から解決
