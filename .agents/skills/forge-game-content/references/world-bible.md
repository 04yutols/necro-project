# Necromance Brave 世界観正典

## Source priority

矛盾した場合は上から優先する。

1. `src/data/story/` と `src/data/master/` の現在値
2. `docs/progress/DONE.md` の確定済み意思決定
3. `docs/設計書/01_ゲームデザイン.md`、`15_ワールド・ダンジョン・エネミー設計.md`、`22_ストーリー進行システム.md`
4. 個別システム設計書
5. 新しい制作依頼のクリエイティブブリーフ

## Core pillars

- 主人公アルドは、亡き友ラインに由来する死霊術の力を継ぎ、魔王に滅ぼされた世界を進む。
- 力は便利な魔法ではない。死、記憶、怨念、契約、喪失のいずれかと結び付き、代償や不穏さを伴う。
- 第1章「亡国の王都」は、繁栄の残骸、果たされなかった忠誠、眠れない死者を中心に描く。
- 敵を倒す行為と、死者を使役する行為の倫理的な緊張を消さない。
- 希望は存在するが、明るさだけで問題を解決しない。勝利にも傷跡を残す。

## Character rules

- 第1部の戦闘パーティはアルド＋使役魔物3体。人間のプレイアブル仲間を追加しない。
- 登場人物には「望み」「恐れ」「アルドと対立または共鳴する価値観」を最低1つずつ持たせる。
- 既存人物の口調は現行シーンを正典とする。アルドは短く率直に話し、説明台詞を連発しない。
- 悪役も世界設定の説明装置だけにせず、自身の合理性を持たせる。

## Naming language

- 日本語名は2〜8文字程度の核語を優先し、必要なら「〜の〜」で由来を示す。
- 語彙軸: 骸、魂、灰、墓、葬、冥、奈落、深淵、王権、弔い、契約、残響。
- 同じ接頭辞を乱用しない。「深淵」「冥界」を希少性なしに付けない。
- 現代製品名、ネットスラング、軽い駄洒落、他作品固有語の模倣を避ける。

## Content-specific rules

### Story

- 1シーンにつき、状態変化または認識変化を1つ置く。
- 会話で全設定を説明せず、環境描写、沈黙、アイテム由来で分散して示す。
- トリガーと完了フラグを既存ステージ進行へ接続する。

### Weapons

- 名前、フレーバー、2つのパッシブを同じ由来へ結び付ける。
- レアリティが高いほど概念を大きくする。Rは道具、SRは逸話、SSRは歴史、URは世界法則への違反を扱う。
- 実装済み `systemTag` だけを使用し、文章上の効果とゲーム効果を乖離させない。

### Visuals

- 人物、武器、敵、背景は、黒曜石、古骨、褪せた金、Void Purpleを核にしつつ、所有者や地域ごとの差を残す。
- 暗さだけで統一せず、シルエット、属性色、希少性色で小さいモバイル画面でも識別できるようにする。
- 表情差分や別サイズ画像は同じ基準デザインから派生させ、顔、装備、紋章の一貫性を守る。
- VFXは派手さより、cast、impact、damage timingが理解できることを優先する。

### Abyssal residues

- 残滓は完成した装備品ではなく、死や記憶が物質化した痕跡として命名する。
- COMMONは個人の痕跡、RAREは集団や儀式、EPICは王国史や大事件、LEGENDARYは神性・世界法則に触れる。
- 名称制作は性能抽選から独立させる。数値バランスを創作バンドルに混ぜない。

## Hard constraints

- 現行リリース範囲は第1章。第2章以降の新規コンテンツは適用しない。
- 固有IDは既存データと重複させない。
- ストーリー人物の立ち絵を参照する場合、実アセットを同じContent Packageの必須成果物にする。未制作ならDRAFTのままにする。
- 世界観の「良さ」は人間が承認し、構造・参照・数値は決定論ゲートで検証する。
